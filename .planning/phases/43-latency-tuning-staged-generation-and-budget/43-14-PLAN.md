Hard rules for this plan (the user's standing rules):
- LOCAL ONLY. Every spacetime command names `--server local`. Never publish to, call or query maincloud; never run `pnpm spacetime:publishprod`.
- Publish with no flags first (`spacetime publish uwr --server local < /dev/null`, the same as `pnpm spacetime:publish`); add `--break-clients` only if the CLI output asks for it (the admin view's row type changed). Stdin is closed so a prompt aborts instead of hanging. NEVER pass `-y`, `--yes=all`, `--delete-data` or `--clear-database`.
- If the publish is refused or aborts for any reason other than the break-clients prompt, STOP: do not retry with other flags and do not clear. Return a checkpoint to the user with the exact output (recovery would be the Phase 41 runbook `docs/runbooks/llm-key.md`).
- Never read, print or log the key, `llm_config` (never query it), the CLI token, `spacetimedb/.env.local`, the root `.env.local` or any `.dev.vars`. Query only `admin_llm_status` fields and `COUNT(*)` values; filter `spacetime logs` through grep.
- Do not call any spending reducer (no `llm_smoke_test`, no gameplay reducer that enqueues an LLM job). The kill-switch and ceiling reducers spend nothing.
- The local server may or may not be running: check `spacetime server ping local` first and start it per the run-local skill if needed (pre-flight netstat on port 3000; never kill a process you did not start).
- No pushes. Stage by explicit path only; never stage `.claude/settings.local.json`, `public/assets/logo.png`, `public/assets/logo_old.png`; never `git stash`. Every commit ends with the attribution lines. Do not run `requirements mark-complete`.
- Tests single-worker: `CI=true pnpm exec vitest run --maxWorkers=1` (the root run also collects the server suite).
