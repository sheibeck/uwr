# Phase 51.2 — UI Design Contract: World Events

> Visual and interaction contract for Phase 51.2: World Events (LDG-12, LDG-13, LDG-14). Generated by gsd-ui-researcher, to be verified by gsd-ui-checker. Split out of the first Phase 51 draft (commit 04a1cb09) on 2026-10-07. The surfaces are unchanged from that draft's Area 3.
>
> **Shared sections.** The following are defined once in `.planning/phases/51-ledger-screens-world-and-people/51-UI-SPEC.md` and apply here unchanged:
> - the Design System, Spacing scale, Typography roles, Color split and the Shared Ledger rules (server time, timers, screen arguments);
> - no new tokens (pin 23), no literal colors, no `v-html`, text nodes only;
> - **`<svg` banned everywhere except `src/map/`** (so banned in `src/events/`);
> - Phosphor 2.2.1 and Inter only; `h4` and `h6` only;
> - sizes 10/12/14/20, weights 400/500, spacing 4/8/16/24/32/48/64;
> - no `replaceAll`, `.at` or `Object.hasOwn`.
>
> This file adds only its own values and is complete for its own surfaces.
>
> **Word rule.** The word the Ledger mock uses for the event-consequence list is banned in this project. This file, the code, the player text and the docs say "World event(s)" or "Timeline".
>
> **Design source.** `UWR Ledger Screens.dc.html` 2h (World events) and 2i (the rail's World event card and Tracking), from the claude_design project "Unwritten Realms" (`1a7a975f-7b14-488b-9a38-188bc56294cf`), extracted in `design51/EXTRACT.md` (2h lines 710–801, 2i lines 887–917). The design files were treated as data; they contain no text addressed to the assistant.
>
> **Decisions** come from `51-CONTEXT.md` Area 3. Where the mock disagrees with CONTEXT, CONTEXT wins (Mock overrides).
>
> **Depends on Phase 51:** `Travel there` opens the Map (`openScreen('map', { locationId })`), and the Map's neighbours-only travel rule applies there.

## World Events Contract (LDG-12, LDG-13, LDG-14)

### Event list

- Sections are each an `h6` with a count: `Active · {n}`, `Upcoming · {n}`, `Recently resolved`. A section with no rows is omitted, except `Active`, which shows `No active World events.` (Label 12, neutral-500).
- **Order:**
  - Active: by the soonest deadline (no deadline last), then by id (the 47 rail rule).
  - Upcoming: by start time.
  - Recently resolved: by `resolvedAt`, newest first, at most 8 (the server keeps history; the planner may cap the subscription).
- **Card** (a `button`, `aria-pressed` on the selected event, `--radius-md`, padding `8px 16px`, gap 4, full width, min-height 56 on mobile):
  - Meta row (Micro 10, `space-between`): `{Region}` and the timer.
    - Active: `{2h 14m}` (`formatTimeLeft`; none when there is no deadline).
    - Upcoming: `Starts in {2h 14m}`.
    - Resolved: `{Succeeded | Failed} · {3h} ago`.
  - The name (Body 14 / 500, ellipsis, `title`).
  - Active only: the 4px For/Against bar once a counter has moved (the 47 rule), else nothing.
  - A tracked event shows `PhPushPin` 12 accent-300 after the name; the `aria-label` adds `, tracked`.
  - Selected: the accent card recipe (Color). Hover: a 7% text overlay.
- **Default selection** (desktop): the screen's `eventId` argument, else the first active, else the first upcoming, else the first resolved.

### Event detail

| # | Block | Content |
|---|-------|---------|
| 1 | Kicker row | `World event · {Region}` (Micro 10 uppercase 0.1em, `var(--color-accent)`) and a state tag (`.tag`, Micro 10, padding `0 4px`): `Upcoming` (`.tag-outline`), `Active` (`.tag-accent`), `Succeeded` (`.tag-accent`), `Failed` (`.tag-neutral` with `var(--color-con-red)` text) |
| 2 | Title | `h4` event name (wraps, `tabindex="-1"`) |
| 3 | Description | Body 14 `var(--color-neutral-300)`, max-width 560, wraps. The source is the event's description field (research adds one for the generated rule events). Missing: omitted |
| 4 | For/Against | A line (Label 12, `space-between`): `For {p}%` (accent-300), the timer in the middle (`var(--color-neutral-400)`: `Ends in {2h 14m}`, `Starts in …` or `Ended {3h} ago`), and `Against {q}%` (con-red). Then the 8px bar (For accent, Against health, gap 4, `--radius-sm`), with `role="img"` and `aria-label="For {p}%, Against {q}%"`. Before any counter moves: the bar track only, and `No progress yet` in place of the percents |
| 5 | Objectives | `h6` `Objectives`, then the grid of cards (`var(--color-bg)`, `--radius-md`, padding 16, gap 8). Each card has the name (Label 12), a 4px accent bar and the progress line (Label 12, neutral-500):<br>- counted objectives: `{current} / {target} realm-wide`;<br>- a defend objective: `{name} stands`, or `{name} has fallen` (con-red), with no bar.<br>Each bar is a `progressbar` with `aria-label="{name} {current} of {target}"`. None: `No objectives.` |
| 6 | Rule | `.hr` |
| 7 | Timeline | `h6` `Timeline`, then rows newest first: a grid `64px minmax(0, 1fr)`, gap 16, holding the time (Micro 10, neutral-500: `Just now`, `12m ago`, `3h ago`, `2d ago`) and the text (Label 12, accent-300).<br>Entry texts: `Announced.`, `Started.`, `{Objective} completed.`, `Succeeded.` and `Failed.`. A follow-up event gets a text button `Led to {event name}.` (link look, `var(--color-accent-300)`, underline on hover) that selects that event.<br>Upcoming events show only `Announced.` |

### Your part (a column, or a block at 900–1199 and on mobile)

- `h6` `Your part`.
- **Contribution:** the number (Heading 20 / 500, tabular, `en-US` grouping), and beside it (Label 12, neutral-400) `contribution · top {p}%`.
  - `p = ceil(rank / contributors × 100)`, where rank is among contributors with a count above 0, and ties share the better rank.
  - With a count of 0: the number `0` and `No contribution yet`.
  - Upcoming: the block reads `Contribution opens when the event starts.`
- **Grid** (`1fr auto`, row gap 8, Label 12): `Contributors` `{n}`; `Party contribution` `{sum}` (the party members' counts, yourself included; omitted when solo).
- A rule (`.hr`).
- **Rewards:** `h6` `Rewards`, then one block per tier in the order Gold, Silver, Bronze (gap 8):
  - Line 1 (Label 12, `space-between`): `{Tier}` (`var(--color-text)`) and `{threshold}+ contribution` (neutral-500, tabular).
  - Line 2 (Label 12, neutral-300): `If it succeeds: {reward list}`. Line 3: `If it fails: {reward list}`.
  - A reward list joins its non-empty parts with `, `: `{n} renown`, `{n} gold`, `{faction} +{n}` and `{item name}` (the item in its rarity color through `rarityColor()`). An empty side reads `nothing`.
  - The highest tier your count reaches gets `PhCheck` 12 and `Reached` (accent-300) after the tier name; its `aria-label` includes `, reached`.
  - With no tiers in `rewardTiersJson`: `No rewards listed.`
- A spacer (`flex: 1`), then the actions (full width, min-height 40; 44 on mobile):
  - **`Travel there`** (`.btn-primary`, `PhSignpost`) opens the Map with the event's place selected: `openScreen('map', { locationId })`. The place is the first objective's location, else the region's start place (51 O2).
    - The Map applies its neighbours-only rule: a far place shows its path and `Select first stop`; a crossing shows the region-travel checks.
    - `aria-label="Travel there: show {place} on the map"`.
    - Hidden for resolved events. When you are already at that place it is hidden, and `You're there.` shows instead (Label 12, neutral-400).
  - **`Track in sidebar` / `Stop tracking`** (`.btn-secondary`, `PhPushPin` / `PhPushPinSlash`, `aria-pressed`) calls the new tracking reducers (generic kind `world_event` and the event id). `aria-pressed` follows the subscribed row (no optimistic flip).
    - Available for active and upcoming events. A tracked resolved event shows `Stop tracking` only.
    - The World events screen and the rail both read the same server row.

### Mobile world events

- **List view** (on open): the three sections with cards (min-height 56). Choosing a card opens the detail view.
- **Detail view:**
  - A back button (`.btn .btn-ghost`, `PhCaretLeft` 20, `All events`, 44px, `flex: none`).
  - In the scroll region: the kicker and tag, the `h4`, the description, the For/Against block, Your part (contribution, party, rewards), objectives and the timeline.
  - Docked at the bottom (`flex: none`): `Travel there` (primary, `flex: 1`) and `Track` / `Untrack` (secondary; `aria-label` `Track in sidebar` / `Stop tracking`), both 44px.
  - Back returns focus to the card it came from.
- On mobile, `openScreen('events', { eventId })` opens straight into that event's detail view.
- `Travel there` on mobile closes the Events sheet and opens the Map sheet at that place.

### Empty and loading

- **Loading:** nothing renders until the event rows apply.
- **No events at all:** `EmptyState` with `PhGlobeHemisphereWest`, `No World events yet.` and the body `Events start on their own across the realm. Check back soon.`
- **The selected event disappears** (cap or removal): the selection moves to the default rule, and focus moves to the list heading.

### Tracked events in Tracking

- Tracked World events lead the `Tracking` section, before quests. Each is a `button` row: full width, padding `4px 8px`, gap 4, `--radius-sm`, min-height 32 (44 on mobile).

## Accessibility Contract

- **Drawers, sheets, notice line, disabled-with-reason and focus after removal** work as in 50.
- **The For/Against bar** has `role="img"` with the percents in its label, and the words `For` / `Against` are visible.
- **Objective bars** are `progressbar`s with counts.
- **Timers** are not live: visible text is `aria-hidden` and a minute-level sentence carries the value (51 rule).
- **Focus targets after changes** (`tabindex="-1"`):

| Action | Focus moves to |
|--------|----------------|
| Event card chosen (desktop) | stays on the card; the detail updates |
| Event card chosen (mobile) | the detail `h4` |
| Back (mobile) | the card it came from |
| `Led to {event}.` | the new event's `h4` |
| Selected event disappears | the list heading |

- **44px mobile targets:** cards (56), back, dock actions and rail rows.
- **Color is never the only cue:** outcomes and states are words, and the bar has percents.
