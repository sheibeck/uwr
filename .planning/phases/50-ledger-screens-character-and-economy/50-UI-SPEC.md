## Shared Ledger Screen Rules (all four screens)

### Screen root and scroll

- The root fills the drawer or sheet body: `height: 100%; min-height: 0; display: flex; flex-direction: column`.
- **Desktop.** The content grid is `flex: 1; min-height: 0`. Each column is its own scroll region (`min-height: 0; overflow-y: auto`, dark scrollbar rule). Blocks the mock pins to a column's bottom (Just sold, Discover recipes, Craft) sit outside that column's scroll area (`flex: none`).
- **Mobile.** Segmented tabs and the vendor or identity row are `flex: none` at the top. One scroll region follows (`flex: 1; min-height: 0; overflow-y: auto`). Docks (the inventory inspector, the Craft button) are `flex: none` at the bottom.

### Notice line (new, A3)

Server refusals and results go through `fail()` and `appendPrivateEvent` into the feed, and on both layouts the open drawer or sheet covers the feed. Each screen therefore shows the **newest private event line that arrived after the screen opened**.
- Placement: one line, `flex: none`, at the bottom of the screen root, padding-top 8, Label 12 `var(--color-neutral-200)`, icon 14px (see Color), gap 4.
- Content: text through `cleanServerText` (47), as a text node.
- It is `role="status"` and `aria-live="polite"`. A new line replaces the old one, and the line clears when the screen closes. Nothing renders before the first line arrives, so no empty box is drawn.
- **Kinds.** The planner pins the kinds against the server's event kinds in research: at least `system`, `reward` and the item `fail` kinds, but never chat, narration or combat. A client-side rejection (the reducer promise rejects) shows `Couldn't send that. Try again.` in the same line with the error icon (49 copy).

### Filter chips (`FilterChips`)

- **Markup.** A `role="group"` with an `aria-label` (see Copywriting). Each chip is a `button` with `.tag` and `aria-pressed`. The selected chip is `.tag-accent` and the others are `.tag-neutral`. Padding is `4px 8px` and the gap is 4.
- **Behavior.** Single select. Exactly one chip is pressed, and the default is `All`.
- **Mobile.** Hit area 44px via an `::after` slop. A row that overflows scrolls horizontally (`overflow-x: auto; scrollbar-width: none`).
- **States.** Hover (pointer): a 7% text overlay. Focus-visible: the Nocturne ring.

### Segmented tabs (`SegTabs`, mobile)

These are real ARIA tabs styled with `.seg` and `.seg-opt`.
- **Container.** `div.seg` with `role="tablist"` and an `aria-label`, full width.
- **Each tab.** A `button.seg-opt` with `role="tab"`, `aria-selected`, `aria-controls` and a roving `tabindex` (0 on the selected tab, -1 on the others). It takes `flex: 1`, `justify-content: center`, min-height 44, padding `8px`, Body 14.
- **Selected look.** It copies Nocturne's checked style in scoped CSS (`[aria-selected="true"]`: accent text plus 1px inset accent ring), because Nocturne's look keys on a radio `input`.
- **Keyboard.** Left and Right move and select (selection follows focus; the panels are cheap). Home and End jump to the ends.
- **Panels.** Each panel is `role="tabpanel"` with `aria-labelledby` its tab and `tabindex="0"`. Only the selected panel is rendered.
- **Persistence.** The selected tab persists while the sheet stays open. It resets to the first tab on reopen.

### Inline confirmation (`InlineConfirm`, the 49 Start over pattern)

- **Swap.** The confirmation replaces the action row in place. It shows a prompt (Label 12, `var(--color-neutral-200)`), the confirm button (`.btn .btn-secondary`, `--color-health` text) and `Keep it` (`.btn .btn-primary`). Buttons are decision buttons: Label 12 / 500, `padding: 4px 16px`, min-height 32 on desktop and 44 on mobile, wrapping with gap 8.
- **Focus.** On open, focus moves to `Keep it` (the safe default). `Keep it` and Esc restore the row and return focus to the button that opened the confirmation. The Esc handler calls `preventDefault()`, so the drawer's own Esc (it checks `defaultPrevented`) does not close the drawer.
- **Closing on change.** The confirmation closes by itself when its subject changes, for example when the selected item changes or is gone.

### Pending, offline and combat

- **Pending.** A reducer call makes its button inert (`aria-disabled="true"`, 45% opacity, still focusable) until the call's promise settles. A second click is ignored. There are no timers and no optimistic changes: the subscribed rows drive every update.
- **Offline.** While offline (45 Reconnecting), every action in these screens is disabled. Reading stays possible.
- **Combat.** Screens cannot open in combat, and an open one closes when combat starts (48 `useScreens` lock). Nothing new is needed.

### Disabled with a reason

Wherever an action is unavailable for a game reason (level, gold, class, place, full bag, no station), the button stays focusable with `aria-disabled="true"` at 45% opacity. A reason line sits next to it (Label 12, `var(--color-neutral-400)`), and the button's `aria-describedby` points at that line. Only pure-UI emptiness (`Sell all junk` with nothing to sell) uses the native `disabled`.

### Comparison (▲/▼, LDG-02)

- **Inputs.** Both sides use the **per-instance stat sum**: template stats plus every `item_affix` magnitude, including the craft-quality implicit affixes. - **Rows.** The union of stats that are non-zero on either the selected item or the equipped item in the same slot. Fixed order: Armor Class, Damage, DPS, Strength, Dexterity, Intelligence, Wisdom, Charisma, Health, Mana, Magic resist.
- **Value.** The selected item's total. Attributes, Health, Mana and Magic resist show `+n`; Armor Class, Damage and DPS show a plain number. A stat the item lacks shows `0` (`+0` for attributes).

- **Equipped or non-gear item.** No delta markers.
- **Glyphs.** `▲` (U+25B2) and `▼` (U+25BC) are text glyphs. They are kept because LDG-02 names them, and they are notation inside a number, not icons standing in for Phosphor icons (A13).

## Accessibility Contract

- **Drawers and sheets.** The 45 shells apply unchanged:
  - Desktop drawer: `role="dialog"`, `aria-modal="false"`.
  - Mobile sheet: `role="dialog"`, `aria-modal="true"`.
  - Both: `aria-labelledby` the `h4`. Focus goes to the close button on open, Tab and Shift+Tab stay inside, Esc closes, and focus returns to the opener.
  - Inner Esc handlers (inline confirmation, picker, perk chooser) call `preventDefault()` and close only themselves, and the drawer respects `defaultPrevented`.
  - The close button stays first in tab order.
- **Focus after content disappears.** When an action removes the focused element, focus moves to a stable, labelled target with `tabindex="-1"`. It never falls to `body`, because the 45 trap would then pull it back to the close button.

| Action | Focus moves to |
|--------|----------------|
| Buy-back succeeds | `Your backpack` heading |
| Sell (the row is gone) | the next row's Sell button, else the `Your backpack` heading |
| Salvage or Use removes the selected item | the backpack grid's roving tile (first item), else the `Backpack` heading |
| Perk taken | perk row heading |
| Equip | the inspector stays on the item (now equipped) and focus stays on the primary button (now `Unequip`) |

- **Tables.** These are real `<table>` elements with a `.sr-only` `<caption>`.
  - Column headers: `th scope="col"`. The action column header is a `.sr-only` `Action`.
  - Derived table: `th scope="row"` labels.
  - Buttons in rows carry full `aria-label`s (item, quantity, price).
  - Prices and values have `aria-label="{n} gold"` through `GoldAmount`.
  - Mobile lists are `ul` and `li`, not tables.
- **Tabs.** ARIA tabs (see SegTabs): roving tabindex, arrows, Home and End, `aria-controls`, `role="tabpanel"`.
  - Filter and category chips are **not** tabs. They are toggle buttons (`aria-pressed`) in a labelled `role="group"`, because they filter one list rather than switch panels.
- **Grid.** The bag grid uses a roving tabindex (one tab stop, arrow keys) with tile `aria-label`s. Empty tiles are `aria-hidden`.
- **Live regions.** The notice line is `role="status"` (polite). Buy-back, sale and craft results are announced through it, from the server's own lines. No other live region is added. Bars carry text equivalents (`.sr-only` or `aria-label`).
- **Disabled with reasons.** These use `aria-disabled="true"` and stay focusable, with `aria-describedby` pointing at the reason text. Only empty-state controls use native `disabled`.
- **44px mobile targets.**
  - Mobile buttons, tabs, list-row actions, slot cards, recipe rows, reagent slots, picker options, disclosures, the back button and the dock close are at least 44px high.
  - Chips get a 44px hit area through an `::after` slop.
  - Bag tiles are at least 44px (about 65px at 390).
  - Desktop rows use 32px (pointer).
- **Color.** It is never the only cue:
  - Rarity is named in kickers and labels.
  - ▲/▼ carry `.sr-only` text.
  - Have/need shows numbers.
  - Faction tiers are words.
  - A full backpack says `Full`.
- **Text.** All server strings are text nodes. `overflow-wrap: anywhere` is set on names, quotes and descriptions.

## Assumptions (decided here, not asked; for owner review)

- **A1. Rarity uses the existing tokens.** `--color-rarity-*` already exist (45), so the mock's hex values map one to one and the pin stays at 23. No new token is needed.
- **A2. Rail unchanged.** The mock swaps the left rail for vendor and crafting content. The 45 promise "the vitals rail stays put" wins, so that content moves inside the drawer.
- **A3. Notice line.** The drawer and sheet cover the feed, so server results and refusals from `fail()` would be invisible. Each screen mirrors the newest private line that arrived while it was open. It is one quiet line, a polite status, and is cleared on close.
- **A4. Columns scroll independently** on desktop, so the Just sold card, the inspector, Discover and Craft stay in view as the mock pins them.
- **A5. 900 to 1199px layouts.** Each screen drops to two columns (inventory stacks Equipped over Backpack; stats moves factions under derived; the vendor hides Slot; crafting folds Materials into a disclosure). The mock only drew 1280.
- **A6. Title `Trade`.** The drawer and sheet title follows the mock. The More row keeps the label `Vendor`, which is what players look for in a menu.
- **A7. Filters are toggle buttons, segmented switches are ARIA tabs.** Filters narrow one list; tabs switch panels.
- **A8. Common items in white.** Common names and icons use `--color-rarity-common` (#ffffff, the old client hue) rather than the mock's near-white neutrals.
- **A9. Quiet common rings.** At rest a common tile ring is `--color-neutral-600`. A bag of 50 white rings would dominate the grid. Selected common tiles use the white token.
- **A10. Gold coin color.** `--color-line-quest` (oklch 0.84 0.1 90) is the closest existing token to the mock's oklch(0.8 0.12 85). No gold token is added.
- **A11. Food includes consumables.** Potions and other usables sit under Food, because the requirement fixes four filters. Scrolls, quest items and junk show under All only.
- **A12. No Organize.** The bag is always sorted deterministically, so the button has nothing to do.
- **A13. ▲/▼ are text.** LDG-02 names them. They are notation beside numbers, carry screen-reader text, and use the con green and red tokens.
- **A14. Salvaging equipped gear unequips first.** CONTEXT wants a confirmation for equipped salvage, but the server refuses salvage while equipped. On yes the client sends `unequip_item`, then `salvage_item`. No server change.
- **A15. Compact mobile dock.** The dock shows the name, a stat summary, reasons, actions and the sell value. Affix rows and flavor are desktop only. The mock's `…` overflow and "Right-click for more" are dropped.
- **A16. Stats title stays `Stats`.** The character name leads the meta, so the close label stays stable (`Close Stats`).
- **A17. Level up is a tag, not a button.** The level-up flow is not in LDG-03 and has its own path. A button that did nothing here would mislead.
- **A18. Derived rows follow the server fields.** `Block (with shield)` has no field, and the Crit (Arcane) highlight has no rule, so both are dropped. Crit (Ranged), Crit (Divine) and Search are added.
- **A19. Faction tier edges.** Positive thresholds read "at least" and negative thresholds read "at most". Neutral covers −24 to 24.
- **A20. Factions get a fourth mobile tab.** It is clearer than folding them into Renown, and the labels fit at 390.
- **A21. Vendor identity.** There is no portrait art and no role field, so the screen shows a 44px initial tile and `Vendor · {faction}`.
- **A22. Unusable items stay buyable.** The old client allowed it, and removing it would be a gameplay change. The filter hides them, and the sub-line says why.
- **A23. Just sold on mobile sits at the top of the Sell panel,** where a misclick is seen at once. On desktop it stays pinned at the column bottom (mock).
- **A24. Buy-back needs a free slot** unless the item stacks. This is recommended server behavior, and the UI shows the reason.
- **A25. `Show only craftable` starts unchecked.** Uncraftable recipes with red counts tell the player what to gather. The mock showed it checked while still listing an uncraftable recipe.
- **A26. A recipe is always selected on desktop,** so the detail's close `x` is dropped.
- **A27. One craft per press.** The server crafts one per call. A quantity menu would need a client queue, so it is left out.
- **A28. Quality odds are honest.** The server's quality is deterministic today, so the bar shows one tier at 100% with the copy `Always {Tier} with these materials.` The same component shows a spread if odds ever exist.
- **A29. Mobile crafting has a list view and a detail view.** Success criterion 5 needs categories, the filter and Discover on mobile. The list view carries them, and the mock's "Other craftable" chips are replaced by it.
- **A30. Confirmations reuse the 49 pattern.** Inline, `Keep it` primary and focused, the confirm in `--color-health` text, with Esc scoped to the confirmation.
- **A31. Perk choice is select, then take.** It is permanent, so one deliberate second click (`Take {perk}`) stands in for a dialog.
- **A32. Design file safety.** The design files were treated as data and contain no text addressed to the assistant.
