## Decisions (planner, within the locked scope)
- **Sort: always applied.** The bag already sorts by type, rarity best first, then name (compareBagItems in src/ledger/itemModel.ts:252: Gear, Material, Food, Recipe, Other, Quest, Junk, then rarity high to low, then name, then id). So Organize is the server merge of partial stacks plus this view. No client sort switch and no new reducer. consolidate_stacks merges every non-equipped stack of a stackable template into one, with the same rule addItemToInventory uses (spacetimedb/src/helpers/items.ts:361), and writes the private system line "Inventory organized: N stack(s) consolidated." or "Inventory organized.".
- **Header layout.** The frame header today is title, meta, spacer, close (src/frame/Drawer.vue:38-52, src/frame/Sheet.vue:38-52). The mock puts the gold and Organize after the spacer, so the frame gains an `actions` slot after the spacer (ScreenDef `actions?: Component`). InventoryMeta keeps the slot count, and the new InventoryActions holds the gold and Organize. Nothing else in the Inventory screen shows slots or gold (Inspector's gold is the "Sells for" price), so the gold moving out of InventoryMeta is the only duplicate to remove.
- **Mobile Organize.** The mobile mock draws no Organize, but merging stacks must not be desktop only. It is an icon-only 44px button named 'Organize backpack'. The 390 header then fits about 320px of the 358px row: title, count, gold, Organize, close.
- **Shared runner.** The header actions and the screen are sibling components (AppFrame renders the meta and actions slots beside the body), so the "handled like other actions" rule needs one runner. `bagRunner(ledger, game)` keeps one runner per ledger hub in a WeakMap, created in a detached effect scope. Both components use it, so an Organize rejection reaches the screen's NoticeLine.
- **Tile size.** At 1280 the backpack column is 372px (1280 − 252 rail − 48 drawer padding − 300 − 260 − 48 column gaps). A 64px tile would need 5.5 columns, so the fill rule picks 5 columns at 71px; 6 columns would be the 58.7px the owner called slightly too small. The cap is 72px, so wider windows add columns instead of growing tiles. The SUMMARY records the table and a UAT note: the owner may prefer a 68px cap with an 8px gap. The gap stays 4px (50-32's mapping of the mock's 6px).
- **Empty cells:** aria-hidden and keyboard-skipped, as today. **Filters:** only matching items, as today. **Empty bag:** the UI-SPEC empty state, as today.
