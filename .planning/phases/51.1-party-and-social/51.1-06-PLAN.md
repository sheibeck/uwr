## Decisions
- **UI-SPEC "Data the UI reads"** and research "Recommended Project Structure": a separate hub in `src/social/` beside the map and ledger hubs, copying `src/map/mapData.ts` / `mapContext.ts`.
- **Planner, the incoming invite:** one at a time (the server allows one pending invite per target); when several rows exist for the active character (a stale row before the server ends it), take the lowest id.
- **Planner, the incoming invite group:** its `group` row and `group_member` rows are subscribed by the invite's groupId (not your own group), so the chips work while you are solo.
- **Planner, extra characters:** outgoing invite targets plus the inviting group's members, by id list, excluding ids the game hub already has is NOT required (duplicate subscriptions are fine because each binding filters to its own ids).
- **Coordinator:** the client never calls the join-by-group-id reducer; that rule is enforced in Plan 08's action layer.
