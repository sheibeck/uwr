# Phase 51.1 Plan 11: Invite surfaces Summary

The incoming invite card (Accept, Decline, display-only countdown, member chips, announce) and the leader's Invited · waiting list (countdown, Cancel invite, focus after cancel), with the mobile card placed first in FeedShell's composer section.

## What was built

- `InviteCard.vue` (props `variant: 'rail' | 'mobile' | 'sheet'`, emits `answered`). Reads `social.incomingInvite`, `inviteGroup`, `inviteGroupMembers`, `inviteGroupApplied`, `characterById`, `inviteSecondsLeft`. Accept / Decline go through `createPartyActions` (`acceptInvite` / `declineInvite`); the file never names the join reducers. The body renders only once the inviter's name resolves. Chips (leader with a crown first, then join order) wait for the group rows; unresolved member names read "Player". Expired at 0 seconds replaces the timer; both buttons are `aria-disabled` (also while offline or while either answer is pending). The status region says "Party invite from {name}." once per invite id, clears when the invite goes, and never holds the timer.
- `OutgoingInvites.vue` (props `variant: 'rail' | 'sheet'`, emits `focusHeading`). Leader sees all invites of the group, a non-leader inviter only theirs, ordered by invite id; hidden in combat and when empty. Rows: hourglass, `CharacterName` (Player while unresolved), timer (aria-hidden) + sr text, `Cancel invite` (`aria-label="Cancel invite to {name}"`, calls `cancelInvite`). Focus after cancel: the invite id and index are remembered at click time (the server row can leave before the promise settles); when the row is gone, focus goes to the button now at that index, else `focusHeading` is emitted. Focus is only moved when it is on body, null or inside the list. A rejected cancel forgets the mark.
- `FeedShell.vue`: `<InviteCard v-if="props.compact" variant="mobile" @answered="focusInput" />` first in `.composer`; `focusInput` focuses `input.composer-input` through a ref on the section. Desktop rendering is unchanged.
