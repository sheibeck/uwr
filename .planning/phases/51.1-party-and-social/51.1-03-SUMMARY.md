# Phase 51.1 Plan 03: Party invite consent, expiry and cancel Summary

Joining a party now needs the character's own Accept of a live invite: `join_group` requires an invite for that group, invites expire after 5 minutes through a module-identity-guarded one-shot `expire_group_invite` tick (with lazy checks as the backstop), the leader or inviter can withdraw an invite with `cancel_group_invite`, a refused invite leaves no stray group, and a lone group dissolves when its last invite ends.

## What was built

**Task 1 (dc417886 RED, a64f7551 GREEN): invite rules**
- `spacetimedb/src/helpers/group_invites.ts`: `inviteIsLive`, `liveInvitesTo`, `liveInvitesOfGroup`, `endExpiredInvitesTo`, `endExpiredInvitesOfGroup` (extra), `InviteEnd`, `endInvite`, `dissolveLoneGroup`, `nextLeaderAfter`, `scheduleInviteExpiry`.
- `reducers/groups.ts`: `MAX_GROUP_SIZE` imported from `../data/group_config` (local constant gone); shared `joinFromInvite`; `join_group` refuses 'You need an invite to join.' and ends an expired invite with 'That invite has expired.'; `accept_group_invite` has the same expiry rule; `reject_group_invite` goes through `endInvite(..., 'declined')` (silent when no invite); `invite_to_group` validates everything before the solo inviter's group is created and adds 'You invited {name}.'; `leave_group` uses `nextLeaderAfter`.

**Task 2 (a1be2e10 RED, 8336e138 GREEN): guarded expiry and cancel**
- `schema/tables.ts`: private `GroupInviteExpiryTick` (`group_invite_expiry_tick`: `scheduledId`, `scheduledAt`, `inviteId`), registered last in the schema object.
- `index.ts`: `GroupInviteExpiryTick` imported and passed in `reducerDeps`.
- `reducers/groups.ts`: `invite_to_group` calls `scheduleInviteExpiry` after the insert; `cancel_group_invite { characterId, targetName }`; `scheduledReducers['expire_group_invite']` whose first statement is the module-identity guard, then ends the invite only if it exists and is expired.
- `scheduled_guard.integration.test.ts`: `expire_group_invite` in SCHEDULED (forged call, control, source pin, coverage).

## Deviations from Plan

1. **[Rule 3 - Blocking] `scheduleInviteExpiry` wired in Task 2, not Task 1.** The strict mock refuses inserts into a table missing from the recorded schema, and the table lands in Task 2. The helper was written in Task 1; the `invite_to_group` call and its tests came with the table in Task 2.
2. **[Rule 2 - Correctness] `endExpiredInvitesOfGroup` added.** The plan's case "4 members + 1 expired invite to Eli, invite Finn succeeds and the expired invite is ended first" involves an invite to someone other than the target, so `endExpiredInvitesTo(target)` alone cannot end it. `invite_to_group` now also ends the inviter's group's expired invites before re-reading the inviter.
3. **[Rule 2 - Correctness] `cancel_group_invite` ends the target's expired invites first** (as expired), so only live invites can be cancelled and a stale row never reads as "cancelled".
4. **Removed the unused `GroupInvite` deps destructure** in `groups.ts` after the rewrite (no behaviour change).
