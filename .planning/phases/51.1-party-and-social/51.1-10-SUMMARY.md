# Phase 51.1 Plan 10: Party and Player Menus Summary

A `⋯` opener (`PlayerMenu`) now builds the role-aware entries for one character from the applied rows and runs the chosen action through the shared party action layer. `ActionMenu` draws it as a keyboard-complete desktop popover or a focus-trapped mobile action sheet, with inline confirms for Remove and Leave, one open menu at a time and a focus fallback when the opener disappears.

## What was built
- `menuPosition.ts`: `MENU_WIDTH` (224) and `menuPosition({ anchor, side, height, viewport })`. Right side: `left = anchor.right + 4`. Left side: `left = anchor.left - 224 - 4`. Top is `anchor.top`, flipped to `anchor.bottom - height` when `top + height` passes `viewport.height - 8`. Both values are clamped to the 8px viewport margin, and the margin wins on a viewport smaller than the panel.
- `menuRegistry.ts`: `claimMenu(id, close)` closes the previous holder (another id) after setting the new one, so a close that releases itself cannot drop the new holder. `releaseMenu(id)` clears only that id. `newMenuId()` returns `player-menu-{n}`.
- `ActionMenu.vue`: has the props and emits from the plan interface.
  - Shared parts:
    - An icon map from the nine `MenuIcon` ids to Phosphor components.
    - Groups render in order, with `role="separator"` only between non-empty groups.
    - Items are `button role="menuitem"` with a `data-action`. Disabled or pending items get `aria-disabled="true"`. When an entry has a hint, its `aria-label` is `{label}, {hint}`, and the visible hint is aria-hidden.
    - Tone classes: `tone-accent` gives an accent-200 icon, `tone-danger` gives con-red text and icon, and disabled text is neutral-600.
    - Keys on the panel: Arrow Up and Down wrap and include disabled items, and Home and End jump. Escape calls preventDefault and stopPropagation, then emits `close(true)`. If an inline confirm already took the Escape, the panel only stops it.
    - An entry with a confirm swaps the list for `InlineConfirm`, built from the re-derived entry. Keep, or Escape, restores the list and refocuses that entry. Confirm emits `select` once, and the confirm button is inert while pending.
    - Initial focus goes to the first or last enabled item.
  - Desktop: a fixed panel 224 wide with `--radius-md`, surface, inset 1px neutral-800 plus `--shadow-lg`, padding 4, z-index 40 and `max-height: calc(100vh - 16px)`.
    - It is placed by `menuPosition`: the first render uses height 0 and the measured height is applied on mount. It is placed again when the groups or the confirm change.
    - Header: the name through `CharacterName`, wrapping, at 14/500, then ` you` at Micro 10 neutral-500 and the line at Micro 10 neutral-500.
    - Tab emits `close(false)` and is not prevented.
  - Mobile:
    - A scrim with `color-mix(in srgb, var(--color-bg) 45%, transparent)` at z-index 40.
    - A bottom `section role="dialog" aria-modal="true"` at z-index 41, labelled by the header name and holding the `role="menu"`. It has `--radius-lg` top corners, `--shadow-lg`, the 45 grabber, padding `0 8px 24px`, and scrolls past `100vh - 48px`.
    - Header: padding `8px 16px 16px`, gap 16, and a 40 x 40 initial tile (line-whisper, or accent-300 for you). The name is Body 14/500 and the sub-line is Label 12 neutral-400.
    - Rows: min-height 48, padding `0 16px`, gap 16, icon 20, Body 14.
    - `Cancel`: `.btn .btn-ghost` on `--color-bg`, min-height 44, margin `8px 16px 0`.
    - Tab is trapped with `trapTabKey`. Escape, Cancel and a tap on the scrim emit `close(true)`. The inline confirm renders in its mobile size.
- `PlayerMenu.vue`: props `{ targetId, side = 'right', size = 'rail', fallbackFocus? }`, with `defineExpose({ open(focus = 'first'), close() })`.
  - It injects GAME, SOCIAL, CONSOLE and FRAME, each with an inert default, and creates its own runner and party actions.
  - Target resolution: your row, then `game.playersHere`, then `game.knownCharacters`, then `social.characterById`.
  - Input: `memberCount` counts the member rows of your group. `liveOutgoing` is `social.outgoingInvites` with `inviteSecondsLeft > 0`. `selfFollowLeader` comes from your member row and `nextLeaderName` follows the server order.
  - It renders nothing when there are no entries.
  - The opener: `.btn .btn-ghost .btn-icon .menu-opener`, 28 x 28 in neutral-300, or 44 x 44 with `size: 'sheet'`. It shows `PhDotsThree` at 16 and is labelled `Actions for {name}` or `Actions for yourself`. It carries `aria-haspopup="menu"` and `aria-expanded`, plus `aria-controls` while open. While open it keeps the ghost hover fill.
  - Opening: a click toggles. Enter, Space and Arrow Down open with focus on the first enabled item, and Arrow Up opens with focus on the last.
  - While open: the anchor is the opener's rect, `claimMenu` runs, and a document `pointerdown` outside the root closes the menu and returns focus.
  - Select: disabled or pending entries are ignored. `await actions.perform(action, name)` runs, then the menu closes and focus returns to the opener. Whisper closes first and does not refocus.
  - A rejection appends `SEND_ERROR_TEXT` once, through `game.feed.appendLocal('system', ...)`.
  - When the entries become empty while the opener holds focus, or the component unmounts with focus inside, the menu is released and `fallbackFocus()` gets focus.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] Test file renamed for the Windows case rule**
- **Found during:** Task 3
- **Issue:** The plan's `src/social/PlayerMenu.test.ts` differs only in case from the existing `src/social/playerMenu.test.ts`, which binding rule 7 forbids.
- **Fix:** Named it `src/social/PlayerMenu.component.test.ts`.
- **Commit:** 0ed47a24

**2. [Rule 1 - Bug] Registry ids from useId() could collide**
- **Found during:** Task 3
- **Issue:** `useId()` restarts in every Vue app instance. Two menus in different app instances (seen in the tests) would claim the same id, and opening one would not close the other.
- **Fix:** Added `newMenuId()` (a module counter) to `menuRegistry.ts` and used it for both the registry and the DOM id. Tested in menuSupport.test.ts.
- **Files modified:** src/social/menuRegistry.ts, src/social/PlayerMenu.vue, src/social/menuSupport.test.ts
- **Commit:** 0ed47a24

**3. [Rule 1 - Bug] Tab from the popover would start from a removed element**
- **Found during:** Task 3
- **Issue:** Vue re-renders in a microtask before the browser's default Tab action, so the focused menu item is gone by then.
- **Fix:** On `close(false)` with focus inside, PlayerMenu focuses the opener first, so Tab moves on from the `⋯`. ActionMenu still emits `close(false)`, unprevented, as the plan's test requires.
- **Commit:** 0ed47a24
