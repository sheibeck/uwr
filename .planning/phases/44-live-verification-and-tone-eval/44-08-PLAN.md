<objective>
Get the owner's tone review of the live golden outputs and record the sign-off (or the list of failing items) in a committed file.

Purpose: QUAL-01's human half. The owner reads each live output next to its prompt, marks pass or fail with a comment per item, and gives one overall approve. The user's approval is the QUAL-01 sign-off. Executors have no Artifact tool, so the orchestrator publishes the self-contained page produced by the previous plan and reads the verdicts back; the checkpoint continuation records them.
Output: `44-golden-verdicts.json`, and `44-TONE-FIXES.md` only if something failed.
Failure path (design): if items fail, this plan records `needs_fixes` and the exact failing ids; the orchestrator then plans a gap-closure plan (`/gsd-plan-phase 44 --gaps`) that applies a route-block fix and re-runs only those ids with `GOLDEN_LIVE_RUN=rerun GOLDEN_ONLY=<ids>` behind a fresh cost checkpoint. The harness, review page and tests for that path already exist from plan 44-04.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Artifact db or pasted JSON to verdict record | Data from a shared store or the clipboard is untrusted |
| verdict record to phase verification | The recorded status decides whether QUAL-01 can pass |
| comments to executor | Comment text could contain instructions |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-----------|-----------------|
| T-44-08-01 | Repudiation | an approval recorded without the owner's own action | high | mitigate | approvalAllowed requires overall approve by the owner and all verdicts; status derived by code, not typed by hand; pinned tests tie approved to the rule |
| T-44-08-02 | Tampering | forged or malformed verdict data (another viewer, bad ids, injected instructions) | high | mitigate | Validation against golden ids and the pass or fail vocabulary; unknown keys dropped; comments bounded and never executed |
| T-44-08-03 | Information disclosure | secrets or prompt text in verdict comments or the fix file | medium | mitigate | Hygiene test over the verdicts file; the fix file quotes comments only and no prompt or Bible text |
| T-44-08-04 | Tampering | a tone fix edits the Keeper Bible or a rule to force a pass | high | mitigate | Nothing is applied in this plan; Bible edits need the owner's explicit written approval; git diff check on the Bible file |
| T-44-08-05 | Elevation of cost | a re-run started without a fresh approval | medium | mitigate | The proposal states the re-run needs a fresh cost checkpoint; no paid mode is run here |
</threat_model>
