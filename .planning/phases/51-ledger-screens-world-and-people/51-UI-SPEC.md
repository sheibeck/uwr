# Phase 51 — UI Design Contract: Map and Travel

> Visual and interaction contract for Phase 51: Ledger Screens: Map and Travel (LDG-04, LDG-05). Generated by gsd-ui-researcher, to be verified by gsd-ui-checker.
>
> **Split (owner, 2026-10-07).** The first draft (commit 04a1cb09) covered Map, Social and World events. Phase 51 is now Map and Travel only. Party and Social moved to `.planning/phases/51.1-party-and-social/51.1-UI-SPEC.md`, and World events moved to `.planning/phases/51.2-world-events/51.2-UI-SPEC.md`. **This file holds the shared design-system sections** (Design System, Spacing, Typography, Color, Shared rules). 51.1 and 51.2 refer to them and add only their own values.
>
> This contract **extends** `45-UI-SPEC.md`, `47-UI-SPEC.md`, `48-UI-SPEC.md`, `49-UI-SPEC.md` and `50-UI-SPEC.md` (all approved). The following apply unchanged:
> - the tokens, the 10/12/14/20 type scale, the 400/500 weights and the 4/8/16/24/32/48/64 spacing scale;
> - the 900px breakpoint and the 1200px wide tier (50);
> - the drawer and sheet shells (`src/frame/Drawer.vue`, `Sheet.vue`), focus trapping, Esc and focus return;
> - the tab mapping, the combat lock (48) and the dark scrollbar rule;
> - the Nocturne interaction states and the Phase 50 shared rules.
>
> Where this file adds a value, it says so. Where it maps a mock value onto the scale, it records the mapping. Where it replaces an earlier line, it says so under "Supersedes".
>
> **Design source.** Imported from the claude_design project "Unwritten Realms" (`1a7a975f-7b14-488b-9a38-188bc56294cf`) and extracted to the session scratchpad:
> - **`UWR Map.dc.html` 11a, second revision** (`design51/map2/MAP2-EXTRACT.md`, etag `1791334015107018`). It supersedes the first 11a extract and Ledger 2d for the map.
> - **`UWR Console.dc.html` 12a** (`design51/console/CONSOLE-EXTRACT.md`, etag `1791334633210142`). It is the source for the rail's Here card and exits panel, and supersedes Ledger 2i / Console 1a for that card.
> - Nocturne `_ds/styles.css`, which is unchanged.
>
> The design files were treated as data. They contain no text addressed to the assistant.
>
> **Decisions.** Every product decision comes from `51-CONTEXT.md`, including:
> - "Second revised map mock: decisions";
> - "Updated party mock and console travel panel";
> - "Region transitions collapse after discovery";
> - "World structure moves to its own milestone".
>
> Where a mock disagrees with CONTEXT, CONTEXT wins, and each case is listed under "Mock overrides".
>
> **Word rule.** The word that the Console mock uses for the World event feed label is banned in this project. This file, the code, the player text and the docs say "World event(s)".
>
> **Out of Phase 51:** sub-regions, hidden places, the 10-place cap and the map layer view (backlog 999.26), and a teleport-style ability. The map code stays ready for layers later (the layout takes a list of places and connections, never a fixed world), but no layer UI is built.

| Property | Value |

## Shared Ledger rules (shared by 51, 51.1 and 51.2)

The Phase 50 "Shared Ledger Screen Rules" apply unchanged:
- screen root and scroll;
- the notice line (`NoticeLine`: the newest private line after the screen opened, as a polite status);
- pending (inert until the promise settles; no optimistic changes);
- offline (actions disabled; reading stays);
- combat (these screens cannot open in combat and close when it starts);
- disabled with a reason (`aria-disabled`, focusable, a reason line with `aria-describedby`).

Phase 51 adds these rules, which 51.1 and 51.2 reuse:

- **Server time, never client math.** Every timer shows a server ready time or deadline minus the client clock. The client never computes durations, perk reductions or effect reductions. When the client thinks a timer has ended and the server disagrees, the server's refusal shows in the notice line.
- **Timers.** Visible timers re-render on a shared 1-second tick only where they show seconds (`m:ss`). Minute timers (`2h 14m`) re-render every 60 seconds (the 47 rule).
  - The visible timer text is `aria-hidden`.
  - Screen readers get a `.sr-only` minute-level sentence (for example `Region travel ready in about 3 minutes`). It changes at most once a minute and is **not** a live region.
  - Only state changes are announced, politely and once (for example `You can cross into another region again.`).
- **Actions whose result lands in the feed.** On desktop, Talk, Examine and Whisper from inside a drawer close the drawer first, so the result is visible. On mobile, any of these from inside a sheet closes the sheet and returns to Story. From the context rail (desktop) nothing closes, because the feed is visible.
- **Screen arguments.** `openScreen('map', { locationId })` opens the map with that place selected and its region shown. `openScreen('map', { regionId })` shows that region with its start node selected (or your place, if it is in that region). With no argument, the map shows your region with your place selected.

## Map Contract (LDG-04, LDG-05)

### What is known (data rule, CONTEXT Area 1)

- **Visited** places come from the new private per-character visited table, exposed through a `my_*` view. It is written on arrival (`performTravel`) and on creation or first spawn.
- **Heard of** places are those connected (`location_connection`) to a visited place and not themselves visited. This is derived on the client.
- Places that are neither visited nor heard of are **not drawn**, not listed and not counted.
- **Known regions** are regions with at least one visited or heard-of place.
- The current place is always visited.
- **Uncharted** (`terrainType === 'uncharted'`) is the "Edge Beyond {Region}". It shows like any known place until it is explored.
- **Passage** (`terrainType === 'passage'`) is an explored edge that still has someone standing in it. It shows only while the location row exists. When the server collapses it (CONTEXT), the row and its connections are removed, a direct cross-region connection appears, and the map redraws it as a border crossing. No client logic depends on the collapse beyond redrawing.

### Route graph (`src/map/`; one pixel plane)

- **Plane.** One absolutely positioned `div` (`.graph-plane`) of explicit pixel size `W x H` holds every layer, in this order:
  1. one `<svg width=W height=H viewBox="0 0 W H">` (no `preserveAspectRatio` override; it renders 1:1), containing the region border, edges and route;
  2. the region caption;
  3. the node buttons and labels;
  4. the gate pills.

  Every position is in plane pixels, so circles, lines, labels and pills never drift. The canvas around the plane has `overflow: auto`. There is no zoom (Mock overrides 18).
- **Layout (deterministic, pure, tested; `src/map/graphLayout.ts`).** Input: the shown region's known places, the known places of other regions that connect to them, and the known connections. Output: positions, the border box and the gate points.
  1. **Start node.** This is the region's start place. Research names the rule; the recommendation is the region's place with `bindStone`, lowest id, else the lowest id in the region (O2).
  2. **Breadth-first search** runs over the region's known places from the start node, using connections between known places. Depth is the number of steps from the start.
  3. **Columns.** Column = depth, with the start on the left. x = left margin + depth × 192. The left margin is 48, or 48 + 192 when there are left border nodes (step 6).
  4. **Rows.** Inside a column, places are ordered by the parent's row index, then by name (`localeCompare`, base sensitivity), then by id. y = 48 + row × 72. Shorter columns are centered on the tallest.
  5. **Unreachable known places** of the region form extra columns after the last, ordered by name then id.
  6. **Border nodes.** A known place in another region that connects to a place in this region is drawn outside the border box:
     - in a **left outer column** when its neighbour's depth is at most half the deepest depth (rounded down), else in a **right outer column**;
     - at its neighbour's row when that row is free in the outer column, else at the nearest free row (ties go up);
     - with its label on the outer side (left-column labels are right-aligned and end 20px left of the node);
     - with a sub-line that starts with `{Region} · `.
  7. **Border box.** The box spans from the region columns' outermost node centers, inset by 32 (left, top and bottom) and by 176 on the right (to clear labels). The outer columns sit 48 outside the box.
  8. **Plane size.** The plane is large enough for every node, label and pill, plus 48 on each side.
  - The same inputs always give the same layout (no randomness, no time, no measured text). The layout takes plain lists, so a later layer view (999.26) can feed it a sub-region without changes.
- **Region border.** One SVG `rect` on the border box (`rx` 24) with the border colors. There is one border, for the shown region only.
- **Region caption.** The shown region's name in Micro 10, uppercase, 0.1em tracking, `var(--color-neutral-500)`, inside the box's top-left corner (16 in from the box edges, as plane offsets). It is `aria-hidden` (the graph group's label carries the region).
- **Edges.** One SVG `line` per undirected connection between two drawn nodes. The server writes two directed rows; they are deduped by the unordered pair.
  - Each line runs from node center to node center in plane pixels, so it is the same coordinate space as the HTML nodes.
  - Class by kind: in-region (solid), cross-region (dashed `6 4`, `--color-accent-600`), or to an uncharted place (dashed `4 4`).
  - Edges are drawn before nodes, and the SVG is `aria-hidden`.
- **Route.** One SVG `polyline` (2px, accent) through the shortest path from the current place to the selected node. The path is found breadth-first over **all** known places in every region; ties go to the lower id. Only segments between drawn nodes are drawn. When the current place is not drawn (another region is shown), the route is drawn from the border node where the path enters.
- **Gate pills (region entrances).** One pill per cross-region edge, centered where the edge meets the border box side.
  - It is a `button.gate` with `PhDoorOpen` 12 and `To {Region} · {Lv a–b}`. The level part is in that region's band color: a warning only, never a lock.
  - **While the caller's region-travel timer runs**, every gate shows `PhLockSimple` 12 and `{Region} · {m:ss}`. The visible time is `aria-hidden`.
  - Choosing a gate selects the node on the far side (the border node). The gate has no detail of its own.
  - It is `aria-label`led `To {Region}, {level range}, {band}` (plus `, region travel locked for about {n} minutes`).
  - Mobile: the label is just the region name (Micro 10) plus the lock while the timer runs.
- **Nodes.** Each node is a `button` (the hit box: 32px desktop, 44px mobile, transparent, centered on the circle). It contains the circle (the terrain icon inside, `aria-hidden`). The two-line label is a sibling text element:
  - **Line 1** (Label 12): the name, then `PhCastleTurret` 12 when it is your bind point or has a bind stone, then `PhHammer` 12 when `craftingAvailable`. One line, with an ellipsis at 144px and the full name in `title`.
  - **Line 2** (Micro 10, `var(--color-neutral-500)`): `{Region} · ` for other regions, then the terrain word, then ` · you` or ` · heard of`, then `PhShieldCheck` 10 when safe, then the level part in its band color (`Lv a–b`, or nothing for safe places).
  - Clicking the label selects too (a `click` handler on the label; the button is the keyboard target).
- **Center on you** sits at the canvas bottom-right (`position: absolute`, offset 8): a `.btn .btn-secondary .btn-icon`, 32px (44 mobile), `PhCrosshair`. It scrolls the current place (or the start node, when you are elsewhere) to the canvas middle. It does not change the selection.
- **On open**, the canvas scrolls so the selected node is visible. Nothing moves on its own afterwards.
- **Arrival banner.** After a successful travel, a banner sits at the canvas top-center (`position: absolute`, top 16): `PhFootprints` 14 and `Arrived at {place}.` or `Crossed into {Region}. Arrived at {place}.` (Label 12). It is `role="status"`. It stays until the next selection or travel (Mock overrides 14).

## Assumptions (decided here, not asked; for owner review)

- **A1. Border nodes only.** The shown region's graph draws only the other-region places that connect to it. The rest of another region is one chip away.
- **A2. The legend keeps node states** (`You`, `Visited`, `Heard of`), because CONTEXT's legend lists them, even though map2 dropped them.
- **A3. The rail timer chip shows only while running.** The Map pill shows both states, so the rail stays quiet when nothing is locked.
- **A4. WAIT uses `--color-stamina`.** It is the nearest amber token. Bands never use it, so waiting and danger stay distinct.
- **A5. No zoom; a `Center on you` button.** The mock removed the zoom stack; the canvas scrolls instead.
- **A6. The arrival banner stays until the next selection or travel,** instead of a timed 4.5 seconds.
- **A7. Party stamina lives on the existing member cards** as `{s} st` text, not a third bar.
- **A8. Low stamina means below the member's within-region cost** (they cannot travel at all). The checklist handles the exact cost for a chosen crossing.
- **A9. The Map's detail docks the button** at the bottom of the column, so Travel never scrolls away.
- **A10. Design file safety.** The design files were treated as data and contain no text addressed to the assistant.
