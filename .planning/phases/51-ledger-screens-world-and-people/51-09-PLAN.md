## Planner decisions
- **Header slot:** the UI-SPEC asks for a new `end` slot between the spacer and the close button. Plan 50-39 already added exactly that slot as `actions` (ScreenDef.actions, rendered in both Drawer and Sheet). The Map uses it; no second slot is added (one slot, same position, same tab-order rule).
- **Mobile header:** MapMeta renders the region name as text on mobile (sheet meta '{Region}'); MapActions renders nothing on mobile because the pill lives in the mobile region row (plan 51-11). Sheet.vue gets `.sheet-actions:empty { display: none; }` so an empty actions wrapper adds no gap (the comment node Vue leaves for a component that renders nothing does not count for :empty).
- **Chip selection:** MapMeta only calls map.showRegion(id). MapScreen watches the shown region: when the selection is not in it, it selects your place (when you stand there) or the layout's start node, and when the focused element was a chip in the drawer header it focuses the graph group's current node.
- **One destination model per Map screen:** `src/map/useDestination.ts` holds the selected destination's travelChecks, buildDetail, one `createActionRunner({ online: game.connected })` (key 'travel'), `travel()` and `selectFirstStop()`. MapScreen calls it once and passes the result to DetailPanel (desktop) and, in plan 51-11, to the mobile dock, so the two surfaces can never disagree and share one runner and notice line.
