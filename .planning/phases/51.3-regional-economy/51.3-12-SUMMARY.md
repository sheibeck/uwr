# Phase 51.3 Plan 12: Region economy chain Summary

The approved region_economy route is now wired into the game. It runs only when `economy_dials.aiEnabled` is on. The job is queued after a region fill, after a late enemy type (from a quest or added while the region was pending), and on `/economy design`. It is always charged `phase_only` and never breaks world generation.

## What was built

- **`helpers/region_economy.ts`**
  - `startRegionEconomy(tx, region, who, { retryFailed })` runs these gates in order and returns the first that applies:
    1. `getDials(tx).aiEnabled !== true` returns 'off' (a missing row reads as off).
    2. An existing region_economy row returns 'exists'. A failed row is re-queued only with retryFailed.
    3. A region with no locations returns 'no_region'.

    If every gate passes, it calls `enqueueLlmJob` with route region_economy, `SOURCE_KEYS.regionEconomy(id)`, budget 'phase_only', and request `{ regionId, mode: 'region', enemyTemplateId: '0', characterId, input }`. A refusal logs one console.info line (route, region id, reason; no identity), writes nothing, and returns `refused:<reason>`. Otherwise it calls `markRegionEconomyPending(..., job.id, foreign region ids JSON)` and returns 'enqueued' or 'duplicate'.
  - `startEnemyLoot(tx, enemyTemplate, regionId, who)`:
    - Gates, in order: aiEnabled, then a complete region row ('not_ready' otherwise), then no enemy_loot_entry rows for the enemy ('exists' otherwise).
    - It enqueues mode 'enemy' with `SOURCE_KEYS.enemyLoot(id)` and budget phase_only.
  - **Follow-up:** after a region-mode apply sets status 'complete', every region enemy template with no loot entries gets `startEnemyLoot`. It uses the region job's player and the stored characterId, with the switch checked once and each start in try/catch.
- **`helpers/llm_apply.ts`**
  - `applyWorldFillResult` calls `startRegionEconomy` right after the COMPLETE update, on a fresh region row, inside try/catch. A failure logs `Region economy start failed for region <id>: <errName>`.
  - The npc_conversation new-enemy branch calls `startEnemyLoot` after the `location_enemy_template` insert, also in try/catch.
  - `applyLlmResult` dispatches region_economy to `applyRegionEconomyResult`, and `applyLlmFailure` dispatches it to `failRegionEconomy`. Neither writes a player line.
- **`helpers/llm_executor.ts`:** a region_economy job claims under `LLM_NARRATION_MAX_IN_FLIGHT`, the same limit as combat_narration, so the last slot stays free for gameplay. The narration age expiry is unchanged and applies to narration only.
- **`helpers/economy_admin_commands.ts`:** new verb `/economy design <region...>` (no name gives help), and `ECONOMY_COMMAND_USAGE` now lists `/economy design NAME`. After the admin check, the handler finds the region by case-insensitive name and calls `startRegionEconomy(ctx, region, { playerId: ctx.sender, characterId: character.id }, { retryFailed: true })`. The line it writes depends on the result:

  | Result | Line |
  |---|---|
  | off | `The AI economy is off. Turn it on with /economy ai on first.` |
  | exists | `<Region> already has an economy (designed\|pending).` |
  | unknown region or no locations | `No region by that name.` |
  | queued | `Economy design queued for <Region>. It runs in the background; see /economy region <Region> for the status.` |
  | refused, halted or ceiling | `LLM_RESTING_LINE` |
  | any other refusal | `Economy design refused: <reason>.` |

## Tests

- **`region_economy_chain.test.ts` (new, 20 tests):** strict mock under the recording schema, driven through the real apply layer. Covers:
  - the fill hook: off by default (no economy_dials row, and aiEnabled false); on (one job, budget phase_only so budgetDay is '' and no player-budget row, dedupe sourceKey `region:1`, request mode/ids/input equal to `buildRegionEconomyInput`); a second fill completion (one job, one row); halted (nothing written, one console.info line with no identity); a forced throw from economy_dials (fill COMPLETE, completion line written);
  - starter reuse writes nothing;
  - the npc_conversation late enemy: on with a complete region gives one enemy job; pending, failed, missing, switch off and no dials row give none; an enemy with loot entries gets 'exists';
  - dispatch: success writes the economy, failure sets the row to failed, neither writes a player line;
  - the follow-up enemy job after a region apply (and none with the switch off);
  - the start gates: off, no_region, retryFailed;
  - end to end: a fill, then the real `runLlmJob` with a scripted fetch returning the region_k0 reply in the ok_json Claude envelope. The outcome is 'completed', with one fetch and none left, region status complete, 9 or more economy_item rows, loot entries, 3 region_recipe rows and no follow-up job.
