# Phase 51.3 Plan 10: Region economy input builder and idempotent apply Summary

**The input builder turns a region's stored rows into the route input: region facts, lowercase terrains, enemies as E handles, the server's recipe tier slots, and a foreign offer that lists neighbors first. The apply writes a validated reply once, whatever the transaction replays: gatherables, creature drop, trophy and gear, AI loot tables, recipes with req4, scrolls and region_recipe rows, then status complete. Every number comes from the design and economy rules.**

## Accomplishments

- `buildRegionEconomyInput`, region mode:
  - Reads only database rows: name, biome, area level from `areaLevel(danger, 0n)`, faction, and landmarks and threats parsed from JSON (malformed JSON gives []).
  - Terrains are counted by location, ordered by count then name, with `['plains']` when there are none.
  - Lists the distinct enemy templates, sorted by id, as E1..
  - `k` is the number of other regions with a complete economy and at least one gather or drop material. `recipeTierSlots(k)` gives the tiers, `orderForeignRegions` orders the regions (neighbors first), and the first `min(3, k)` are used.
  - Each picked region's materials go through `foreignOffer`, in region order, as F1..
- Enemy mode returns one enemy (E1), no slots, and the region's gather and drop materials.
- `readEconomyJobContext` parses `{ regionId, mode, enemyTemplateId, input }` and revives the four `REGION_ECONOMY_BIGINT_PATHS` plus the top-level ids with a local `a[].b` reviver. It does not import llm_apply.ts or llm_inputs.ts.
- `applyRegionEconomyResult` does these steps in order:
  1. Pending guard.
  2. Parses the reply locally (whole text, else the first `{` to the last `}`).
  3. Snapshots the taken names.
  4. Runs `validateRegionEconomyReply`. A null result sets status `failed` and writes nothing else.
  5. `ensureItem` per slotKey for `gather:*`, `drop:/trophy:/gear:<enemy>`, `recipe:<n>` and `scroll:<n>`.
  6. Writes `aiLootTable` rows only when the enemy has none.
  7. Writes `recipe_template` keyed `region:<id>:r<n>`. req3 is undefined and req4 is 0n/0n when absent. materialType is `materialKey(primary)`; consumables have none.
  8. Writes `region_recipe`: learnBy `scroll` for rare and above, with the scroll template, otherwise `research`. foreignRegionIds holds the decimal region ids.
  9. Sets status `complete` and updatedAt last.
- Late-creature mode only runs when the region is complete and the enemy has no loot rows. It uses `writeCreature` with the region's gatherables (ordered common, uncommon, rare, then id). An unusable reply writes nothing and changes no status.
- `failRegionEconomy` changes only pending to failed, only in region mode. `markRegionEconomyPending` inserts a pending row, or turns a failed row back to pending with the new jobId. It returns false when a pending or complete row exists.
- Nothing in this module writes a player line (`appendPrivateEvent|writePrivateSegments|fail(ctx` grep = 0).

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Re-run renamed its own rows after a partial write**
- **Found during:** Task 2 design.
- **Issue:** The plan says to snapshot every item_template and recipe_template name. After a partial write (or a withTx re-run with state kept), the apply's own earlier items would count as taken names. The validator would then rename the recipe (for example to `<Region> Rivetbound Mace`), so it would no longer match the reused output item.
- **Fix:** `openBook` leaves out the names of rows the apply owns (its slotKeys and recipe keys). A test checks that a partial write followed by a re-run equals one clean apply.
- **Files modified:** spacetimedb/src/helpers/region_economy.ts
- **Commit:** bba3278e

**2. [Rule 2 - Robustness] region_recipe and the scroll are ensured even if the recipe key exists**
- **Found during:** Task 2.
- **Issue:** Skipping the whole recipe when its key exists would leave out region_recipe after a throw between the recipe_template insert and the region_recipe insert.
- **Fix:** Reuse the existing recipe row, then look up the scroll by slotKey and region_recipe by recipeTemplateId. A test covers a throw on the region_recipe insert followed by a re-run.
- **Commit:** bba3278e

**3. [Rule 2] Context consistency guard**
- `readEconomyJobContext` returns null if `input.regionId` differs from the top-level `regionId`.
- The late apply returns if the validated enemy differs from the context `enemyTemplateId`.
- **Commits:** bba3278e, e044f581

There were no other deviations. Nothing was published, no route was registered, no enqueue was added, no prompt wording was touched, and STATE.md and ROADMAP.md were not edited.
