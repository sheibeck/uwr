## User Constraints (from CONTEXT.md)

### Locked Decisions

#### Economy dials (Area 1, owner)
- **Granularity:**
  - Global dials, each overridable per region.
  - Per-rarity-tier weights, so one tier can be tuned without shifting the rest (for example epic ×0.5, legendary ×0).
  - Per-item drop-rate overrides that an admin pins to a specific item template.
  - The owner chose "Add per-item overrides", the option that builds on per-rarity weights.
- **Dial set (all four):**

  | Dial | Range |
  |------|-------|
  | Rarity shift | −2…+2 tiers |
  | Drop rate | 0–300% |
  | Gold | 0–300% |
  | Gather rate | 50–300% |
  | Boss/named rarity bonus | 0…+2 tiers |

  - Every dial defaults to today's tuning, so a fresh install behaves exactly as now.
  - Every value is clamped to its safe range.
  - Every roll reads the dials.
- **Storage:** a private server config table (or tables) for global, per-region, per-tier and per-item values, seeded with defaults. The `llm_admin_state` singleton is the pattern: `.default()` columns plus ensure and patch helpers.
- **Admin path:**
  - A server-side `/economy` admin command, following `handleLlmAdminCommand` in `helpers/llm_admin_commands.ts`:
    - parse function
    - in-voice refusal through `fail`
    - plain-text output
    - routed from `submit_command`
  - It shows the dials, sets global values, sets per-region values, sets per-tier and per-item values, and resets them.
  - Example forms: `/economy`, `/economy rarity +1`, `/economy region <name> gold 150`, `/economy reset`.
  - It is backed by admin-only reducer(s) guarded by `requireAdmin`.
  - The Phase 52 admin screens get a panel later.
- **Timing:** a dial change takes effect on the next roll only. Loot already dropped and nodes already found keep their rolls.

#### The per-region AI economy job (Area 2, owner)
- **Size, "Small" (the server fixes these counts; the AI fills them):**
  - 3 gatherable materials per region
  - 1 drop material per enemy type
  - a loot table of 4–6 entries per enemy type, drawn from materials, gear and trophies
  - 3 regional recipes
- **Gear:**
  - The AI supplies each gear item's name, slot and kind, and description.
  - The server computes every stat through the shared item rules. Quest rewards already work this way: `computeQuestRewardStats` in `reducers/quests.ts`.
  - Generated names never clash with existing templates. Follow the `questRewardItemName` pattern, because many lookups resolve by name and the starter upsert overwrites by name.
- **Timing:**
  - The job is chained right after region generation completes. The hook is `applyWorldFillResult` in `helpers/llm_apply.ts`, where the world state becomes COMPLETE.
  - Region generation stays as fast as today.
  - The route is cap-exempt like world_gen but is counted in the global daily ceiling.
  - A refused or failed job falls back silently.
  - Starter-region reuse (`reuseStarterRegion` in `world_gen.ts`) never re-runs it.
- **Results:** stored once and reused. Apply must be idempotent, because the `withTx` body in `llm_run` may run more than once. Look up by region and key before inserting.
- **Late enemies:** enemy types added later (the npc_conversation quest effect in `llm_apply.ts`, around line 877) get a small follow-up job, once per enemy type. It designs that enemy's loot table from the region's existing materials.
- **The server owns every number:**
  - entry counts
  - the rarity mix by enemy level, better for bosses and named foes
  - gold ranges
  - drop and gather rates
  - all item stats

  The AI supplies only names, kinds, descriptions, and which materials go into which recipe. Its output is validated and clamped.

#### Regional and cross-region recipes (Area 3, owner)
- **When rare recipes appear:**
  - A region's job adds a rare recipe only when at least one other generated region exists.
  - Epic and legendary recipes need two or three other regions.
  - The job pulls the extra materials from those older regions.
  - Until enough regions exist, the region's recipe slots are common and uncommon.
  - Common and uncommon recipes use local materials.
  - No backfill of older regions.
- **How players learn them:**
  - Common and uncommon regional recipes join the existing research flow at a crafting station (`research_recipes`). You see them when you hold the materials.
  - Rare and better come as recipe scrolls dropped by bosses and named foes in that region. The existing `learn_recipe_scroll` flow applies.
- **Vendors:**
  - A region's vendors may stock that region's common and uncommon materials.
  - Rare materials, and anything from other regions, must be gathered or looted, so cross-region recipes mean travel.
  - Today the 50-24 restock is region-agnostic: `restockVendor` iterates all of `item_template`. It needs a region rule.
- **Gathering:** a region's gatherables appear only in that region, on matching terrain, alongside today's terrain gatherables. `getGatherableResourceTemplates` and `spawnResourceNode` gain a region dimension.

#### Fallbacks, rolls and the prompt (Area 4, owner)
- **Fallback:**
  - Until the job lands, or if it fails, a rule-based loot table per creature type applies. It is built from existing materials, junk and level-fit gear, plus gold, so a kill is never empty.
  - The rule-based recipes (50-25) and terrain gatherables keep working as today.
- **Legendary:**
  - The rarity mix rises with enemy level.
  - Normal enemies top out at epic. Legendary drops only from bosses and named foes, subject to the dials.
  - Today `rollQualityTier` never yields legendary.
  - In production "boss" means `named_enemy` / `isBossOrNamed` (`helpers/combat_moments.ts`), because `enemy_template.isBoss` is never set.
- **Same rolls:** fix the identical rolls for enemies of one template in a fight. Seed each enemy's roll separately. Today the seed is timestamp + character id.
- **Prompt approval:**
  - The planner drafts the exact prompt wording (a route block in `data/llm_layers.ts`) as a plan artifact, and the coordinator shows it to the owner before execution.
  - Until the owner approves, the route stays switched off and the fallbacks run, so nothing paid happens.
  - No paid calls in tests.

## Summary

Today a kill drops nothing because `loot_table` has zero rows and `findLootTable` (`reducers/combat.ts:713-743`) finds no table, so `generateLootTemplates` (`combat.ts:760-810`) returns `[]` and gold falls back to `template.level`. Reading the loot path also turned up three more bugs the rewrite must fix:
1. **Identical rolls:** every enemy of one template in a fight rolls from the same seed, `ts + character.id` (`combat.ts:2078`). This is the bug the owner already knew about.
2. **Correlated rolls:** the gear roll (`seed+19`, `combat.ts:784`) and the rarity roll (`seed+53`, `items.ts:154/158`) are the same number shifted by 34 mod 100. So once gear drops, its rarity is almost fixed. At T1 a gear drop is uncommon only when the gear roll is exactly 0. The intended rate is 5-35%.
3. **Lost gold:** in a fight with several enemies, only the last enemy's gold is kept. The update at `combat.ts:2144` spreads a `character` row read once per participant (`combat.ts:2073`), so each later enemy's update overwrites the earlier ones.

The phase is mostly brownfield wiring around one new pure rules module. The recommended shape:
- **Rules:** one import-free `data/economy_rules.ts` holds every number: dials, the rarity mix, splitmix rolls, gold, gather yield, fallback profiles, recipe tier slots, cross-region picks and name cleaning.
- **Storage:** seven new private tables. No new column on any existing table, so nothing needs `.optional().default(undefined)` and nothing can force a clear.
- **AI route:** one new JSON route, `region_economy`, with two modes (region and late creature). The response schema enforces the "Small" counts through fixed-key objects.
- **Off by default:** the route is gated by `economy_dials.aiEnabled`, default false. While it is off, nothing is enqueued and the existing world_gen characterization snapshots stay byte-identical.
- **Fallbacks:** they are pure functions evaluated at kill time from existing templates, using the pre-v2.0 per-creature numbers (git `9ac55586^:spacetimedb/src/seeding/ensure_enemies.ts`). Nothing is stored for them, so an AI table that lands later simply takes over.

**Primary recommendation:** build and ship the server in this order: pure rules first, then the new tables, then the loot rewrite with fallbacks (publish A), then gathering/vendor/crafting region rules and `/economy`, then route registration with the prompt draft gated off (publish B). Keep `region_economy` out of the sweep and smoke lists and use `budget: 'phase_only'`, so nothing paid can happen until the owner approves the wording and types `/economy ai on`.

### Pattern 1: Data model (Q1)

All seven tables are new and private (no `public: true`). They are registered in `schema({...})` (`schema/tables.ts:2394-2519`), whose keys are snake_case and match the code's `ctx.db.<snake_name>`.

| Table | Key | Columns | Indexes | Purpose |
|-------|-----|---------|---------|---------|
| `economy_dials` | `id: u64 pk` (singleton 1n) | `rarityShift: i64.default(0n)`, `dropRatePct: u64.default(100n)`, `goldPct: u64.default(100n)`, `gatherRatePct: u64.default(100n)`, `bossRarityBonus: u64.default(0n)`, `tierCommonPct`, `tierUncommonPct`, `tierRarePct`, `tierEpicPct`, `tierLegendaryPct` (each `u64.default(100n)`), `aiEnabled: bool.default(false)` | — | Global dials plus the five per-tier weights, and the route switch. Missing row = defaults (Pitfall 3). |
| `economy_region_dial` | `regionId: u64 pk` | `rarityShift: i64.optional()`, `dropRatePct`, `goldPct`, `gatherRatePct`, `bossRarityBonus` (each `u64.optional()`) | — | Per-region overrides; `undefined` = inherit global. |
| `economy_item_dial` | `itemTemplateId: u64 pk` | `dropRatePct: u64` (0-300) | — | Per-item pin. |
| `region_economy` | `regionId: u64 pk` | `status: string` (`pending`/`complete`/`failed`), `jobId: u64`, `otherRegionIds: string` (JSON array of bigint strings), `createdAt`, `updatedAt: timestamp` | `by_status` (btree status) optional | Once-only lock and status for `/economy`. |
| `economy_item` | `itemTemplateId: u64 pk` | `regionId: u64`, `role: string` (`gather`/`drop`/`trophy`/`gear`/`recipe_output`/`scroll`), `slotKey: string`, `kind: string` (MaterialKind or ''), `rarity: string`, `terrain: string`, `timeOfDay: string`, `enemyTemplateId: u64` (0n unless drop/trophy/gear) | `by_region` (regionId), `by_enemy` (enemyTemplateId) | **The item origin tag.** It is how `item_template` rows get a region without a breaking change. It also stores each material's kind and the idempotency key (`slotKey`). |
| `enemy_loot_entry` | `id: u64 pk autoInc` | `enemyTemplateId: u64`, `regionId: u64`, `itemTemplateId: u64`, `role: string`, `weight: u64` | `by_enemy` (enemyTemplateId) | AI loot tables, 4-6 rows per enemy type. No header row: "has a table" = `by_enemy.filter(id)` is non-empty. |
| `region_recipe` | `recipeTemplateId: u64 pk` | `regionId: u64`, `tier: string`, `learnBy: string` (`research`/`scroll`), `scrollTemplateId: u64` (0n none), `foreignRegionIds: string` | `by_region` | Regional recipe metadata for research, scrolls and the `/economy` report. |

Rules:
- A new table needs no `.default()` for migration (new tables are always allowed). `.default()` on the singleton is still the right habit: a later added column can then follow the same pattern (`llm_admin_state`, `schema/tables.ts:2321-2334`).
- `slotKey` values: `gather:common` / `gather:uncommon` / `gather:rare`, `drop:<enemyTemplateId>`, `trophy:<enemyTemplateId>`, `gear:<enemyTemplateId>`, `recipe:<n>`, `scroll:<n>`. Each is unique per region and is the "look up by region and key before inserting" key.
- `recipe_template.key` for regional recipes: `region:<regionId>:r<n>`. This never collides with the `gen:...` keys from `recipeKey` (`recipe_rules.ts:233`).
- Keep `loot_table` / `loot_table_entry` in the schema, unused. Removing non-empty tables is forbidden by auto-migration [CITED: spacetimedb.com/docs/databases/automatic-migrations], and deleting them buys nothing.

**Response schema (one route, two modes, exact counts enforced by the grammar through fixed keys):**
```typescript

const TROPHY = obj({ name: S, description: S });

  name: S, slot: enumOf(['weapon', 'chest', 'legs', 'boots']),
  weaponType: enumOf([...WEAPON_TYPES, 'none']), armorType: enumOf(['cloth', 'leather', 'chain', 'plate', 'none']),

});
const CREATURE = obj({ enemyRef: S, drop: DROP, trophy: TROPHY, gear: GEAR });

export const REGION_ECONOMY_SCHEMA = deepFreeze(obj({
  region: nullable(obj({
    gatherables: obj({ common: GATHERABLE, uncommon: GATHERABLE, rare: GATHERABLE }),   // exactly 3

```
How the "Small" counts are enforced:
1. **Grammar:** fixed required keys make exactly 3 gatherables and 3 recipes, and exactly one drop, trophy and gear per creature.
2. **Prompt:** the creature count equals the listed handles.
3. **Server:** the validator keeps the first creature per known `enemyRef`, ignores unknown or duplicate refs, and leaves missing creatures on the fallback. Each loot table gets 4-6 entries from the server's composition rule (Pattern 4), never from the model.

`maxItems` and numeric bounds are rejected by the structured-output subset (`schema_lint.ts:162-169`), so arrays cannot be bounded in the schema.

### Pattern 4: Rolls and dials, one pure module (Q4)

`data/economy_rules.ts` is import-free, ES2020, never throws. It may be imported by `vendor_stock`, the `llm_schemas` kind list, and later by the client through `@game-data`. Contents:

**Dial ranges and combination (most specific wins within a dial; separate axes multiply):**
```typescript
export const DIAL_RANGES = {
  rarityShift: { min: -2n, max: 2n, def: 0n },
  dropRatePct: { min: 0n, max: 300n, def: 100n },
  goldPct: { min: 0n, max: 300n, def: 100n },
  gatherRatePct: { min: 50n, max: 300n, def: 100n },
  bossRarityBonus: { min: 0n, max: 2n, def: 0n },
  tierPct: { min: 0n, max: 300n, def: 100n },      // per QUALITY_TIERS entry
  itemDropPct: { min: 0n, max: 300n, def: 100n },
} as const;
export function effectiveDials(global, region?, ): EffectiveDials  // region field ?? global field, then clamp
export function itemWeight(baseWeight: bigint, itemPct?: bigint): bigint  // base × clamp(itemPct)/100
```
How the levels combine:
- **Scalar dials:** global → region → item. The region value replaces the global one, and the item pin replaces the drop rate for that item's weight. Never compound region × global.
- **Tier weights:** a separate axis that multiplies the rarity mix.
- **Boss bonus:** adds to the rarity shift for boss and named foes only.

Test every level with a clamp at both ends and with an absent override.

**Rarity mix:**
- `baseMix(level, danger)` returns 5 weights summing to 100.
- At default dials it equals today's `rollQualityTier` distribution (`helpers/items.ts:132-165`):
  - T1 (L1-10): `[100-u, u, 0, 0, 0]` where `u = min(35, min(30, 5L) + db)`, and `db = floor((danger-120)/10)` when danger > 120.
  - T2+: `[wC-b, wU, wR, wE+b, 0]` where `b = min(10, max(0, floor((danger-120)/15)))` and the `TIER_RARITY_WEIGHTS` row (`items.ts:100-106`).

  Pin this with a parity test over L1-50 × danger {100..1000}.
- `shiftMix(mix, k, cap)` moves every tier's weight k tiers up (or down), piling overflow on the cap (or on common).
  - Normal foes: `k = shift`, `cap = 'epic'`.
  - Boss and named foes: `k = shift + 1 (built-in "better for bosses", SC2) + bossBonus`, `cap = 'legendary'`.
  - Legendary weight for a normal foe is always 0, whatever the dials.
- Then multiply each tier by `tierPct/100`; if everything is 0, return `common`.

**Rolls:**
- `economyRoll(seed, index): bigint` uses the same splitmix64 step as `salvageRoll` (`crafting_rules.ts:847-853`) but returns the full 64-bit value. `rollBelow(seed, index, n) = economyRoll % n`.
- **Per-enemy seed:** `lootSeed(ts, characterId, combatEnemyId) = BigInt.asUintN(64, ts*1000003n + characterId*7919n + combatEnemyId*104729n)`. `combat_enemy.id` is unique per enemy row in a fight, which fixes the identical rolls.
- **Fixed indexes in one const object** (never additive offsets on a raw timestamp):
  - `PICK_COUNT: 1`, `PICK: 2..9`
  - `GEAR_CHANCE: 10`, `GEAR_PICK: 11`, `RARITY: 12`, `CRAFT_QUALITY: 13`, `AFFIX: 14`
  - `GOLD: 20`, `ESSENCE: 21`, `MODIFIER: 22`, `SCROLL: 23`, `SCROLL_PICK: 24`
  - `GATHER_QTY: 30`

  Pass `economyRoll(seed, CRAFT_QUALITY)` and `economyRoll(seed, AFFIX)` as the `seedBase` into the existing `rollQualityForDrop` / `generateAffixData`. Their internal +67/+37/+41/+43 offsets then act on independent bases.

**Pick count from the drop rate:** `picks = pct/100 + (rollBelow(.., PICK_COUNT, 100) < pct%100 ? 1 : 0)`. At the default of 100% that is exactly one "common pick", the same as today's one junk pick. 0% gives none; 300% gives three.

**Gear chance:** `min(100, (profile.gearChance + min(25, 2L)) × dropPct/100)`. This is today's formula (`combat.ts:773-775`), scaled.

**Gold:** `(rollRange(goldMin, goldMax) + L) × goldPct/100`, then the existing `goldFindBonus` perk. Credit it once per participant per fight, from a fresh row read (Pitfall 2).

**Gather yield:** `max(1, qty × gatherRatePct/100)`. Apply it in `finish_gather` after the base 2-6 roll and before the perk bonuses (`items_gathering.ts:155-163`). Modifier reagents stay at 1.

**Legendary affixes:** `AFFIX_COUNT_BY_QUALITY.legendary` is 0 today (`data/affix_catalog.ts:248-254`). Set it to 3, which uses `magnitudeByTier[3]` (4n), with no rare cap. The only other caller is the admin `/createitem` (`reducers/commands.ts:420`), where this is also correct.

### Pattern 6: Regional recipes (Q6)

**Tier slots by the number k of other regions with a complete economy** [ASSUMED, discretion]:
- k=0: common, common, uncommon (all local)
- k=1: common, uncommon, rare (1 foreign region)
- k=2: uncommon, rare (1), epic (2)
- k≥3: uncommon, epic (2), legendary (2, or 3 under Option B below)

At least one research-learnable slot always remains.

**Foreign pick:** candidates are other regions with `status 'complete'` and at least one gather or drop material. Order: neighbors first (`buildRegionContext`, `world_gen.ts:111`), then ascending id. Pick deterministically by rotation from `regionId`, then offer up to 4 materials per picked region (prefer uncommon and rare) as `F` handles. Record the picked ids in `region_economy.otherRegionIds`.

**Validation and repair (pure, in `region_economy_validate.ts`):**
- Resolve handles. Drop unknown handles and duplicates.
- The primary must be local, with a kind in `PRIMARY_KINDS[category]` (`recipe_rules.ts:95-100`). If the category does not fit, derive it from the primary's kind (metal → weapon, hide/cloth → armor, trinket → accessory, edible → consumable). wood and base are secondary only. If no local material can be primary, drop the recipe: the 50-25 rule recipes still work.
- Rare and above: the distinct foreign regions must equal the slot's count. Add the first offered material of each missing region and drop surplus foreign refs. Common and uncommon recipes get every foreign ref stripped.
- Truncate to 3 requirements. Counts come from the server table [ASSUMED]: common 3+1, uncommon 3+2, rare 3 + 1 foreign + 1 local, epic 3 + 2 + 2, legendary 4 + 2 + 2.

**The 3-requirement limit** (`recipe_template` has `req1..req3` only, `schema/tables.ts:428-444`; `planCraft` consumes three, `crafting_rules.ts:520-524`):

- **Option B:** legendary needs 3 foreign regions through a 4th requirement. This needs `req4TemplateId/req4Count: t.u64().optional().default(undefined)` on public `recipe_template`, plus `planCraft`, craft, salvage and the client crafting model.

### Anti-Patterns to Avoid
- **Additive seed offsets on one raw seed:** they correlate every roll (Pitfall 4). Use `economyRoll(seed, index)`.
- **Looking items up by name for generated content:** resolve regional items by `itemTemplateId` through `economy_item`. `findItemTemplateByName` (`items.ts:345-350`) scans, and the first match wins.
- **Storing the fallback tables:** they would need cleanup when the AI lands. Compute them at kill time instead.
- **Per-player budget for a world job:** `phase_only` instead.
- **Giving the model ids or numbers to return:** use handles in, handles out; the server maps them.

| Problem | Don't Build | Use Instead | Why |

## Common Pitfalls

### Pitfall 1: Name clashes with by-name lookups
**What goes wrong:** a generated "Iron Ore" or "Training Sword" is found first by `findItemTemplateByName`. The starter upsert (`ensureStarterItemTemplates`, `items.ts:501-521`) then overwrites a generated template with the same name on the next character creation. `learn_recipe_scroll` matches by recipe name (`items_crafting.ts:420-421`). `materialKind`/`primaryMaterialTier` read static maps by name.
**How to avoid:** `cleanItemName()` keeps letters, spaces, `'` and `-`, collapses whitespace, uses 1-4 words and at most 40 characters, and rejects `[ ] { } < >`. Uniqueness is case-insensitive against:
1. every `item_template.name`;
2. every `recipe_template.name`;
3. a static reserved set: `JUNK_DEFS`, `STARTER_*`, `MATERIAL_DEFS`, `CRAFTING_MODIFIER_DEFS`, essence names, `BASIC_RESOURCES`. Export the last of these from `items.ts:658` to data.
4. names already used in the same reply.

On a clash: `<Region> <name>`, then `<Region> <name> 2`, ... (the questRewardItemName stem). A name starting with `Scroll:` is never accepted from the model.
**Warning signs:** a regional item whose stats change after a new character is created; "You already know" for a recipe never learned.

### Pitfall 2: Gold lost in multi-enemy fights (existing bug)
**What goes wrong:** `ctx.db.character.id.update({ ...character, gold: (character.gold ?? 0n) + goldReward })` (`combat.ts:2144`) runs once per enemy against the same stale `character` (`:2073`). Only the last enemy's gold sticks.
**How to avoid:** sum the gold over the enemies, then do one update from a fresh `ctx.db.character.id.find`. The integration test is two enemies, with gold equal to the sum.

### Pitfall 3: Schema changes that force a clear, and missing singleton rows
**What goes wrong:**
- Adding a bare `.optional()` column to an existing table is refused (Phase 43 probe).
- Adding unique or primary key constraints to existing tables is forbidden [CITED: spacetimedb.com/docs/databases/automatic-migrations].
- `init` does not run on a republish (`index.ts:347-349` comment), so `economy_dials` has no row on the owner's database. The comment is at `index.ts:347-349`.

**How to avoid:**
- New tables only.
- `getDials(tx)` returns the defaults when the row is missing. It never fails closed the way `llmGate` does, because a missing row must mean "today's tuning", with AI off.
- Writes go through `ensureEconomyDials` + patch.
- Also call `ensureEconomyDials` in `init` for fresh installs.

### Pitfall 4: Correlated and identical rolls (existing bugs)
**What goes wrong:**
- `rollPercent(seed+19)` and `rollQualityTier`'s `(seed+53)%100` differ by a constant 34, so rarity is decided by the gear roll that let the gear drop.
- Identical seeds per template within a fight, and the essence and modifier seeds repeat per template too (`combat.ts:2094,2112`).

**How to avoid:** use `economyRoll(seed(ts, charId, combatEnemyId), INDEX)`. Tests:
- two enemies of one template give different loot (over a fixed timestamp set);
- the rarity distribution over 10,000 seeds is within ±2% of the mix.

### Pitfall 5: The budget refusing the job
**What goes wrong:** with `'player'` mode the explorer's $1/day budget or the 200 calls cap can refuse (`llm_budget.ts:182-185`). The kill switch or ceiling refuses in any mode.
**How to avoid:**
- Use `phase_only`.
- On `refused`, write nothing (or `failed`) and log once. Fallbacks serve.
- `/economy design` lets the admin retry later.
- At claim time, a halted or ceiling job is refunded and fails through `applyLlmFailure` (`llm_executor.ts:243-245`). Handle it as `failed`.

### Pitfall 6: Starter-region reuse and fill retries
**What goes wrong:** thinking that starter reuse needs a guard. `reuseStarterRegion` never runs the fill, so it never reaches `applyWorldFillResult`. The real double-entry risk is a FILL_ERROR retry (`retryWorldFill`, `world_gen.ts:677-708`) completing later.
**How to avoid:** the `region_economy` row is the once-only lock (`regionId` pk). Test that a second `applyWorldFillResult` for the same region does not enqueue a second job.

### Pitfall 7: Legendary leaking to ordinary kills of a named template
**What goes wrong:** named foes reuse the regular template (`pull_named_enemy` → `spawnEnemyWithTemplate(..., namedEnemy.enemyTemplateId)`, `reducers/quests.ts:493-525`). `isBossOrNamed` with a per-character `named_enemy` set (`combat_moments` usage, `combat.ts:2974-2978`) therefore marks every kill of that template by that character as named.
**How to avoid:** for loot, build the named set fight-exactly. Count only `named_enemy` rows of the participants with `isAlive === false`, `locationId === combat.locationId`, and `lastKilledAt.micros >= combat.createdAt.micros`. The pull sets `lastKilledAt` in the same transaction that creates the encounter, and the encounter insert sets `createdAt: ctx.timestamp` (`reducers/combat.ts:187-196`, verified).

### Pitfall 8: Vendors leaking cross-region materials
**What goes wrong:** `restockVendor` passes all of `item_template` (`index.ts:401`), and the band and profile rules admit any `slot:'material'` template.
**How to avoid:** the origin filter in the pure rule. Tests:
- another region's common material is never picked;
- the own region's rare material is never picked;
- the own region's common material is eligible;
- regional gear, trophies and outputs are never stocked.

### Pitfall 9: The economy job blocking play
**What goes wrong:** a non-silent route locks the client input queue (`queueGateActive`). A JSON route at `maxTokens 4096` holds an in-flight slot (cap 4) for tens of seconds.
**How to avoid:** a null indicator line (silent), and the background in-flight limit (`LLM_NARRATION_MAX_IN_FLIGHT`).

### Pitfall 10: Characterization snapshots and the route switch
**What goes wrong:** chaining from `applyWorldFillResult` writes `llm_job`, `llm_dispatch` and `region_economy` rows, which changes `llm_apply.characterization.test.ts` snapshots.
**How to avoid:** off by default with no row means nothing is written. Put new chained-path tests in their own file with the dials row seeded `aiEnabled: true`.

### Pitfall 11: Markup injection through generated names
**What goes wrong:** loot lines are `{{color:#..}}[Take <name>]{{/color}}` (`combat.ts:2157-2167`); a `]` or `{{` in a name breaks the console line or forges a link.
**How to avoid:** `cleanItemName` rejects those characters. Clean descriptions the same way, capped at 240 characters.

### Pitfall 12: Seed offset collisions with the existing roll catalogue
**What goes wrong:** existing additive offsets are 11/19/23 (loot), 37/41/43 (affixes), 53 (rarity), 67 (craft quality), +7 (racial gather), `*3n` (gold), `*7n/*31n` (essence), `*11n/*43n` (modifier). New rolls added in the same style collide or correlate.
**How to avoid:** all new rolls go through `economyRoll` with the indexes in one frozen object, and a test asserts the indexes are unique.

## Code Examples

### economyRoll (copy of the reviewed splitmix64 step)
```typescript
// Source: data/crafting_rules.ts:847-853 (salvageRoll), generalized to the full 64-bit value
export function economyRoll(seed: bigint, index: bigint): bigint {
  let z = BigInt.asUintN(64, seed + (index + 1n) * 0x9e3779b97f4a7c15n);
  z = BigInt.asUintN(64, (z ^ (z >> 30n)) * 0xbf58476d1ce4e5b9n);
  z = BigInt.asUintN(64, (z ^ (z >> 27n)) * 0x94d049bb133111ebn);
  return z ^ (z >> 31n);
}
export const rollBelow = (seed: bigint, index: bigint, n: bigint): bigint => (n > 0n ? economyRoll(seed, index) % n : 0n);
```

### Known Threat Patterns
| Pattern | STRIDE | Standard Mitigation |
|---------|--------|---------------------|
| Prompt injection through world data (region and NPC names written by an earlier model) | Tampering | `sanitizeWorldData` on every interpolated string; the model returns handles only; the server maps them to ids. |
| Console or link markup injection through generated names | Spoofing / Tampering | `cleanItemName` rejects `[ ] { } < >`; descriptions are cleaned. |
| Non-admin changing dials | Elevation of privilege | Sender check before any write; a test proves nothing is written on refusal. |
| Cost exhaustion by repeated region economy jobs | Denial of service (wallet) | The once-only `region_economy` row; `phase_only` still obeys the kill switch and the global ceiling; the background in-flight limit; off by default. |
| Leaking drop tables or dials to clients | Information disclosure | All 7 tables private; the privacy test. |
