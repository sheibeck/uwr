## What was built

**Schema** (`data/llm_schemas.ts`, section "Region economy (Phase 51.3)"):
- `{ region: anyOf[obj, null], lateCreature: anyOf[ECON_CREATURE, null] }`; region is `{ gatherables: {common, uncommon, rare}, creatures: ECON_CREATURE[], recipes: {first, second, third} }`.
- Kinds from `MATERIAL_KIND_VALUES`, terrain = `LOCATION_TERRAIN`, gear slot weapon/chest/legs/boots, weaponType = WEAPON_TYPES + none, armorType cloth/leather/chain/plate/none, category weapon/armor/accessory/consumable.
- Lint-clean, two union params, deep-frozen, snapshot recorded. `LLM_JSON_SCHEMAS.regionEconomy`.
- `llm_routes.ts` untouched (`grep -c region_economy` = 0).

**Validator** (`helpers/region_economy_validate.ts`, pure, imports only `../data/economy_design_rules` and `../data/recipe_rules`):
- `validateRegionEconomyReply(input: RegionEconomyInput, reply: unknown, isTaken: (name) => boolean): ValidatedRegionEconomy | null`
- `validateLateCreature(input, reply, isTaken): ValidatedCreature | null`
- Types:
  - `ValidatedGatherable { slot, ref, name, kind, terrain, description }`
  - `ValidatedCreature { enemyRef, enemyTemplateId: bigint, drop { name, kind, description }, trophy { name, description }, gear { name, slot, weaponType, armorType, description } }`
  - `ValidatedRecipe { index: number, tier, name, category, description, requirements: { ref, count: bigint }[] }`
  - `ValidatedRegionEconomy { gatherables, creatures, recipes }`
- Repair order follows the plan: gatherables (kind else 'base', terrain in input.terrains else first terrain else 'plains', a rule description when empty), creatures (first entry per known handle, drop kind else 'hide', repairGear), recipes (handles normalised, unknown and duplicate dropped, local primary of a primary kind, category derived, local secondary by model list then SECONDARY_KINDS preference then any, one foreign per required region, counts from regionalRequirementPlan, at most 4).
- Only own keys are read (a `__proto__` or `constructor` key in a reply is never followed); non-string values read as ''.

## Deviations from Plan

### Interpretations

**1. "JSON.stringify contains no 'description'"**
- **Issue:** The reply shape (PROMPT-DRAFT section 3) has `description` as a property name, so the literal string is necessarily present.
- **Resolution:** The test asserts that no schema node carries a `description` keyword with text (no `"description":"` in the JSON and a walk finds no string-valued `description`), plus no maxItems/minItems/length/min/max bounds. That is the intent of the line: no wording in the schema.

**2. "No number-typed value anywhere except the count bigints"**
- **Issue:** The plan's own types include `ValidatedRecipe.index` (number) and `ValidatedCreature.enemyTemplateId` (bigint).
- **Resolution:** The scan allows exactly three paths (recipe index, requirement count, enemyTemplateId) and checks each against the input slot, regionalRequirementPlan and the input enemy. None of them can come from the reply.

**3. Fallback role for recipe names** uses `'output'` (the 02 FallbackRole), not `'recipe'`.

**4. Rule primary prefers the model's category.** When the model list has no usable local handle and the model category is valid, the first local material primary for that category is chosen before the plain G-then-drops order. With the fixtures both orders give the same answer; this only keeps the model's intent when it can.

**5. validateLateCreature with several listed enemies** returns null for an unknown handle (the plan only defines the single-enemy case, where a missing or unknown handle is repaired).

No Rule 1-4 auto-fixes were needed.
