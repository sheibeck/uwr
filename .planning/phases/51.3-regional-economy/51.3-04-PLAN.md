Create `helpers/region_economy_validate.ts` with the pure-module header (pattern: renown_perk_validate.ts). Export these types:
- `ValidatedGatherable { slot, ref, name, kind, terrain, description }`
- `ValidatedCreature { enemyRef, enemyTemplateId, drop: { name, kind, description }, trophy: { name, description }, gear: { name, slot, weaponType, armorType, description } }`
- `ValidatedRecipe { index, tier, name, category, description, requirements: { ref, count }[] }`
- `ValidatedRegionEconomy { gatherables, creatures, recipes }`

Implement `validateRegionEconomyReply(input, reply, isTaken)` in this order:

1. **Usability:** return null unless `reply` is a plain object whose `region` is a plain object. The `lateCreature` field is ignored in region mode.
2. **Shared name set:** one `used` Set for the whole reply. `taken(name) = isTaken(name) || used.has(nameKey(name))`. Each accepted name is added to `used`.
3. **Gatherables:** always three, for common, uncommon and rare as G1, G2, G3.
   - kind: the model's kind if it is in MATERIAL_KIND_VALUES, else 'base'.
   - terrain: the model's terrain if it is in `input.terrains`, else `input.terrains[0]` (or 'plains' when the list is empty).
   - name: `uniqueItemName(cleanItemName(name), input.regionName, taken, { role: 'gather', kindOrSlot: kind })`.
   - description: `cleanDescription`, or a rule description when empty.
4. **Creatures:** iterate `region.creatures` when it is an array.
   - Keep the first entry per `enemy` handle that is in `input.enemies`; ignore others.
   - Drop kind defaults to 'hide' when invalid. Gear passes through `repairGear`.
   - Every name is uniqued through `taken`.
5. **Recipes** for first, second and third, by index 0-2. Tier and foreignRegionIndexes come from `input.recipeSlots[index]`; skip the recipe if that slot is missing.
   - Material handles: normalise each (trim, upper-case, keep the `D:` form). Drop unknown and duplicate handles.
   - Local handles: G1-G3 with their kinds, plus `D:<ref>` for each validated creature with its drop kind.
   - Foreign handles: `input.foreign` refs with their regionIndex and kind.
   - Primary and category:
     - The model category if valid, else derived.
     - The primary is the first local handle in the model list whose kind has a category. If its kind is not in `PRIMARY_KINDS[category]`, set `category = categoryForKind(kind)`.
     - If the model list has no usable local handle, take the first local material (G order, then drops) whose kind has a category, and use that kind's category.
     - With none at all, drop the recipe.
   - Local secondary, when the plan has `localSecondaryCount`:
     - Take the next local handle in the model list.
     - Otherwise the first local handle by `SECONDARY_KINDS[category]` preference.
     - Otherwise any other local handle.
   - Foreign: for each required region index, keep the first model F handle of that region, else the first `input.foreign` entry of that region. If a required region has no offer, drop the recipe. Common and uncommon recipes keep no F handle.
   - Requirements: `[primary, secondary?, ...foreign in region-index order]` with counts from `regionalRequirementPlan(tier)`, at most 4.
   - name: uniqued with fallback `{ role: 'recipe', kindOrSlot: category }`. description: cleaned.
6. **Result:** return null if no gatherable, creature or recipe survived. Otherwise return the plan.

The function never reads a number from the reply.

Fixtures are realistic model replies in the PROMPT-DRAFT shape: `region_k0.reply.json` (region mode, two creatures, three local recipes) and `region_k3.reply.json` (one creature, three recipes using F handles). The test file builds the matching `RegionEconomyInput` objects inline, with bigint ids.
