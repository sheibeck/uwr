- **The job shape the apply receives.** `helpers/llm_apply.ts` `ApplyJob` is `{ domain, playerId, contextJson, errorCode }`; `contextJson` is the stored `requestJson`. Plan 12 enqueues with `request: { regionId: '<id>', mode: 'region'|'enemy', enemyTemplateId: '<id or 0>', input: encodeRouteInput(input) }`.
  - `encodeRouteInput` (`helpers/llm_inputs.ts`) turns bigints into decimal strings.
  - The apply revives the four bigint paths `REGION_ECONOMY_BIGINT_PATHS` (Plan 02) with a small local reviver in this module. Plan 11 adds the same paths to `ROUTE_BIGINT_PATHS` for the executor, so do not depend on that table here.
- **Avoid an import cycle.** `helpers/llm_apply.ts` will import this module in Plan 12, so this module must not import `llm_apply.ts`. Parse the reply text locally: try `JSON.parse`; on failure, parse the substring from the first `{` to the last `}`; on failure, treat it as unusable.
- **Idempotency** (RESEARCH "Idempotent apply" steps 1-5):
  1. Read `region_economy` by regionId. Return unless the status is `pending`.
  2. For each slot, look up `economy_item` `by_region` with the slotKey before creating item_template plus economy_item.
  3. Write enemy_loot_entry only when `by_enemy.filter(id)` is empty.
  4. Write recipe_template only when no row has `key === 'region:<regionId>:r<n>'`.
  5. Set status `complete` last.

  The strict mock does not roll back, so a partial-write test simulates the real rollback by re-running on the same mock after a forced throw.
- **slotKeys:** `gather:common`, `gather:uncommon`, `gather:rare`, `drop:<enemyTemplateId>`, `trophy:<enemyTemplateId>`, `gear:<enemyTemplateId>`, `recipe:<n>`, `scroll:<n>`.
- **Region facts:**
  - `region` columns: name, dangerMultiplier, biome, dominantFaction, landmarks (JSON string), threats (JSON string).
  - `location` has regionId, terrainType and isSafe, and no region index (scan `location.iter()`, as `buildRegionContext` in `helpers/world_gen.ts` does).
  - `location_enemy_template` has `by_location`. `location_connection` has `by_from` and `by_to`.
  - The area level is `areaLevel(dangerMultiplier, 0n)` (`data/recipe_rules.ts`).
- **Name checks:** snapshot `[...ctx.db.item_template.iter()]` and `[...ctx.db.recipe_template.iter()]` names into a lowercase Set before any insert (the strict mock returns live arrays). The validator's `isTaken` reads that Set plus names written earlier in the same apply.
- **`rowColumnProblems(table, row)`** (`helpers/schema_recorder.ts`) checks every non-optional column, defaulted ones included.
- **Plans 05 and 06** read these tables: `rollEnemyLoot` reads `enemy_loot_entry` (role drop, trophy, gear or gatherable; weight), `research_recipes` reads `region_recipe.learnBy`, and the scroll drop reads `region_recipe.scrollTemplateId`.
