> Per-phase validation contract. Source: the "Validation Architecture" section of 51.3-RESEARCH.md, which holds the full per-requirement test map.

## Test Infrastructure

| Property | Value |
|----------|-------|
| **Framework** | vitest 5.0.2 (server tests through the repo's mock ctx in `spacetimedb/src/helpers/test-utils.ts`, plus real-handler integration tests) |
| **Config file** | `vite.config.ts` (alias `@game-data`) |
| **Quick run command** | `npx vitest run <touched test files> --maxWorkers=1` (folders: spacetimedb/src/data, spacetimedb/src/helpers, spacetimedb/src/reducers, spacetimedb/src/schema) |
| **Full suite command** | From the repo root, `npx vitest run --maxWorkers=1` plus `npx vue-tsc -b`. Baseline failures: `scripts/llm/call_log_report.test.mjs`, `scripts/llm/proof_rules.test.mjs`, `spacetimedb/src/helpers/measurement.results.test.ts` |
| **Estimated runtime** | about 15 minutes for the full suite single-worker; about 10-30 seconds for a quick run |

## Sampling Rate

- **After every task commit:** run the quick command on the touched test files.
- **After every plan:** run the server suite, `npx vitest run spacetimedb/src --maxWorkers=1`.
- **Before `/gsd-verify-work`:**
  - The full suite is green apart from the baseline.
  - Each local publish has the key-108 check before and after, with no clear.
- **Max feedback latency:** 30 seconds (quick).
- **No paid LLM calls anywhere.** The route is tested through canned JSON and the scripted `http.fetch`.
