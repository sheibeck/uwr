## Interaction Contract

### Component wiring (reuse, do not add components)

- `NarrativeConsole.vue` keeps its single indicator `<div :style="consideringStyle">`. Its text changes from the hard-coded string to a line supplied by a new optional prop `llmIndicatorLine: string | null`.
- The indicator renders when the displayed line is non-null. Add `role="status"` and `aria-live="polite"` to that div. Keep the `narrativePulse` animation and the existing `consideringStyle` object unchanged. Add one `@media (prefers-reduced-motion: reduce)` rule next to `@keyframes narrativePulse` that sets the animation to none for the indicator (additive, no change for default users).
- The existing `isLlmProcessing` prop is narrowed in meaning to the **input lock** only: `isCreationLlmProcessing || isWorldGenProcessing` in `App.vue` (the `|| isLlmProxyProcessing` term is removed, along with `useLlmProxy`). It keeps driving: the `disabled` state of `NarrativeInput`, the `Awaiting response...` placeholder, and the empty-state suppression at line 30.
- `App.vue` passes `:llm-indicator-line="llmIndicatorLine"` from `useLlmStatus`.

### Displayed line (single source rule)

```
displayedLine = useLlmStatus.indicatorLine
             ?? (isLlmProcessing ? LLM_INDICATOR_FALLBACK_LINE : null)
```

The fallback covers the brief gap between a creation or world-gen state row flipping busy and its `my_llm_jobs` row arriving, so the lock never shows without a line.

### `useLlmStatus` mapping (pure function, unit-tested)

- Input: rows of `my_llm_jobs` (`id`, `route`, `status`, `createdAt`, `errorCode`, `userMessage`). It reads nothing else. `userMessage` and `errorCode` are not shown by this indicator.
- Active job: `status` in `pending`, `in_flight`, `received` AND `route` not in the silent set (`combat_narration`, `smoke_test`).
- Output: `{ active: boolean, route: string | null, indicatorLine: string | null }`.

### Precedence when several jobs are active

Exactly one line is ever shown. Pick the active job with the highest-priority route; break ties by the oldest `createdAt`, then the lowest `id`.

| Priority | Route |
|----------|-------|
| 1 | world_gen |
| 2 | creation_race |
| 3 | creation_class |
| 4 | skill_gen |
| 5 | renown_perk_gen |
| 6 | npc_conversation |

Rationale: blocking work (locks input) outranks background work; among background jobs the one that changes the character outranks chat. A route not in the table and not silent falls back to `LLM_INDICATOR_FALLBACK_LINE` at priority 7.

### When the list empties

When no active job remains, `indicatorLine` becomes null and the div unmounts immediately. No fade-out, no "done" flash, no toast. Completion is communicated by the content the server posts to the log. Terminal statuses (`completed`, `failed`, `expired`) are never "active".

### Input locking

| Route | Locks input? | How |
|-------|--------------|-----|
| creation_race, creation_class | yes | existing `isCreationLlmProcessing` (own state rows) |
| world_gen | yes | existing `isWorldGenProcessing` (own state rows) |
| skill_gen, renown_perk_gen, npc_conversation | no | indicator only; player keeps playing |
| combat_narration | no | silent, no indicator |
| smoke_test | no | never shown to players |

`useLlmStatus` must never feed `NarrativeInput.disabled`. A duplicate request during a background job gets the server's in-voice "already considering" log line (no client handling).

### Failure

No error chip, no red state, no `errorCode` bucket in the UI. The server posts an in-voice line to the log via `applyLlmFailure`; the client only lets the row leave the active set so the indicator clears.

### Legacy credential handling

No UI. On app load, `localStorage.removeItem('llm_proxy_secret')` in try/catch; nothing is shown to the player.

## Copywriting Contract

Indicator lines live in a new shared server-side data module, `spacetimedb/src/data/llm_indicator_lines.ts`, exporting `LLM_INDICATOR_LINES: Record<route, string | null>` (null = silent) and `LLM_INDICATOR_FALLBACK_LINE`. The client imports it (server is source of truth; no client copy of the strings). Follows the Keeper VOICE (dry, understated, no exclamation marks, no banned phrases) and the pronoun rule: the Keeper is he/his, NPCs he/she, the player is "you". Trailing ellipsis is three ASCII dots, matching the existing line.

| Route | Indicator line |
|-------|----------------|
| creation_race | The Keeper is considering your fate... |
| creation_class | The Keeper is deciding what you are good for... |
| world_gen | The Keeper is unrolling a map, with visible reluctance... |
| skill_gen | The Keeper is weighing what you might become... |
| renown_perk_gen | The Keeper is tallying what your name is worth... |
| npc_conversation | The Keeper leans in to listen... |
| combat_narration | (silent, null) |
| smoke_test | (never shown, null) |
| Fallback (unknown route, or lock with no job row yet) | The Keeper is considering your fate... |

Notes: creation_race and the fallback deliberately reuse today's exact string, so existing creation flow shows no visible change. The NPC line names no NPC because `my_llm_jobs` carries no NPC identity; the Keeper is the actor, which keeps the pronoun rule trivially satisfied. No line uses it/they for a person, and every second-person reference is "you/your".

| Element | Copy |
|---------|------|
| Primary CTA | none (no new player action in this phase) |
| Empty state | none new. Existing console empty-state copy is unchanged |
| Error state | none in the client. Server-posted log line via `applyLlmFailure` / `keeperMessageForJob` (unchanged) |
| Destructive confirmation | none (no destructive player actions; deletions are developer-side) |

## UI Considerations

Applicable state considerations resolved: 6 covered, 1 backstop, 0 unresolved

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty | my_llm_jobs with no active rows | ✅ covered | Indicator is not rendered; `indicatorLine` is null |
| loading | job row pending/in_flight/received | ✅ covered | Shows the route's line with the existing pulse animation |
| error | job row failed/expired | ✅ covered | No client error UI; indicator clears, server log line carries the failure |
| partial | several active jobs at once | ✅ covered | One line only, chosen by the documented priority then oldest `createdAt` |
| zero-one-many | silent routes (combat_narration, smoke_test) | ✅ covered | Never produce an indicator, even when the only active job |
| long-text | longest line (~47 chars) on narrow viewport | 🧪 backstop | Wraps inside the scroll area; visual UI-state check at narrow width |
| overflow | job row stuck in pending/in_flight forever | ✅ covered | The Phase 41 server sweeper (`llm_sweep`, every 30 s) expires in_flight jobs after the route timeout plus 30 s and pending jobs after 10 min (renown 24 h), so the job leaves the active set and the indicator clears. No client staleness cutoff is needed |
