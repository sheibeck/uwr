## Summary

Phase 45 deletes the old browser UI and builds a new Vue 3 client at the repo root. Most of the surface is a layout shell on Nocturne tokens; the risk is concentrated in four places: (1) the connection and session layer, (2) the deletion blast radius on existing tests, (3) how to test layout and typography without a real browser, and (4) the vendored design stylesheet and its constraints.

The decisive SDK finding is that the `spacetimedb/vue` binding is much thinner than its React sibling. `SpacetimeDBProvider` builds exactly one connection (module-level singleton `connRef`), never reconnects, and `useTable` empties its rows the moment `isActive` flips to false. The React and Solid providers use a `ConnectionManager` with exponential backoff, but that class is not exported publicly. The roadmap's requirement that the frame keep showing the last data while a "Reconnecting..." banner counts down therefore cannot be met with `SpacetimeDBProvider` + `useTable` as shipped. Recommendation: own the `DbConnection` lifecycle in a small controller (build, classify errors, backoff, rebuild) and bind tables with a small `bindTable` helper that never blanks on disconnect. This is the same pattern the deleted `useCoreData.ts` already used (`subscriptionBuilder` + `onInsert/onUpdate/onDelete` rebind), minus its double-bind bug.

Testing: happy-dom 20.14.5 plus `@vue/test-utils` 2.5.1 run fine under the existing root `vitest run` via a per-file `// @vitest-environment happy-dom` docblock (verified in a scratch project with Vite 8.3.1 / Vitest 5.0.2 / Vue 3.5.43 / TS 6.0.3). But happy-dom cannot compute Nocturne's cascade (it parsed the vendored sheet to 0 rules), does not apply Vue scoped `<style>` blocks in tests, and does not fire `matchMedia` change events on viewport changes. So computed font-size, layout width and breakpoint assertions must be done as static CSS contract tests (postcss over `.css` and the `<style>` blocks parsed with `vue/compiler-sfc`), plus stubbed `matchMedia` for behavior, plus a short manual real-browser UAT at 1280x800 and 390x844.

**Primary recommendation:** Build the client with a client-owned connection controller (not `SpacetimeDBProvider`/`useTable`), vendor Nocturne `styles.css` byte-for-byte into `src/styles/`, enforce the design contract with static scanners, and treat the deletion as a test-impact change: trim `legacyLlmRemoval.test.ts`, keep the `src/main.ts` bootstrap shape that `legacyCredentials.test.ts` pins, and make sure the new `src/` has more than 10 non-test source files because three server tests assert it.

### Pattern 1: Client-owned connection controller

**What:** A plain TS module (no Vue provider) that owns one `DbConnection` at a time, exposes reactive `status`, `nextRetryAt`, `conn` (shallowRef), and handles retry/classification. It is unit-testable with an injected `buildConnection` factory and fake timers.
**When to use:** Always in this phase; it is the only way to meet "Reconnecting banner + frame keeps last data".
**Example:**
```typescript
// Source: verified against node_modules/spacetimedb/src/sdk/db_connection_builder.ts, db_connection_impl.ts,
// sdk/ws.ts and vue/SpacetimeDBProvider.ts (2.10.1); builder chain copied from the old src/main.ts
import { DbConnection } from '../module_bindings';

export const BACKOFF_MS = [1000, 2000, 5000, 10000, 20000, 30000] as const; // then stays at 30000
export const backoffDelayMs = (attempt: number) => BACKOFF_MS[Math.min(attempt, BACKOFF_MS.length - 1)];

function build(token: string) {
  let handled = false; // connectError AND disconnect can both fire for one failure: retry once per connection
  const conn = DbConnection.builder()
    .withUri(HOST)
    .withDatabaseName(DB_NAME)
    .withToken(token)
    .onConnect((c, identity) => { /* attempt = 0; status = connected; window.__db_conn = c; window.__my_identity = identity */ })
    .onDisconnect((_ctx, err) => { logDisconnect(err); if (!handled && !intentional) { handled = true; onDrop(); } })
    .onConnectError((_ctx, err) => { logConnectError(err); if (!handled) { handled = true; onFail(err); } })
    .build();
  return conn;
}
```

### Pattern 2: `bindTable` that never blanks on disconnect

**What:** Subscribe, then mirror a table into a `shallowRef` from `iter()` on insert, update and delete (views can deliver an update as delete+insert, so always re-read). On a new connection keep the old rows until the new subscription's `onApplied` replaces them. Return an `applied` flag (needed so the picker does not flash "No characters yet" before the character subscription arrives).
**Example:**
```typescript
// Source: pattern from deleted useCoreData.ts (rebind) + SDK useTable.ts; subscription API per
// node_modules/spacetimedb/src/sdk/subscription_builder_impl.ts
import { toSql } from 'spacetimedb';
import { tables } from '../module_bindings';

const handle = conn.subscriptionBuilder()
  .onApplied(() => { applied.value = true; rows.value = [...conn.db.character.iter()]; })
  .onError(() => { /* surface as sign-in failed / log */ })
  .subscribe([toSql(tables.character.where(r => r.ownerUserId.eq(userId)))]);
// on userId change or reconnect: handle.unsubscribe(), then subscribe again
```
Table handle events to attach: `table.onInsert/onUpdate/onDelete(cb)`; detach with `removeOnInsert/removeOnDelete/removeOnUpdate` (the old client never detached, so every `isActive` toggle double-bound its handlers).

### Pattern 3: Pure `deriveScreen(state)` for the splash/picker/frame decision

Inputs: `hasStoredToken`, `tokenExpired`, `authError`, `status` (connecting/connected/reconnecting/rejected/unreachable), `player` (`userId`, `activeCharacterId`), `charactersApplied`, `characters`, `activeCharacter`. Output: `'splash:<state>' | 'picker' | 'noCharacters' | 'frame'` using exactly the seven splash states of the UI-SPEC table. A pure function makes requirement FND-06 testable without a socket.

### Pattern 4: Screen state as one value

`activeScreen: null | 'map' | 'bag' | 'stats' | 'craft' | 'social' | 'events' | 'vendor' | 'more'` plus `opener: HTMLElement | null`. `open(screen, openerEl)` replaces; clicking the open screen's header button closes (desktop); `more` maps to `null` on desktop; tab mapping Story->null, Map->map, Bag->bag, Party->social, More->more. Opener for a screen picked from the More sheet is the More tab button.

### Pattern 5: Hand-rolled Tab-wrap focus trap (small, testable)

Keydown listener on the drawer element: on Tab/Shift+Tab compute focusable descendants (`button:not([disabled])`, `[href]`, `input`, `select`, `textarea`, `[tabindex]:not([tabindex="-1"])`, skipping `[hidden]`), wrap at the ends. Do not use `inert` or block pointer focus: the header and rails must stay interactive while a drawer is open. In tests dispatch `new KeyboardEvent('keydown', { key: 'Tab', shiftKey, bubbles: true })` and assert `document.activeElement`: happy-dom does NOT move focus on a synthetic Tab, so the trap's own `.focus()` call is what the test observes (verified).

### Anti-Patterns to Avoid
- **`SpacetimeDBProvider` remount for reconnect:** it keeps a module-level `connRef`; on unmount it schedules `disconnect()` via `setTimeout(0)` and sets `connRef = null` afterwards; a remount in the same tick clears that timeout (`if (cleanupTimeoutId) clearTimeout`) and then `if (!connRef)` is false, so the OLD (dead) connection is reused. Never rely on `:key` to rebuild.
- **Connecting without a token:** every connection, anonymous or not, runs `clientConnected`, which inserts a `player` row for that identity, and `clientDisconnected` schedules a 30 s `disconnect_logout` tick. The old client connected anonymously on every load. The new client connects only when a stored, unexpired token exists (UI-SPEC: Sign in works "without a live DB connection").
- **Deep reactivity on SDK rows:** use `shallowRef` (rows contain `bigint`, `Identity`, `Timestamp` instances).
- **Subscribing to whole public tables you filter later:** `player`, `character`, `pending_skill` are `public: true` and would stream every player's rows. Use `my_player` (public view of the sender's row) and `where(...)` subscriptions.
- **Colors or sizes in `.ts` strings:** no inline style objects; the old `src/ui/styles.ts` approach is exactly what FND-02 forbids.

## SpacetimeDB Vue SDK (Research Question 2)

Verified against `node_modules/spacetimedb/src/vue/*` and `src/sdk/*` (2.10.1):

| Export (`spacetimedb/vue`) | Behavior |
|---|---|
| `SpacetimeDBProvider` (prop `connectionBuilder`), `useSpacetimeDBProvider(builder)` | Calls `connectionBuilder.build()` in `onMounted`, once (module-level `connRef`). Registers onConnect/onDisconnect/onConnectError on the builder AFTER `build()`. Provides reactive `ConnectionState { isActive, identity, token, connectionId, connectionError, getConnection() }`. On unmount: removes its callbacks, then `setTimeout(0)` -> `connRef.disconnect(); connRef = null` |
| `useSpacetimeDB()` | `inject`s that state; throws without a provider |
| `useTable(query, callbacks?)` | Returns `[readonly rows Ref, readonly isReady Ref]`. Subscribes with `toSql(query)`; re-subscribes on `conn.isActive` change; when `isActive` becomes false it sets `isReady=false` and **`rows = []`** |
| `useReducer(reducerDef)` | Returns `(...params) => Promise<void>`; queues calls made before the connection exists |
| `useProcedure` | Procedures (not needed) |

- **No auto-reconnect in the Vue binding.** React and Solid use `ConnectionManager` (backoff 1 s doubling to 30 s, plus `visibilitychange`/`focus`/`online` resume checks), which is internal and not exported from `spacetimedb` or `spacetimedb/sdk` `[VERIFIED: grep of src/index.ts and src/sdk/index.ts]`.
- **`DbConnection` is one-shot.** After `onDisconnect` the object is dead (`isActive=false`); a retry means `DbConnection.builder()...build()` again.
- **Callbacks:** `.onConnect((conn, identity, token) => ...)`; since 2.10.0 an error on an established connection arrives in `.onDisconnect((ctx, err?) => ...)`, not `onConnectError` (documented in `src/connectionLogging.ts`). Failures before the first connect go to `.onConnectError((ctx, err) => ...)`. Both can fire for one failure (`ws.onclose` always emits `disconnect`), so retry scheduling must be idempotent per connection object.
- **Token handling in `openWebSocket` (`sdk/ws.ts`):** with a token the SDK first does `fetch POST <host>/v1/identity/websocket-token` with `Authorization: Bearer`; a non-OK response throws `Error("Failed to verify token: " + response.statusText)` which arrives as `onConnectError`; a network failure arrives as a `TypeError` from `fetch`. `statusText` can be empty (HTTP/2) `[ASSUMED]`, so do not parse a status from the message.
- **Camel-case handles:** generated `tables` and `conn.db` expose both camelCase and deprecated snake_case aliases (`tables.myPlayer`, `tables.worldState`, `tables.appVersion`, `tables.pendingSkill`, `conn.db.worldState`). `DbConnection` is imported from `./module_bindings`. Reducers: `conn.reducers.loginEmail({ email })`, `.logout({})` (params object required even when empty), `.setActiveCharacter({ characterId })`.
- **Subscriptions:** `conn.subscriptionBuilder().onApplied(cb).onError(cb).subscribe(string[])` returns a handle with `unsubscribe()`. Views need an explicit subscription (`toSql(tables.myPlayer)`). Filter with `toSql(tables.character.where(r => r.ownerUserId.eq(userId)))` (pattern already used by the deleted `useWorldData.ts`).

**Reconnect recommendation:** controller + `bindTable` (Patterns 1 and 2). Reuse the carried-over `logConnectError` / `logDisconnect` (they take no generated context type on purpose: TS2589 against 2.10.1 bindings). Also retry immediately on `window` `online` and `document` `visibilitychange` (visible): browsers throttle timers in background tabs; the SDK's own ConnectionManager does the same for React. Guard HMR: `import.meta.hot?.dispose(() => controller.disconnect())` so dev reloads do not leak connections.

**Token-rejected vs unreachable:** on `onConnectError` with a message starting `Failed to verify token`, run a reachability probe `fetch(<http base>/v1/ping)` (the run-local skill already health-checks that endpoint with `curl`): reachable -> treat the token as rejected (clear session, splash `Your session expired. Sign in again.`); unreachable -> `Can't reach the server. Retrying...` and keep backing off. Any other error (`TypeError: Failed to fetch`, websocket error) -> unreachable path. Before every (re)build also call `getStoredIdToken()`: it returns `null` once `expiresAt` has passed, which must route to "session expired" with no retries. `[ASSUMED]` that the host returns 401/403 (not 5xx) for a bad token.

**Server-side consequence of a drop (verified in `spacetimedb/src/index.ts` and `reducers/auth.ts`):** `clientDisconnected` schedules `disconnect_logout` 30 s later; if `player.lastSeenAt` has not advanced by then it sets `player.userId = undefined` and `player.activeCharacterId = undefined`. So an outage longer than ~30 s means that after reconnect the client must run `login_email` again (state "Signing in...") and the player lands on the picker again. Reconnect within 30 s keeps the session (`clientConnected` bumps `lastSeenAt`). The derive-screen function handles this naturally; do not special-case it. Open Question 2 covers auto-restoring the last character.

## Common Pitfalls

### Pitfall 1: Using `SpacetimeDBProvider` + `useTable` for the whole app
**What goes wrong:** No reconnect; on disconnect `useTable` sets rows to `[]`, so the vitals/header blank under the "Reconnecting..." bar; a keyed remount reuses the dead `connRef`.
**Why it happens:** The Vue binding is a thin provider; backoff exists only in the React/Solid `ConnectionManager`.
**How to avoid:** Pattern 1 + 2. Nothing in the app imports `SpacetimeDBProvider`, `useTable`, `useReducer` from `spacetimedb/vue`.
**Warning signs:** Frame flashes empty on server restart; "Reconnecting..." never ends.

### Pitfall 2: One failure triggers two retries
**What goes wrong:** `connectError` and `disconnect` both fire; two timers, two connections, two reconnect banners.
**How to avoid:** `handled` flag per connection object; a single `retryTimer`; `intentional` flag set by `logout()`/`disconnect()`.
**Warning signs:** Two `Connected to SpacetimeDB` logs after one outage.

### Pitfall 3: Flash of "No characters yet" or the picker
**What goes wrong:** `character` rows have not arrived yet, so `characters.length === 0` is read as "none".
**How to avoid:** `charactersApplied` (subscription `onApplied`) is part of `deriveScreen`; until true the screen is `splash:signing in`. UI-SPEC: the frame is not mounted until a character row exists.

### Pitfall 4: `set_active_character` silently does nothing
**What goes wrong:** In combat the reducer returns without error; the picker spins forever.
**How to avoid:** 8 s timeout -> error line, rows re-enabled; clear the timer when `activeCharacterId` arrives.

### Pitfall 5: Anonymous connections and orphan `player` rows
**What goes wrong:** Connecting without a token creates a new identity and `player` row on every load.
**How to avoid:** Connect only with a stored valid token (Anti-Patterns). The splash `idle` state needs no socket.

### Pitfall 6: Dev port drift
**What goes wrong:** Vite moves to 5174; SpacetimeAuth rejects the redirect URI.
**How to avoid:** `server.port 5173`, `strictPort true`; verify with the run-local skill's health check.

### Pitfall 7: The jsdom-style test traps (verified in the scratch probe)
- `getComputedStyle` in happy-dom resolves simple sheets (including `var()`), but the vendored Nocturne file parsed to **0 CSS rules**, so `.card-title`, `.tag`, `.card-body` and `h6` sizes could not be asserted.
- Vue SFC `<style scoped>` blocks are not injected in Vitest unless `test.css` is enabled; computed styles of scoped classes read as defaults (16 px).
- `matchMedia(...).matches` is live after `window.happyDOM.setViewport({ width, height })`, but `change` listeners are **not** fired by `setViewport` or a dispatched `resize` event.
- A synthetic Tab keydown does not move focus.
**How to avoid:** contract tests are static (postcss/SFC parse); layout switching is tested by setting the viewport BEFORE mounting and by stubbing `window.matchMedia` with a controllable fake for crossing the breakpoint; focus trap is tested through its own keydown handler.

### Pitfall 8: `spacetimeAuth.ts` gaps found while reviewing it
- No test exists today (the carried-over tests are `connectionLogging` and `legacyCredentials`); add one (state mismatch throws, successful exchange stores keys, expired token returns `null`, `clearAuthSession` removes every `spacetimeauth_*` key and both `sessionStorage` entries). The module reads `import.meta.env.VITE_SPACETIMEAUTH_*` and `window.location.origin` at import time, so use `vi.stubEnv` + `vi.resetModules()` + dynamic `import()` under happy-dom (note happy-dom's default URL is `http://localhost:3000/`).
- On a failed callback (state mismatch, missing verifier, token endpoint error) the `?code=&state=` stay in the URL, so a reload repeats the failure. Strip the params on failure too.
- It cannot tell "expired token" from "no token" (`getStoredIdToken()` returns `null` for both). The splash needs that distinction (`session expired` vs `idle`). Add a small `hasExpiredToken()` (stored `idToken` present and `expiresAt` in the past). This is the only functional addition to a carried-over file.
- With no `email` claim, `login_email` cannot run: show `Sign-in failed. Try again.`.

### Pitfall 9: Logout losing the reducer
**What goes wrong:** Clearing storage and disconnecting immediately can drop the `logout` call.
**How to avoid:** `await Promise.race([conn.reducers.logout({}), timeout(2000)])`, then `clearAuthSession()`, then controller `disconnect()` (sets `intentional`), then splash. Never call reducers when `status !== 'connected'`; just clear and go to splash.

### Pitfall 10: Server tests that count client files
See Deletion Inventory: `files.length > 10` in three spacetimedb tests; `src/` must hold more than 10 non-test sources after the cutover commit, not only at the end of the phase.

### Pitfall 11: Global happy-dom breaks an existing test
`legacyCredentials.test.ts` asserts `typeof globalThis.localStorage === 'undefined'` (node environment). Configure the environment per file with the docblock `// @vitest-environment happy-dom`, never via `test.environment` in `vite.config.ts`. Spacetimedb and scripts tests stay in node.

### Pitfall 12: Spec arithmetic and Nocturne overrides
- UI-SPEC says the splash logo resolves to 342x192 at 390x844, but with its own 16 px side padding the container is 358 px, so `width: min(960px, 100%)` gives 358x201. Assert the CSS rule, not that number (960x540 at 1280x800 is correct).
- `h6` and `.card-title` etc. must be overridden AFTER Nocturne at equal-or-higher specificity (`frame.css` imported last), or the declared 10/12/14/20 px scale is silently violated.

### Pitfall 13: HMR duplicates the connection
A module-level controller survives HMR and a new instance builds another socket. Dispose on `import.meta.hot`.

## Security Domain

> `security_enforcement` is absent from `.planning/config.json`, so treated as enabled. ASVS Level 1.

### Applicable ASVS Categories

| ASVS Category | Applies | Standard Control |
|---------------|---------|-----------------|
| V2 Authentication | yes | OIDC Authorization Code + PKCE (S256) against SpacetimeAuth; no client secret; carried-over `spacetimeAuth.ts` |
| V3 Session Management | yes | Tokens in `localStorage` with client-side expiry check; logout clears every `spacetimeauth_*` key; reconnect re-validates before rebuild |
| V4 Access Control | yes (server-side) | Enforced in the module (`requireCharacterOwnedBy`, ownership checks); client only sends ids. Pre-existing gap noted below |
| V5 Input Validation | yes (small) | Never `v-html`; render character names and location text as text; truncate with CSS; `email` is only sent from a stored token claim |
| V6 Cryptography | yes | WebCrypto `crypto.getRandomValues` + `crypto.subtle.digest('SHA-256')`; no hand-rolled crypto |
| V14 Config | yes | `check-bundle.mjs` guard keeps provider hosts/keys/proxy tokens out of `dist/`; `.env.local` secrets stay gitignored |

### Known Threat Patterns for this stack

| Pattern | STRIDE | Standard Mitigation |
|---------|--------|---------------------|
| Authorization-code interception / CSRF on the redirect | Tampering | PKCE verifier + random `state` in `sessionStorage`, compared on callback (already implemented); strip `code`/`state` from the URL on success AND failure (Pitfall 8) |
| Token theft via XSS from `localStorage` | Information disclosure | Accepted for a public PKCE SPA; reduce the surface: no `v-html`, no third-party scripts (only the Google Fonts stylesheet), consider adding a ban test for `v-html` and `innerHTML`; optionally a CSP meta allowing `fonts.googleapis.com`, `fonts.gstatic.com` and the SpacetimeDB `ws(s)` host `[ASSUMED]` that this is acceptable to the owner |
| LLM/provider credential in the bundle | Information disclosure | `scripts/check-bundle.mjs` runs last in `pnpm build`; `clearLegacyLlmCredential()` first in bootstrap; `legacyLlmRemoval` forbidden-word scan kept |
| Binding a private `llm_` table | Information disclosure | Bindings guard (`llmAdminBindings.test.ts`, only the two views) plus a client-source scan for the eight private table names |
| Spoofing via stale or foreign token | Spoofing | Expired token never used (`getStoredIdToken`); host rejection clears session |
| Open handle / globals | Tampering | `window.__db_conn` is the documented CLAUDE.md pattern; XSS could call reducers anyway, so it adds no new capability |
| Reducer identity trust | Elevation of privilege | Client never sends identity args; `ctx.sender` is authoritative (CLAUDE.md core rule) |

**Pre-existing server-side issue (out of scope, flag to owner):** `login_email` (`spacetimedb/src/reducers/auth.ts`) trusts the email string the client sends: it finds or creates a `user` by that email and sets `player.userId`, with no check against the verified token claims. Any signed-in identity could claim another player's email and then own their characters. Phase 45 explicitly makes no server change, so it is recorded here and in Open Questions rather than fixed.

## Project Constraints (from CLAUDE.md)

- Reducers take object arguments (`conn.reducers.setActiveCharacter({ characterId })`), never positional.
- Import `DbConnection`/`tables` from `./module_bindings`; never from `spacetimedb` itself; never edit generated bindings (regenerate with `spacetime generate`).
- Do not invent SpacetimeDB APIs; only use what exists in the installed SDK/docs. (Everything in this document was read from `node_modules/spacetimedb/src`.)
- `ctx.sender` is the principal; never send identity arguments from the client.
- Views need explicit subscription SQL; `public: true` exposes all rows (hence `my_player` and `where` subscriptions).
- Timestamps are objects (`row.createdAt.microsSinceUnixEpoch`); compare identities with `toHexString()`.
- Memoizing `connectionBuilder` and `<SpacetimeDBProvider connectionBuilder>` guidance applies only if the provider were used (it is not recommended here).
- Feature checklist: tables -> reducers -> subscribe -> call reducers from the UI -> render. Phase 45 wires `login_email`, `logout`, `set_active_character`; do not leave any of them uncalled.
- Make the smallest change; do not touch unrelated files/configs; no server change in this phase.
- Auto-memory rules: server is the source of truth (import constants from `spacetimedb/src/data`, never duplicate); unit tests are mandatory for every phase; greenfield, no compatibility shims or backups; publish only to the local server, never maincloud; never pass `--clear-database` unless the schema requires it (not needed here); `STATE.md`: no pushes to master.
