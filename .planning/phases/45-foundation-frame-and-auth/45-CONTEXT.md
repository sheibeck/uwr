# Phase 45: Foundation, Frame and Auth - Context

**Gathered:** 2026-10-05
**Status:** Ready for planning

<domain>
## Phase Boundary

Delete the old `src/` UI (after tagging it `v2.2-client`) and build the new client from scratch in its place at the repo root: Vite + Vue 3 on the Nocturne design system. A player signs in with SpacetimeAuth, reaches their character, and sees the frame: header, persistent vitals rail, center feed and context rail on desktop (1280×800); compact vitals strip, feed and bottom tab bar on mobile (390×844). Every secondary screen opens as a drawer (desktop) or full-height sheet (mobile) shell. The splash screen shows the 16:9 key-art logo.

Rails and feed are shells here; Phase 47 fills them. The header and the auth/session flow carry real data. Requirements: FND-01 to FND-07, CUT-03.

</domain>

<decisions>
## Implementation Decisions

### Greenfield replacement (owner, 2026-10-05)
- The old client does not need to run or work. No side-by-side clients, no second port, no second redirect URI. Quote: "we dont need the other client. it doens't need to run, or work. we can delete it, re-use all of it's ports, etc. Dn't keep both up and running. this is greenfield."
- First step of the phase: create the local git tag `v2.2-client` on the commit before deletion (no push), then delete the old UI: `src/App.vue`, `src/components/`, `src/composables/`, `src/ui/`, `src/data/`, `src/main.ts` and the tests that only cover them.
- The uncommitted splash-logo work in `src/ui/styles.ts` and `src/ui/splashLogo.test.ts` belongs to the old UI and is discarded with it; FND-07 is rebuilt in the new splash with the same rule (16:9, undistorted, `object-fit: contain`, no pixelated rendering, fits 1280×800 and 390×844).
- The root project (package.json, vite.config.ts, index.html, `src/`) becomes the new client. It keeps dev port 5173, the SpacetimeAuth redirect URI from `.env.local` (`http://localhost:5173/uwr`), the build scripts and the deploy path.

### App setup and tooling
- No router. Splash and one game screen; drawers and sheets are app state.
- Styling: import Nocturne's `styles.css` as-is (re-imported from the claude_design MCP, never cached) so tokens are CSS custom properties. Components use scoped styles that reference only `var(--…)`. A test fails on any literal color (hex, rgb/hsl, named) in component or style source.
- Icons: `@phosphor-icons/vue` components.
- Font: Inter, per Nocturne.

### What survives the deletion
- Carry over (with their tests, adjusted only for new paths): `src/auth/spacetimeAuth.ts` (PKCE flow), `src/connectionLogging.ts`, `src/legacyCredentials.ts` (one-time credential clear), and `scripts/check-bundle.mjs` with its test. `src/module_bindings/` stays and is regenerated by the root `spacetime:generate`.
- Static guard tests tied to old files (`legacyLlmRemoval.test.ts` reads `src/composables/data/useCoreData.ts`; `llmAdminBindings.test.ts` reads bindings) are kept only where their subject still exists: keep the bindings guard, rewrite or drop guards whose target file is deleted. The "no private llm_ table bound to the client" rule must still be enforced.
- New code uses camelCase table handles (`conn.db.abilityCooldown`), not the deprecated snake_case aliases. This resolves the pending todo `2026-09-29-migrate-client-table-handles-to-camelcase.md` for the new client.
- Game data comes from `spacetimedb/src/data` through a Vite/TS path alias (server is source of truth).
- Rarity and enemy-difficulty colors become CSS tokens in a client token file layered on Nocturne. A test pins them to today's hues: rarity common `#ffffff`, uncommon `#22c55e`, rare `#3b82f6`, epic `#aa44ff`, legendary `#ff8800`; difficulty conRed `#ff6b6b`, conOrange `#f08c00`, conYellow `#ffd43b`, conWhite `#e9ecef`, conBlue `#4dabf7`, conLightGreen `#69db7c`, conGray `#868e96`. Craft-quality colors (`dented #888`, `standard #ccc`, `reinforced #6c9`, `exquisite #9cf`, `mastercraft #f90`) move the same way.
- Port the app-version check (reload prompt after a deploy; reads the `app_version` table). The bug report and admin commands wait for the Phase 52 parity checklist; drop `html2canvas` from dependencies until then.

### Frame behavior
- One breakpoint near 900px: below it the mobile layout (vitals strip, tab bar, sheets); above it the three columns. Exact values follow the design import.
- One drawer at a time. Opening another replaces it. Esc or the close button dismisses it; focus returns to the opener; focus stays inside the open drawer/sheet.
- Every screen button opens its real drawer (desktop) or sheet (mobile) shell with an empty state, so later phases only fill content.
- Mobile tab bar: Story, Map, Bag, Party as tabs; More opens a sheet listing Stats, Crafting, Events, Vendor and Log out.

### Sign-in and session
- Splash: large 16:9 logo and one Sign in button; sign-in status and errors show below it.
- After sign-in: the player's active character (`player.activeCharacterId`) opens the frame directly. With no active character, a simple picker lists their characters and calls `set_active_character`. With no characters, a note says character creation is coming (Phase 49); testing uses existing local characters.
- Dropped connection: a "Reconnecting…" banner and automatic retries with backoff (1s, 2s, 5s, then up to 30s). An expired or rejected token clears the session and returns to the splash.
- Log out: calls the `logout` reducer, clears the stored session, returns to the splash. Desktop: header menu. Mobile: More sheet.

### Claude's Discretion
- Component and file layout inside the new `src/`, state management (plain composables vs a small store), and test tooling for components (for example @vue/test-utils with happy-dom) as long as tests run under the existing `vitest`.
- Empty-state copy for unbuilt screens (keep it short and plain; Keeper-voiced copy is a later concern).
- Exact backoff implementation details and how the version check prompts.

## Existing Code Insights

### Reusable Assets
- `src/auth/spacetimeAuth.ts`: OIDC PKCE login, callback handling, token storage (`spacetimeauth_*` keys), `clearAuthSession`, issuer/client id/redirect from `VITE_SPACETIMEAUTH_*`.
- `src/main.ts` (old): connection bootstrap pattern: `clearLegacyLlmCredential()`, `handleSpacetimeAuthCallback()`, `DbConnection.builder().withUri(HOST).withDatabaseName(DB_NAME).withToken(...)`, `SpacetimeDBProvider` from `spacetimedb/vue`. Env: `VITE_SPACETIMEDB_HOST` (default `ws://localhost:3000`), `VITE_SPACETIMEDB_DB_NAME` (`uwr`).
- `src/composables/useAuth.ts` (old, reference only): `login_email` reducer is called once connected with the stored email; `isLoggedIn` = token present and `player.userId != null`.
- Reducers: `login_email`, `logout` (`spacetimedb/src/reducers/auth.ts`), `set_active_character` (`spacetimedb/src/reducers/characters.ts`).
- `public/assets/logo.png` (1672×941 key art), `public/assets/favicon.ico`, `public/version.json`.
- `scripts/check-bundle.mjs`: the post-build credential guard run by `pnpm build`.

### Established Patterns
- Root package scripts: `dev` (vite), `build` (`vue-tsc -b && vite build && node scripts/check-bundle.mjs`), `test` (vitest run), `spacetime:generate` into `src/module_bindings`.
- Vite config defines `__BUILD_VERSION__` for the version check.
- Unit tests are required in every phase (project rule).
- `spacetimedb/vue` provides `SpacetimeDBProvider`, `useTable`, `useReducer`.

### Integration Points
- `index.html` mounts `#app`; `src/main.ts` is the entry.
- `window.__db_conn` / `window.__my_identity` globals are set on connect (CLAUDE.md pattern).
- Header data: location (character's current location), time of day (world clock table), level-up and new-skill tags (pending skill choice / level-up state).
