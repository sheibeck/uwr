# Phase 51.3.1.1 Plan 18: Client Data Layer Summary

The client now subscribes to the public density levels by region (here, exits and visited places), its own named enemies and its harvest caps; every Nearby, console and keyword action calls pullFamily, gatherPool, pullNamedEnemy or startCombat with object arguments, and the feed keywords offer family names instead of ordinary spawns.

## What was built

**Subscriptions (Task 1).**
- `queries.poolLevelsInRegions(ids)` is an OR chain on `region_id`; an empty list throws.
- `queries.namedEnemiesOf(characterId)` selects `named_enemy WHERE character_id = me`.
- `queries.myHarvestCaps` and `queries.myVisitedLocations` select their views with no WHERE.
- `resourceNodesAt` and the resource_node binding are gone.
- `GameData` gained:
  - `poolLevels`: the rows of every loaded region;
  - `poolLevelsHere`: the rows of the current place;
  - `poolRegionsApplied` and `poolsAppliedFor(locationId)`;
  - `namedEnemies`, `harvestCaps` and `visitedLocationIds`.
- `nodesHere` was removed. `enemiesHere` and `enemyTemplatesHere` stay, because event spawns still use them.

**Reducers, console and keywords (Task 2).**
- `GameReducers` gained `pullFamily`, `gatherPool`, `pullNamedEnemy` and `startCombat`, with the generated argument names. `startPull` and `startGatherResource` were removed.
- Console:
  - `pull({ id, name })` echoes `pull {name}` and calls `pullFamily({ characterId, poolId })`, with no pull type (D-12);
  - `gather({ id, name })` calls `gatherPool({ characterId, poolId })`;
  - the new `fight({ kind, id, name })` echoes `fight {name}` and calls `pullNamedEnemy({ characterId, namedEnemyId })` for kind 'named' or `startCombat({ characterId, enemySpawnId })` for kind 'event';
  - pull and fight do nothing in a fight or offline.
- `actOnKeyword` handles the enemy kind by `entry.target`: 'family' (or none) pulls; 'named' and 'event' fight.
- `KeywordEntry.target?` is carried through `buildVocabulary`. No regex is built from names (T-47-02 kept).
- `src/rails/pullTargets.ts`:
  - `pullTargets(poolsHere, namedHere, eventSpawnsHere)` returns the families with level > 0 (target 'family', id = pool id, name = family name), the living named enemies (target 'named') and the available spawns (target 'event'), sorted by name;
  - `gatherTargets(poolsHere)` returns the resource pools with level > 0, sorted by name.
- `FeedView.vue` builds the vocabulary from these (namedHere = the own named enemies at the character's place).

**Consumers of the removed node data (Task 3).**
- `useActionProgress` takes `pools` (`game.poolLevels`) instead of `nodes`.
  - A pool gather (`poolId > 0`) is labelled `Gathering {pool name}`.
  - A legacy node gather, or a pool that is not known yet, reads `Gathering`.
  - `actionProgress.ts` (outside my list) is unchanged: each pool gather is passed to it with a negative synthetic node key (minus the gather row id), which no real node id can equal.
- `routeContext.nodeNames` = `gatherTargets(poolLevelsHere)` names.
- `NearbyList.vue`:
  - no node rows: `nodes: []` goes to the unchanged `nearbyRows`;
  - the main-row gather button branch is gone;
  - the spawn row button fights the spawn.
  - Nothing was restyled. Plan 19 rewrites Nearby.

## Notes for Plans 19-22

- **Readiness:** read `game.poolsAppliedFor(locationId)`. When it is false, rate the place Unknown, never Safe (`placeRating({ ready: false })`). It covers here, every exit destination and every visited place. Any other place stays Unknown, because its region is not loaded.
- **Pool rows:** `game.poolLevels` holds pool_level rows across the loaded regions; filter by `locationId` and `kind` ('creature' | 'resource'). `game.poolLevelsHere` holds the current place's rows.
  - Fields: `level` (0-3), `lvLo`, `lvHi`, `name` (the family name or the resource name), `iconKey`, `temperament`, `singularNoun`, `pluralNoun` and `timeOfDay`.
  - The pool id is `row.id`.
- **Named enemies:** `game.namedEnemies` holds the own named_enemy rows at every place. Filter them by `locationId === here` and `isAlive`.
- **Harvest caps:** `game.harvestCaps` holds `{ id, locationId, cappedUntilMicros }`. Compare `cappedUntilMicros` with `game.clock.nowMicros()`.
- **Console calls:**
  - Pull card: `consoleApi.pull({ id: poolLevel.id, name: poolLevel.name })`.
  - Gather card: `consoleApi.gather({ id: poolLevel.id, name: poolLevel.name })`.
  - Fight on a named enemy: `consoleApi.fight({ kind: 'named', id: named.id, name: named.name })`.
  - Fight on an event spawn: `consoleApi.fight({ kind: 'event', id: spawn.id, name: spawn.name })`.
- **Keyword mapping:** `pullTargets(poolLevelsHere, namedHere, enemiesHere)` gives the enemy entries.
  - A family is `{ id: pool id, name: family name, target: 'family' }`, offered only at level > 0.
  - A server `[Goblins]` keyword matches the family name, so a click equals the Pull button and the typed `pull goblins`.
  - `[Gather X]` matches the resource name, as a 'node' keyword that examines (behaviour kept).
- **Open copy and label item (outside my list):** `src/console/keywordLabel.ts` labels every enemy keyword "Pull {name}", named and event targets included. A plan that owns the feed line should label 'named' and 'event' targets "Fight {name}". The Nearby spawn row label "Pull {name} (Lv n, ...)" in `src/rails/enemies.ts` also now fights; Plan 19 replaces it.
- `src/rails/nearby.ts` (`visibleNodes`, `nodeStatus` and the node kind) and `pullableSpawns` in `enemies.ts` are now unused by production code apart from the `nearbyRows` signature. Plan 19 rewrites them.
