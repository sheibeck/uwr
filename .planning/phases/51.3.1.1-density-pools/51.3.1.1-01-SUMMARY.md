# Phase 51.3.1.1 Plan 01: Density rules file and pool vocabularies Summary

`data/density_rules.ts` is now the one pure rules file for density. All of the phase's tunable numbers sit in one deep-frozen `DENSITY_RULES` object, and every pool rule is a seeded function over those numbers. That covers encounter chance, group size and roles, the lowest-member party level, lazy settling, yield and the harvest window, hunters, the vacuum pick, region trend, home levels, and the hub count, hub choice and crafting-station roll of D-59 to D-63. The seven closed vocabularies for families, pools and combat origins were added to `mechanical_vocabulary.ts`.

## What was built

- **Vocabulary** (`data/mechanical_vocabulary.ts`, after `ENEMY_ROLES`): seven `as const` lists, each with its type:
  - `FAMILY_TEMPERAMENTS`, `FAMILY_RELATIONS`, `FAMILY_ICON_KEYS`
  - `FAMILY_PROMPT_ROLES` (`support` = server `healer`)
  - `POOL_KINDS`, `RESOURCE_ICON_KEYS`
  - `COMBAT_ORIGINS` (`''` = no recorded origin)
  - Types: `FamilyTemperament`, `FamilyRelation`, `FamilyIconKey`, `FamilyPromptRole`, `PoolKind`, `ResourceIconKey`, `CombatOrigin`.
- **Constants:**
  - `DENSITY_RULES` holds every value the plan lists. Each one has a comment naming its decision, and the object is deep-frozen, nested arrays and band objects included.
  - `POOL_ROLL` has fixed indexes 0/1/2, 10+i, 20+i, 40/41, 50, 60, 70 and 80/81/82.
  - Also exported: `ENCOUNTER_PHASE_CODE` (enter, leave, pull, gather, aggro) and `HUB_SEED_TAG` (7n).
- **Seeds:**
  - `poolSeed(...parts)` uses multiply-add-primes with a distinct prime per position.
  - `encounterSeed(ts, leaderId, placeId, phase)` takes `phase` as a key or a bigint code.
  - `hubSeed(regionId)` and `stationSeed(regionId, locationId)` read no timestamp.
- **Levels:** `countToLevel`, `homeCount`, and the `DensityLevel` type.
- **Rules:**
  - Encounters: `gapPct`, `encounterChanceBp`, `encounterHit`, `pickEncounterPool`
  - Groups and party: `groupSizeFor`, `composeGroupRoles`, `partyLevel`
  - Settling and gathering: `settleCount`, `yieldForLevel`, `nextHarvest`, `isHarvestCapped`
  - Hunters and vacuum: `hunterActive`, `pickHunterTargets`, `pickSurgeTarget`
  - Region and homes: `regionTrend`, `creatureHomeLevels`, `resourceHomeLevel`
  - Hubs and stations: `bandPct`, `hubCountFor`, `hubHasStation`, `chooseHubs`
- **Exported interfaces:** `EncounterPoolInput`, `SettleInput`, `SettleResult`, `HarvestState`, `HubPlace`, and the type `EncounterPhase`.
- **Tests:**
  - `density_rules.test.ts` has 79 tests. They include the source guard (no ctx, Math.random or Date; imports only `./economy_rules` and `./mechanical_vocabulary`; no `% 100n`) and the lazy-vs-stepwise settling property test (5 starts x 5 spans x 4 step counts, uneven steps).
  - `mechanical_vocabulary.test.ts` gained 15 tests.
