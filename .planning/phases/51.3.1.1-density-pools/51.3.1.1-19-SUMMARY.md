# Phase 51.3.1.1 Plan 19: Nearby creature, named and resource pool cards Summary

Nearby now shows one card per creature family (icon, con-coloured name, `Lv 4–5`, density badge, template line, group hint, labelled Pull), the named enemies and World event spawns as Fight cards, and one Gather card per resource pool of this time of day. No ordinary enemy and no resource node is listed any more. The NPC, bind stone and player rows sit under "Also here".

## What was built

- **`pools.ts`**: pure view models.
  - `familyRows(pools, playerLevel, place)`: danger-first order (density desc, lvHi desc, name, id), wiped-out families last.
  - `namedRows(namedHere, eventSpawnsHere, templates, quests, playerLevel)`: living before slain, then level, then name. The sub-line is `Named|Boss · Quest: X · Lv n · In combat`, and a slain enemy reads `Slain · back after a long rest`.
  - `resourceRows(pools, isNight|null, caps, gathering, now, place)`: time-of-day filter, then the harvest-cap reason or the gathering reason.
  - `allExhausted`, `nearbyGroups` (ready gate, safe/uncharted, empty lines, Also here label), `NEARBY_COPY`.
  - All copy comes from `@game-data/density_lines`.
- **`familyIcons.ts`**: closed maps from the UI-SPEC table, using own-key lookup. Unknown keys fall back to PhSkull for families and PhCube for resources.
- **`DensityBadge.vue`**: shows the word with an sr-only `Population: ` or `Supply: ` prefix. Level classes use the token `color-mix` recipes.
- **`PoolCard.vue`**: an `li > div` shell with three variants: family (PhTarget Pull), named (PhCrownSimple or PhSkull icon, PhSword Fight) and resource (PhHandGrabbing Gather).
  - The button's label is part of its accessible name (`Pull Goblins`), and the button is described by the line plus the hint or reason.
  - It is aria-disabled when offline, capped, gathering or in combat elsewhere, and aria-busy while pending.
  - Level 0 or slain: no button. Names ellipsize; lines and reasons wrap. Buttons are 28px, or 44px under 899px.
- **`NearbyList.vue`**:
  - Groups in this order: Creatures, Named & quest targets, Resources, Also here.
  - Pool groups wait for `game.poolsAppliedFor(place.id)`.
  - Pull, Fight and Gather call `consoleApi.pull/fight/gather` inside `createActionRunner`. `reportRejections` prints the send error line.
  - A cap-expiry timer re-reads `game.clock` when the soonest cap runs out.
  - `keepFocus` keys: `family-{id}-{level}`, `named-{key}-{state}`, `resource-{id}-{level}-{capped}`, then the rows, indexed over `li.nearby-item` across groups.
- **`enemies.ts`**: now only `enemyStatus`. **`nearby.ts`**: the node kind, `visibleNodes` and `nodeStatus` are gone, as is the `nodes` input.

## Deviations from Plan

1. **[Rule 3 - Blocking] Time of day is not reachable from Nearby.** The world_state time lives only in the session's FrameView (AppFrame props). Neither GAME_KEY nor FRAME_KEY exposes it, and the files that could pass it (`context.ts`, `AppFrame.vue`, `ContextContent.vue`, `ContextRail.vue`, `MapScreen.vue`) are outside this plan.
   - `NearbyList` takes an optional `timeOfDay` prop. When it is null, every resource pool is listed and the server still refuses an out-of-time gather.
   - Behaviour with the prop set is tested. A follow-up must wire it (see Open items).
2. **[Rule 2] Named-enemy templates are not subscribed.** gameData only loads the templates of the spawns here and of the current fight. So a named enemy's level, con and Boss flag are unknown, and its card reads `Named` (plus `Quest: X` when a quest targets it) with no Lv. This is the UI-SPEC partial rule, but every named card is in that state today.
3. **Rejections through the console.** `consoleApi.pull/fight/gather` return void and swallow reducer promise rejections themselves (`useConsole.fire` only logs a warning). The runner therefore catches only a synchronous throw, and an async transport rejection does not print `Couldn't send that. Try again.` Fixing that is outside this plan (useConsole.ts).
4. **En dash** in level ranges (`Lv 4–5`), at the coordinator's request, to match Plan 20. The plan text said `Lv 4-5`.
5. **No current place keeps "No one is nearby."** A missing character or location row is treated as ready and safe, so `railsShell.test.ts` and the AppFrame.populated first-frame test pass unchanged. Neither file was edited.
6. **Test file outside my list:** `src/rails/ContextContent.test.ts` (Plan 20 does not list it).
   - The retired per-spawn "Nearby enemies" block became "Nearby event enemies (51.3.1.1-19)", 7 tests of the named Fight cards.
   - The two empty-line cases now use a safe place whose pool rows have applied (`QUIET_HERE`).
   - An unused `createInertCombatData` import was dropped.
7. `alsoHereLabel` is true only when a group above renders **and** there is at least one Also-here row, so a label never sits over an empty list.
8. **Pending state is momentary:** the console call is synchronous, so `aria-busy` lasts one microtask. It is tested through the PoolCard `busy` prop.
