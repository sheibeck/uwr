## Fixed Issues

### WR-01: An enemy heal or shield wind-up says "→ the party"

**Files modified:** `src/combat/windup.ts`, `src/combat/hostiles.ts`, `src/combat/combatFeed.ts`, plus the three tests
**Commit:** `20b92df9`
**Applied fix:** `windupTarget` now takes `targetEnemyId` and `enemyNames` and names the enemy ally before it tries the player or pet target. `HostileCastRow` carries `targetEnemyId`. The rail row (`hostileViews`) and the feed warning (`wireCombatFeed`) both pass the fight's enemy names. An ally id of 0 means no ally. If the ally's name is unknown, the old fallbacks still apply.

### WR-02: The rating level counts offline party members

**Files modified:** `src/rails/rating.ts`, `src/rails/rating.test.ts`, `src/map/useMapGraph.test.ts`
**Commit:** `ff72a67b`
**Applied fix:** `viewerRatingLevel` skips party members whose `online !== true`, the same rule as the server's `fightRoster` (D-14). `online` is now a required field of the characters input, so every caller has to supply it. `useRatingLevel` already passed `knownCharacters`, which carry it.

### WR-03: Named cards show the template's level

**Files modified:** `src/rails/pools.ts`, `src/rails/levelRange.ts`, `src/rails/NearbyList.vue`, plus four tests
**Commit:** `7f3ba204`
**Applied fix:**
- `namedRows` takes a new `place: NamedPlace | null` argument (`{ target, levelOffset }`). It levels a named enemy with `placeSpawnLevel` from `@game-data/enemy_rules`. That level drives the `Lv n` text, the con colour and the sort.
- The place target comes from a new `placeTargetLevel` in `levelRange.ts`, the client mirror of the server's `computeLocationTargetLevel(ctx, id, 1n)`. `routeLevel` now uses it too, so the client has one copy of the rule.
- When the place or its region row is unknown, the named card leaves the level out instead of showing a wrong one.
- Event spawns still use their own row level.

**Deviation to know:** `computeLocationTargetLevel` lives in `spacetimedb/src/helpers/location.ts`, not in `spacetimedb/src/data`, so it cannot be imported through `@game-data` without a server change. The client already mirrored it in `routeLevel`; that mirror is now the single client copy. A later server change could move the formula into `data/enemy_rules.ts`, and `placeTargetLevel` would then become an import.
