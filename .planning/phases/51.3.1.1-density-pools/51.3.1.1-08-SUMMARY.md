# Phase 51.3.1.1 Plan 08: Ordinary standing spawns retired Summary

Ordinary creatures now exist only as pools. Every path that used to top up standing spawns calls `ensurePoolsForLocation` instead: arrival, login, typed travel, quest pickup, the starter region reuse, the stage-1 world start and `/synccontent`. The day/night turn respawns nothing. `respawn_enemy` keeps its registration and guard but only drains. The old spawn-maintenance helpers are gone. Event spawns and named fights still use `enemy_spawn` (D-07). Nothing was published.

## What was built

**Helpers and the module root (Task 1)**
- `helpers/location.ts`: deleted `ensureSpawnsForLocation`, `respawnLocationSpawns`, `getLocationSpawnCap` and the private `countNonEventSpawns`. Kept `spawnEnemy`, `ensureAvailableSpawn`, `spawnEnemyWithTemplate` and `relevelLegacySpawns`.
- `ensureLocationRuntimeBootstrap` moved to `helpers/world_gen.ts`. It clears spawns at safe places, then calls `ensurePoolsForLocation` for every place.
- `helpers/travel.ts`: the dep is renamed `ensurePoolsForLocation` (type, destructure, `moveOne` call).
- `helpers/llm_apply.ts` (stage-1 start place) and `helpers/world_gen.ts` (starter region reuse) import and call `ensurePoolsForLocation` from `./families`.
- `index.ts`:
  - imports `ensurePoolsForLocation` (families) and `ensureLocationRuntimeBootstrap` (world_gen);
  - the deps object carries `ensurePoolsForLocation`;
  - `tick_day_night` no longer loops over places to respawn. The World line and the reschedule are unchanged.

**Reducers (Task 2)**
- The dep is renamed in `characters.ts` (login), `movement.ts`, `intent.ts` (three deps objects) and `quests.ts` (`pickUpQuestItem`'s aggro type and call, the destructure, `loot_quest_item`).
- `commands.ts` needed no change: it calls `ensureLocationRuntimeBootstrap` from deps by name.

**respawn_enemy drain and tests (Task 3)**
- `respawn_enemy`: the guard stays the first statement, then it returns. The comment says pending `enemy_respawn_tick` rows drain there. The `getLocationSpawnCap` import is gone.
- `reducers/no_ordinary_spawns.integration.test.ts` (7 tests, real handlers, strict mock, pool fixture):
  - an arrival at the flats (linked Skitterer plus two ungrouped undead types, no pools) seeds the Skitterers and a new undead family as creature pools and makes no spawn;
  - a second arrival leaves the flats' pools and the family count unchanged;
  - an arrival at the safe market seeds no creature pool;
  - `tick_day_night` (module) flips the world, reschedules once, and leaves `enemy_spawn` untouched;
  - `respawn_enemy` (module) inserts no spawn; a forged sender touches no db;
  - the bootstrap seeds the flats, clears the market's spawn, spawns nothing, and is a no-op the second time.
