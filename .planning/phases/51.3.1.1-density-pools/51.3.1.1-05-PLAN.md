1. **`helpers/combat.ts`.** Add `targetEnemyId?: bigint` to the enemy args of `executeAbilityAction`, and pass it through `executeEnemyAbility` to `resolveAbility`'s seventh parameter (Plan 04).
2. **`reducers/combat.ts` `pickEnemyTarget`.** Add an ally branch for ability target rules `lowest_hp_ally`, `single_ally`, `all_allies` and `self`. It returns `{ allyEnemyId }`:
   - heal: the living `combat_enemy` of the same fight with the lowest `currentHp/maxHp` below full (the caster included);

   - pass `targetEnemyId` to the immediate cast;
   - or store it in the `combat_enemy_cast` insert (`targetEnemyId`) for a wind-up;
   - and write `combat_enemy.healTargetEnemyId = allyId` (D-40).
4. **`landEnemyCasts`.** Use the cast's stored `targetEnemyId` when that ally still lives; re-pick with the same ally rule only when it is gone. A heal or shield never lands on a player.
5. **Clearing the heal target.** At the start of each enemy's round action (before choosing), clear `healTargetEnemyId` to `0n` if it is set and the enemy is not mid-wind-up on a heal or shield.
6. **Aggro target writes.** Wherever the round engine picks a player or pet target for an enemy (`processEnemyAutoAttackForRound` and the damage paths of `tryEnemyAbilityForRound`), write `aggroTargetCharacterId` / `aggroTargetPetId` when the value differs from the stored one. One update per enemy per round at most.
