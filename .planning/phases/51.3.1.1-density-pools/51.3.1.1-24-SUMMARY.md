## What was built

### Task 1: size constant and the family job input (54020d2a RED, b5236c6a GREEN)

- **Sizes (`economy_design_rules.ts`).**
  - `REGION_ECONOMY_SIZES` is frozen all the way down: small is 3 slots (common, uncommon, rare) and 3 recipes; medium is 5 and 5; large is 7 and 7.
  - `REGION_ECONOMY_SIZE: keyof typeof REGION_ECONOMY_SIZES = 'small'` (D-50, D-57). There is no command and no dial column; `economy_admin_commands.ts` has 0 mentions.
  - New functions: `gatherSlotsForSize`, `recipeCountForSize` and `recipeTierSlotsForSize(k, count)`. The first three tiers come from `recipeTierSlots(k)`; a fourth and later recipe alternates common and uncommon.
  - `REGION_ECONOMY_COUNTS.gatherables` and `.recipes` now derive from the size.
- **Handles and types.**
  - `familyRef(i)` gives E1.., and `memberRef(familyRef, serverRole, occurrence?)` gives E1.tank. A healer member reads E1.support, and a repeated role is E1.damage2.
  - New types `RegionEconomyFamily` and `RegionEconomyMember`.
  - `economyFamilies(input)` returns the stored families. A 51.3 input with no families key comes back as families of one, each with a single damage member.
  - `RegionEconomyInput.mode` is `'region' | 'family' | 'enemy'`, and the input gains optional `families` and `gatherSlots`.
  - `REGION_ECONOMY_BIGINT_PATHS` now has 6 paths, adding `families[].familyId` and `families[].members[].templateId`.
- **Input builder (`region_economy.ts`).**
  - Region mode adds `families` from `regionEconomyFamilies(tx, regionId)`: `creature_family.by_region` in id order, with members from `family_member.by_family` in the order tank, damage, support, caster. Fillers are included. A member whose template is missing is left out.
  - Region mode also adds `gatherSlots` from the size, and its recipe tiers now come from `recipeTierSlotsForSize`.
  - `'family'` mode takes a creature_family row: `families = [that family as E1]`, plus the region's existing materials, with no gather or recipe slots.
  - `'enemy'` mode is unchanged.
  - `EconomyJobContext` gains `familyId`, and `readEconomyJobContext` accepts `mode: 'family'` with a `familyId`.
  - `applyRegionEconomyResult` returns early for a family-mode job, because Plan 25 writes it.
- **Smoke input (`llm_inputs.ts`).** `smokeInputFor('region_economy')` is a small region-mode input with one family (E1.tank, E1.damage) and the small gather slots. It is never smoked.

### Task 2: block, volatile, schema and pins (bfba4feb RED, 96b8736d GREEN)

- **Route block.** `REGION_ECONOMY_BLOCK` is draft B1 as a plain literal with no interpolation.
- **Region mode volatile (`buildRegionEconomyVolatile`).**
  - It prints "Families:" with one family line per family, then an indented line for each member it has, in the order tank, damage, support, caster.
  - The count words are three, five or seven. The gatherable slots are joined with ", " and a final " and ". The recipe lines use the ordinals first to seventh. The recipe rules are the 51.3 rules, unchanged.
  - A region with no families prints `Families: none` and leaves out the "for each family above" line.
- **Late family volatile.** It follows the B2b wording. A stored 51.3 'enemy' input renders as a late family of one, and a 51.3 region input renders each enemy as a family of one with the small slots.
- **Escaping.** Every value goes through `w()`. A hostile family, member, handle or region name yields no raw `<` or `>`, 0 player_input tags, and no extra line.
- **Schema (`REGION_ECONOMY_SCHEMA`).**
  - `region` is nullable: `{ gatherables: array, families: array of ECON_FAMILY { family, drop, trophy, gear: array of ECON_GEAR_MEMBER { member, name, slot, weaponType, armorType, description } }, recipes: array }`.
  - `lateFamily` is nullable ECON_FAMILY.
  - It has no description text and no bounds, and schema_lint passes. The `LLM_JSON_SCHEMAS.regionEconomy` key is kept, and `ECON_CREATURE` is gone.

### Task 3: validator (cfbebd7b RED, c5136590 GREEN)

- **`validateFamilyEconomyReply(input, reply, isTaken)` returns a `ValidatedFamilyEconomy` or null.**
  - **gatherables:** one per input gather slot, in G order, with the slot rarity taken from the input. Extra reply entries are dropped. A missing slot is filled by rule (as in 51.3) and listed in `missingGatherables`.
  - **families:** `{ familyRef, familyId, drop, trophy, gear: { member, templateId, name, slot, weaponType, armorType, description }[], missingGearFor: bigint[] }`.
    - Family and member handles are compared normalised, and only against `input.families` (via economyFamilies).
    - An unknown family is dropped, and so is a second entry for the same family. Gear for an unknown or foreign member is dropped. A member with no gear is listed in `missingGearFor`.
    - `missingFamilies` lists the familyIds of input families the reply left out.
  - **recipes:** the first `recipeSlots.length` replies, validated by the 51.3 recipe rules over G handles and D:E family drops. `missingRecipes` lists the slot indexes with no usable recipe. A D:E3 handle with no E3 family is dropped, and the recipe is then repaired by the 51.3 rules.
  - Numbers are never read: a number placed where a handle or name belongs is ignored.
  - It returns null for a non-object reply, for a reply whose region is not an object, and for a region from which nothing was supplied.
- **`validateLateFamily(input, reply, isTaken)`** reads `reply.lateFamily` and returns a `ValidatedFamilyEntry` or null. A missing or unknown handle is repaired to the single listed family. A stored 51.3 late-creature input reads as a family of one.
- **51.3 functions.** `validateRegionEconomyReply` and `validateLateCreature` are unchanged, and the gatherable body moved into a shared `gatherableAt` helper. The `region_k0` and `late` fixtures still validate through them, and the new functions return null for them.
