# Phase 51.3.1.1 Plan 03: Additive schema and local publish A Summary

The whole additive schema of the density pools phase is now live on the local database. Ten new tables are in place, and `pool_level` is the only public one. The hidden count, home level, wipe and settle times live only in the private `place_pool` table. Thirteen defaulted columns were added to six existing tables. A per-sender `my_harvest_caps` view and a guarded `tick_pools` scheduled reducer were added too. One local publish (key 108 before and after, no clear) accepted everything, and the client bindings were regenerated.

## What was built

**Tables** (`schema/tables.ts`, registered by snake_case key):

| Table | Public | Columns | Indexes |
|---|---|---|---|
| `creature_family` | no | id (pk autoInc), regionId, key (unique), name, singularNoun, pluralNoun, temperament, iconKey, creatureType, ambushVerb, ambushRest, fitTerrains | by_region |
| `family_member` | no | id, familyId, enemyTemplateId, role, filler (bool) | by_family, by_template |
| `family_relation` | no | id, familyId, otherFamilyId, kind | by_family |
| `place_pool` | no | id, regionId, locationId, kind, refId, count, homeLevel, wipedAtMicros, lastSettledMicros, dirty (bool), timeOfDay | by_location, by_region, by_dirty |
| `pool_level` | **yes** | id (pk, no autoInc, = place_pool.id), regionId, locationId, kind, refId, level, lvLo, lvHi, name, iconKey, temperament, singularNoun, pluralNoun, timeOfDay | by_location, by_region |
| `pool_harvest` | no | id, characterId, locationId, windowStartMicros, gathers, cappedUntilMicros | by_character |
| `pool_state` | no | id (pk singleton 1n), version, lastHunterMicros, lastTrendMicros | - |
| `pool_region` | no | regionId (pk), trendSum | - |
| `pool_rumor` | no | id, regionId, locationId, kind, familyId, otherFamilyId, atMicros | by_region |
| `pool_tick` | no (scheduled tick_pools) | scheduledId, scheduledAt, afterRegionId | - |

All numbers are u64, so none is optional.

**Defaulted columns:**
- `location`: shortName '', placeNoun '', isHub false.
- `resource_gather`: poolId 0n.
- `combat_enemy`: poolId 0n, healTargetEnemyId 0n.
- `combat_enemy_cast`: targetEnemyId 0n.
- `combat_encounter`: origin '', originFamilyId 0n, originLevel 0n, originName '', originPlural ''.
- `economy_item`: familyId 0n.

Every production insert site writes the defaults, so behaviour is unchanged.

**View:** `views/harvest.ts` registers `my_harvest_caps` (row `MyHarvestCap`: id, locationId, cappedUntilMicros). It returns the active character's rows with `cappedUntilMicros > 0n`, through `player.id.find(sender)` and `pool_harvest.by_character.filter` only, and never reads the timestamp. Exported helper: `myHarvestCapRows(ctx)`.

**Scheduled reducer:** `scheduledReducers['tick_pools']` in `index.ts`. Its first statement is the module guard, then it inserts one `pool_tick` row at `now + DENSITY_RULES.POOL_TICK_MICROS` with `afterRegionId 0n`. Nothing inserts a tick yet; Plan 14 adds the work and the arming.
