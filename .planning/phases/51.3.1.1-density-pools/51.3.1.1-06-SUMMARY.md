# Phase 51.3.1.1 Plan 06: The pool engine Summary

This plan adds the pool engine. Pools are created with a public level mirror. `setPoolCount` is the only writer of the hidden count. Every read-modify settles the pool from elapsed time first. Kills, hunters and gathers all deplete through one path. A wipe triggers a seeded rival surge. Only level falls are announced, and only to online characters at the place. Big shifts go through one seam, `onPoolShift`, which writes the World event line and records an NPC rumour.

## What was built

**`helpers/pools.ts`**
- `familyRangeAt(ctx, familyId, locationId)` returns `{ lo, hi }`. For each member it takes `computeLocationTargetLevel(ctx, loc, 1n)`, applies `placeSpawnLevel` with the place's `levelOffset`, then takes the min and max. A family with no members reads `0n..0n`.
- `createPool(ctx, { regionId, locationId, kind, refId, homeLevel, timeOfDay?, count? }, now)` finds or creates a pool by (locationId, kind, refId). A new pool starts at its home count, or at `count` when given. It is settled at `now`, and its `pool_level` mirror is written.
- `mirrorLevel(ctx, pool)` inserts the mirror, or updates it only when the level, the level range or a display string changed:
  - creatures: the name, icon, temperament and nouns come from `creature_family`;
  - resources: the item name; the icon comes from `economy_item.kind`, else `materialKind(name)`; lvLo/lvHi are `0n`.
- `setPoolCount(ctx, pool, next, now, settledMicros = now)` is the only writer:
  - it clamps to 0..COUNT_MAX;
  - a creature reaching 0 stamps `wipedAtMicros = now` once; a later write at 0 keeps the first stamp, and any positive count clears it;
  - dirty = `count != home || count == 0`;
  - the mirror is rewritten only when the level changes;
  - a missing row is left alone.
- `settlePool(ctx, pool, now)` re-reads the row by id, then applies `settleCount`. It writes only when the count, the wipe stamp or the dirty flag changes, and announces an Overrun settling down (rises are silent).
- `poolsAt(ctx, locationId, kind?, now = ctx.timestamp)` returns the place's pools, each settled, in id order.
- `applyDepletion(ctx, pool, points, now, cause, seed?)`:
  1. settles the stored row;
  2. writes `count - points` through `setPoolCount` (clamped at 0, nothing reserved);
  3. announces a fall;
  4. when a creature pool hits 0, runs the vacuum (once; a pool already at 0 runs nothing).
- `announceFall(ctx, pool, from, to, now, cause)` writes `density_gone` on a wipe (plus `onPoolShift` family_wiped). A settle from Overrun writes `density_down` with `overrunSettleLine`; any other fall writes `density_down` with `densityDownLine`. Lines go to online characters at the place only, and resources stay silent.
- `runVacuum(ctx, wipedPool, now, seed = poolSeed(now, pool.id))` returns the surged pool or null:
  - **Candidates:** the wiped family's rival and predator relations, plus the families that name it as prey or rival. Same region only, sorted by id.
  - **Pick:** a candidate already pooled at the place wins (count raised to at least 75, home raised to at least 2). Otherwise a candidate whose `fitTerrains` includes the place's terrain gets a new pool at 75 with home 2. Otherwise nothing happens.
  - **Lines:** a Keeper `narrative` takeover line (with segments) goes to online characters at the place. Then `onPoolShift` vacuum_takeover, then overrun_surge.

**`helpers/pool_events.ts`**
- `onPoolShift(ctx, shift, now)` resolves the names (family plural and name, place name, region name) and returns silently if any is missing. It then calls `appendWorldEvent(ctx, 'world_event', worldEventName(...))` and inserts one `pool_rumor` row. Finally it trims the region's rumours: rows older than the TTL go first, then the oldest past RUMOR_KEEP_PER_REGION (5).
- `recentRumors(ctx, regionId, now)` is read-only. It returns `rumorItem` strings, newest first, at most RUMOR_PROMPT_MAX (3). It drops rumours older than the TTL and rumours whose names no longer resolve.

**`helpers/pool_fixture.ts`** (test-only) is described under "For later plans" below.

## Deviations from Plan

1. **[Ordering] Task 3 ran before Task 2.** Task 2's vacuum calls `onPoolShift`, which Task 3 creates. Each task still had its own RED and GREEN commits.
2. **[Rule 2 - Correctness] A stricter source pin.** `setPoolCount` writes a row variable, so a check on "argument text that names count" would miss real writers. The pin now fails on any `place_pool.id.update(` outside `helpers/pools.ts`, and requires exactly one inside `setPoolCount`. Today only passages.ts touches place_pool elsewhere, and it only deletes.
3. **[Rule 1 - Correctness] An optional `settledMicros` on `setPoolCount`.** Without it, settling would reset `lastSettledMicros` to `now` and lose `settleCount`'s leftover time. A test proves that one late settle equals many small ones.
4. **[Interpretation] Rivalry runs both ways.** Vacuum candidates also include families that name the wiped family as their rival (D-20: "a rival ... moves in"), and a test covers it. Prey of the wiped family are never candidates.
5. **[Schema gap, no schema change] Trend rumours.** `pool_rumor` has no trend column, so a region-trend rumour stores `kind = 'region_trend:wilder' | 'region_trend:quieter'` (`rumorKind`, `TREND_RUMOR_PREFIX`).
6. **`poolsAt` takes an optional `now`** (default `ctx.timestamp`), so tests and the tick can pass a time.

No file outside `files_modified` was changed.
