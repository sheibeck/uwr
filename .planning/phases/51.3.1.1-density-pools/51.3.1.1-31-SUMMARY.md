# Phase 51.3.1.1 Plan 31: Client follow-ups (Map rating wiring, encounter row, named templates, time of day, send errors, Fight labels) Summary

The live Map now rates every loaded place from the pool rows for the party's lowest level standing with you (D-56): ring colour, caption and aria label, the destination tag '{Rating} · Lv a–b', and a legend that names the same level. The client also binds the own fight's `combat_encounter` row, so the heading and source line are live. It subscribes the templates of your own named enemies, so named cards show Lv, con colour and Boss. Nearby now hides resource pools outside their time of day, using the frame. A Pull, Fight or Gather card whose reducer call rejects prints the send error line. Named and World event keywords read "Fight {name}". One extra fix came from the coordinator: combat pets never loaded in a fight, because the pets query compared the optional `active_pet.combat_id` with a literal. Pets now come through the fight roster.

## Deviations from Plan

### Coordinator-directed fix
**1. [Rule 1 - Bug] Combat pets never loaded in a fight (pre-existing since Phase 48, e2dc5ccb)**
- **Found by:** the owner, live; the coordinator relayed it during Task 3.
- **Issue:** `combatPets` produced `SELECT * FROM "active_pet" WHERE "active_pet"."combat_id" = 8208`. `active_pet.combat_id` is `t.u64().optional()`, so SpacetimeDB rejected it: "The literal expression `8208` cannot be parsed as type `(some: U64 | none: ())`".
  - The `spacetimedb` 2.10.1 query builder renders literals with no Option form (`literalValueToSql`).
- **Fix:** a semijoin from the fight's participants to their pets on the indexed `character_id`, built with the query builder's `rightSemijoin`. The binding filter (`row.combatId === k`) keeps only this fight's pets. It was verified against the local server.
- **Guard:**
  - A new `queries.test.ts` describe scans every SQL `gameQueries()` builds. It resolves each `"table"."column" <op> literal` to the generated column type and fails on an Option column.
  - A gameData test covers the client filter for a pet with no combat id.
- **Other combatId queries checked:**
  - `combat_enemy_effect.combat_id` and every other `combat_id` used by the client queries are non-optional.
  - The other optional `combat_id` columns (`active_bard_song`, `bard_song_tick`) are not subscribed by the client.
  - The other query files (`src/map`, `src/ledger`, `src/social`, `src/creation`, `src/session`) compare no Option column. I checked them against the generated bindings.
- **Files:** `src/game/queries.ts`, `src/game/queries.test.ts`, `src/game/gameData.test.ts`.
- **Commit:** 155ea118 (RED 2817c04c).
