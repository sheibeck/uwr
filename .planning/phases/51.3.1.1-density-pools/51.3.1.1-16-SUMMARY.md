# Phase 51.3.1.1 Plan 16: Look, examine and typed commands read the pools Summary

The place description, examine and the typed `enemies` / `con` / `attack|fight|kill|pull` commands now describe families with level ranges, density words and lines, resources available at this time of day, and a safety rating. The typed pull and the Pull button share one helper, `pullFamilyFor`, and the `[Careful Pull]` / `[Charge In]` prompt is gone.

## What changed

**look (`helpers/look.ts`, also the arrival look in travel).** Sections 6 and 7 were replaced. The order is now:

1. `Safety: {Word}. {rating line}` from `placeRating`. A safe place reads Safe. A living named enemy of the character here, or a boss individual, raises the rating one step (D-34).
2. `Enemies nearby: ...` in the old format, but only for individuals (D-07):
   - the character's living named enemies here;
   - spawns linked to a World event;
   - spawns whose template is in no family.
3. Creature families in danger order: density descending, then top level descending, then name, then id.
   - Each reads `{{color:<con>}}[{Family}]{{/color}} (Lv a-b, {Word}). {creatureLine}`.
   - A wiped-out family prints only its line.
4. Resources available now (D-55): `{{color:#22c55e}}[Gather {Resource}]{{/color}} ({Word}). {resourceLine}`. An Exhausted resource prints only its line.

Quest items and exits follow, unchanged. `resource_node` is no longer read.

**examine (`helpers/examine.ts`).** The category order is:

1. NPCs.
2. Individuals: today's `You study ...` line.
3. Families, matched by name, plural, singular or a member's name. The answer is the name, `Lv a-b, {Word}.`, the creature line, the group hint, then `Members: {name} ({tank|damage|support|caster}), ...`.
4. Players.
5. Resource pools available now: the name, `{Word}.`, the resource line, then the existing `Gathering yields ...` line and the description.
6. Items, neighbouring places, the bind stone.

Exact matches still win across every category before any partial match.

**Typed commands (`reducers/intent.ts`):**
- `enemies` / `mobs`: families first (keyword, range, word; a wiped-out family is grey with no keyword), then individuals in the old line format. With neither, it prints `No enemies nearby.`.
- `con <name>`: an NPC still gets the regard line. Then `findFightTarget` resolves the name:
  - an individual gets today's singular threat line;
  - a family gets the plural threat line for its top level, plus `Population: {Word}.`.
- `attack|fight|kill|pull [name]`:
  - the not-in-combat check comes first;
  - `findFightTarget` resolves a name. Exact matches are tried before partial ones, and within each pass individuals come before families;
  - with no name, `firstFightTarget` picks the first living family, else the first individual that can be fought;
  - a family goes to `pullFamilyFor`; an individual goes to `fightIndividualFor`;
  - refusals go through `fail(..., 'combat')`, the same as pull_family;
  - an unknown name reads `No enemy named "{name}" here. Nearby: [..].`; with nothing at all it reads `There is nothing to fight here.`.

**Shared pull (`helpers/encounters.ts`, `reducers/pools.ts`).**
- `pullFamilyFor(deps, ctx, character, storedPool, now): string | null` is the whole Plan 11 pull body:
  - the same checks in the same order: fighting, gathering, not here, safe, missing family, settle, wiped out;
  - then the roster's lowest level, `drawForPull`, and `startPoolFight` with origin 'pull' and the lead-in line.
- `pull_family` now only checks ownership, looks up the pool and calls `pullFamilyFor`.
- `fightIndividualFor(deps, ctx, character, one)`:
  - a named enemy is fought as `pull_named_enemy` does it: spawnEnemyWithTemplate (its throw becomes the refusal), mark it slain, `deps.startCombatForSpawn`, then `You engage {name}!`;
  - a spawn is fought as `start_combat` does it: it must be available, and no roster member may already be in combat.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] intent.test.ts needed the recording server mock**
- **Found during:** Task 1
- **Issue:** look.ts now reaches helpers/encounters.ts, which imports spacetimedb/server. The real package cannot load under vitest ("Unexpected identifier 'iter'").
- **Fix:** intent.test.ts now mocks `spacetimedb/server` with the recording mock and records the schema in beforeAll. Its resource-node look cases became resource-pool cases. The file is in this plan's list.
- **Commit:** fa363065

**2. [Rule 1 - Bug] examine read spawns in any state**
- **Found during:** Task 1
- **Issue:** The old examine described a spawn whatever its state. The shared `individualsHere` lists only living spawns (available, engaged or pulling).
- **Fix:** Two examine.test fixtures (Ash Wolf, Stone Golem) now carry `state: 'available'`. Their output is unchanged.
- **Commit:** d8c75b89

**3. [Rule 2 - Correctness] The typed fight pattern is whole-word and includes pull**
- **Issue:** The old `/^(?:attack|fight|kill)\s*(.*)$/` matched "attacking". Adding pull that way would have made "pullover" a pull.
- **Fix:** The pattern is `/^(?:attack|fight|kill|pull)(?:\s+(.*))?$/i` on the raw text. intent.test.ts pins it against the source, and the "attacking" case is now a non-match.
- **Commit:** 6f257147

### Choices inside the plan's latitude
- **Rating level.** The look rating uses the lowest level of the fight roster (D-56, Plan 02 handoff). For a solo character this is the same as the plan's "looking character's level". Con colours use the character's own level.
- **Individuals rule.** An individual is a spawn linked to a World event, or one whose template is in no family. This is wider than "event spawns" alone: it keeps boss_kill and named-fight spawns visible, as D-07 asks.
- **Wiped families in `enemies`.** A wiped-out family is listed grey, without a keyword.
- **Code moves.** `PULL_REFUSALS` moved to encounters.ts and is re-exported from reducers/pools.ts. `PoolMember` gained `name`.

No production file outside files_modified was touched.

## PROPOSED copy for the D-58 review

These are new strings. Everything else comes from density_lines or is existing wording.
- `Safety: {Word}. {rating line}`. The label `Safety:` is `SAFETY_LABEL` in helpers/look.ts.
- `Members: {name} ({role}), ...`. The label `Members:` is `FAMILY_MEMBERS_LABEL` in helpers/examine.ts.
- Family examine line 2: `Lv a-b, {Word}.`, and the group hint with a full stop (`Expect one or two.`).
- Plural threat lines in `threatLine(subject, diff, true)` in helpers/encounters.ts:
  - `{Family} pose little threat. ...`
  - `{Family} are beneath you, ...`
  - `{Family} appear to be an even match. ...`
  - `{Family} look dangerous. ...`
  - `{Family} radiate menace. ...`
  - The two `would` lines are the same as the singular ones.
- The family con suffix `Population: {Word}.` reuses `DENSITY_SR_PREFIX.creature`.
- In `FIGHT_TEXT`, `unknown` / `unknownNearby` keep the old typed-attack wording `No enemy named "{name}" here. Nearby: ...`. `nothing` and `notHere` are existing strings.
