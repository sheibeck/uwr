## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug in plan data] Grave Hounds ambush verb 'bay' -> 'lope'**
- **Found during:** Task 2.
- **Issue:** The plan requires `ambushVerbForms(verb, '').one === verb + 's'` for every bank entry. `ambushVerbForms` treats a verb ending in y as irregular and falls back to "bursts", so 'bay' fails that rule.
- **Fix:** Changed the verb to 'lope' ("Grave hounds lope out of the fog"). The copy is PROPOSED, so the owner reviews it either way.
- **Commit:** ebecba81.

**2. [Clarification] History markup gives '' rather than being stripped**
- **Issue:** The plan's action said "markup stripped ... first", but its behavior list and threat T-93 say markup gives ''.
- **Fix:** Implemented the stricter reading: a tag, an entity or any character outside the allowed set gives ''.
- **Also added:** curly apostrophes become `'`, and en/em dashes become `, `, so ordinary model punctuation does not drop a history.
- **Banned-word check:** the World-event banned word is matched with `/rip{2}le/i`, which keeps the source clean for `no_ripple_word.test.ts`.

**3. [Coordinator change, D-71] The feud is a chance per region**
- `FEUD_CHANCE_PCT 35` is rolled with `feudHappens(familySeed(regionId))` at `POOL_ROLL.FEUD_CHANCE 88n`.
- `feudCountFor` returns 0 when the roll misses, otherwise 2-3 as before. It still returns 0 below two families.
- Over region ids 1..1000 the hit share is within 30-40% (test bound). Both 2 and 3 occur among the hits.
- `completeRegionFamilies` with feudCount 0 returns `feudKeys` []. It clears every `inFeud` mark and writes rule histories without the truce sentence (tested).

### Notes
- `POOL_ROLL.FEUD_PICK + 1` equals `RULE_FAMILY_ORDER` (87n), and both roll on `familySeed`. The plan fixes these indexes. The only effect is a weak correlation between the second feud pick and the rule-family shuffle, which has no gameplay effect.
- I also fixed a stale comment in `family_validate.ts`: ENEMY_ITEM -> CREATURE_TYPE, which Plan 23 had left for Plan 27. The file is in this plan's list.
