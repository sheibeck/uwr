# Phase 51.3.1.1 Plan 22: Encounter panel, enemy cards with role chips and target lines, mobile strip Summary

Each enemy card now shows a role chip (Tank, Damage, Caster, Support for the server's healer, Named, Boss), a `Down` HP text once defeated, and a target line (`Targeting you` in accent-300, `Targeting {name}` or a pet name, `Healing {ally}`, `Out of the fight`). The panel heading reads `Encounter · {Family} · {n} left` with an origin source line and a rail foot `[dot] {Place} · {Rating}`. The mobile strip chips lead with the role icon, and the Phase 48 threat block is gone.

## What was built

- **`src/combat/roles.ts`**: `roleView(role, { named?, boss? })` returns a frozen `{ key, word, icon, cls }`.
  - It reads the role through `normalizeEnemyRole` (`@game-data/family_rules`).
  - `healer` maps to `Support` here and nowhere else (the grep finds `'Support'` only in roles.ts).
  - Boss, then Named, take precedence.
  - Icons: PhShield, PhSword, PhMagicWand, PhFirstAidKit, PhCrownSimple, PhSkull.
- **`RoleChip.vue`**: a span (Micro 10 / 500, uppercase, 0.1em, padding `0 4px`, `--radius-sm`, line-height 16, gap 4) holding the 12px aria-hidden icon and the word. Colours come from existing tokens. The background is `--color-bg` on the rail and `--color-surface` on the sheet.
- **`hostiles.ts`**:
  - `HostileEnemyRow` gains `aggroTargetCharacterId`, `aggroTargetPetId` and `healTargetEnemyId`.
  - `HostileTemplateRow` gains `role`.
  - The input gains `namedTemplateIds` and `namedFight`.
  - `HostileView` gains `role` and `intent: { kind: 'targeting' | 'healing' | 'none'; name; self }`. `hpText` is `'Down'` when defeated.
  - `encounterHeading(title, livingCount)` wraps the shared builder.
  - `encounterTitle(encounter, hostiles)` gives the family name, the enemy's own name for a named fight, or '' with no origin.
  - `encounterSourceView(encounter)` returns `{ text, tone: 'ambush' | 'neutral' }` or null.
  - `encounterRowOf(combat)` reads the optional `combat.encounter` ref.
- **`HostileCard.vue`** (still one button with aria-pressed, phrasing children only):
  - Children in order: the role row (RoleChip, then PhCrosshairSimple when targeted), the name row (name, `Lv n`), the HP track, effect chips, wind-ups, then the target line.
  - The target line has a 1px neutral-800 top rule and padding-top 4. Its icons are PhCrosshair, PhFirstAid and PhSkull at 12px.
  - The old Boss tag is gone.
- **`EncounterPanel.vue`**:
  - The h6 heading ellipsizes. `Tab to cycle` shows on the rail only.
  - The source line is Label 12: con-orange for ambush origins, neutral-400 for the rest.
  - Cards are in one column.
  - The rail foot uses RatingMark (dot only, size 12) plus the place and rating text, pinned with `margin-top: auto`. It reads `usePlaceView().value?.rating`.
  - The sheet has no hint and no foot; the source line is its first paragraph.
  - The ThreatBlock usage and imports are removed.
- **`EncounterStrip.vue`**:
  - Each chip leads with the role icon (12, role colour class, aria-hidden). The role word reaches the chip's aria-label through `HostileView.ariaLabel`.
  - The chip name is capped at `max-width: 144px`, so a chip that sizes to its effect chips still ellipsizes.
  - The strip is `min-width: 0`.
  - The heading uses the same title and count as the panel.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] A long name on a strip chip with effects did not ellipsize**
- **Found during:** Task 2 (the Q8 overflow backstop)
- **Issue:** `.hostile-chip.has-effects` uses `flex-basis: auto`, so such a chip grew to the full max-content width of a long name.
- **Fix:** `.chip-name { max-width: 144px }` (the ExitChips text-column cap) and `.encounter-strip { min-width: 0 }`.
- **Files modified:** src/combat/EncounterStrip.vue
- **Commit:** a4f05fd8

**2. [Rule 1 - Test] A max-HP 0 row is defeated, so it now reads Down**
- **Found during:** Task 1 GREEN
- **Issue:** The existing hostiles test expected '0/0' for a 0/0 row. The plan's `Down` rule covers every defeated row, so the test now expects 'Down'.
- **Commit:** a8d470c0

### Process deviations

**3. The threat files' deletions landed in Plan 21's commit 832d213d.** I staged `git rm` of ThreatBlock.vue, threat.ts and threat.test.ts, then ran the tests. In that window, Plan 21's executor committed and the staged deletions went in with its map commit.
- Between 832d213d and a4f05fd8, the tree had `EncounterPanel.vue` still importing the deleted ThreatBlock, so those intermediate commits do not build.
- a4f05fd8 fixed it, and the tip is consistent.
- Nothing was lost.
- Lesson for later executors: do not stage deletions ahead of the commit. Run `git rm` in the same command as `git commit`.

**4. The encounter row is not bound on the client (outside my lane).**
- The plan says to "add the encounter row to CombatData if it is not exposed yet". It is not exposed, and `combat_encounter` is not subscribed anywhere in `src/`.
- The fix needs `src/game/queries.ts`, `src/game/gameData.ts` and `src/game/context.ts`. None of them is in this plan's files_modified, and the coordinator rule forbids touching them, so I did not.
- Instead, the panel and strip read the row through an optional seam, `encounterRowOf(combat)`, which reads `combat.encounter?.value`.
- The component and frame tests provide `encounter: ref({...})` and pass, so the display is complete.
- In the live game, until the binding exists, the heading reads `Encounter · {n} left` and no source line shows. This is the UI-SPEC's "no recorded origin" fallback, not an error.
- See Open items for the exact wiring.

**5. Test files outside the list:** `src/combat/effectChipsGuards.test.ts`. RoleChip.vue and roles.ts were added to its explicit guard FILES list, as the plan's Guards step asks. Neither Plan 19 nor Plan 21 lists that file.
- `src/frame/railsShell.test.ts` needed no change: it has no threat case.
