- `race_definition` (spacetimedb/src/schema/tables.ts:1951-1965) has a btree index `by_name` on `nameLower`. Existing lookups by a character's race use exactly `ctx.db.race_definition.by_name.filter(character.race.toLowerCase())` and take the first row (spacetimedb/src/reducers/intent.ts:426-428). Use the index; no `.iter()` scan and no fallback is needed.
- `nameLower` is written as `race.raceName.toLowerCase()` (spacetimedb/src/helpers/llm_apply.ts:304-317) and the character row stores `race: state.raceName || 'Unknown'` (spacetimedb/src/reducers/creation.ts:198). Lowercasing `character.race` therefore hits the stored row.
- Mock quirk (spacetimedb/src/helpers/test-utils.ts:98, documented in creation_generation.test.ts:5): the mock maps the `race_definition.by_name` accessor to the column `name`, not `nameLower`. Seed a race_definition row whose `name` AND `nameLower` are both the lowercase race name (for example `saltkin`) while the character row keeps `race: 'Saltkin'`.
- Admin gate of `level_character` (spacetimedb/src/reducers/commands.ts:576-578): `requireAdmin(ctx)` (spacetimedb/src/data/admin.ts:13-17) accepts only a sender whose `toHexString()` is in `ADMIN_IDENTITIES`, then `requireCharacterOwnedBy(ctx, characterId)` (spacetimedb/src/helpers/events.ts:31-39) requires the admin's own `player` row (found by `ctx.sender`) to have a `userId` equal to the character's `ownerUserId`. A test seed therefore uses a sender object `{ toHexString: () => <first entry of ADMIN_IDENTITIES> }`, a `player` row with that same object as `id` and `userId: 7n`, and a character with `ownerUserId: 7n`. The mock compares identities with `===`, so seed and sender must be the same object.
- `recomputeCharacterDerived` computes `maxHp = BASE_HP + totalStats.str * HP_STR_MULTIPLIER + gear.hpBonus + racialMaxHp` (spacetimedb/src/helpers/character.ts:89): only STR moves max HP.
- `awardXp` (helpers/combat_rewards.ts:312-350) only increments `pendingLevels`; the only stat rebuilds are `apply_level_up` (index.ts ~466-520) and `level_character` (commands.ts ~576-640). `recompute_racial_all` does not touch str..int.
- The legacy `race` table racial (`computeRacialAtLevelFromRow` / `computeRacialAtLevelForAdmin`) stays exactly as it is; this plan adds the `race_definition` bonus beside it.
