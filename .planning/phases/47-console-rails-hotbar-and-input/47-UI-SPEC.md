At 900px the center column is 360px: the slot strip scrolls sideways inside its own container (`overflow-x: auto; scrollbar-width: thin; scrollbar-color: var(--color-neutral-700) transparent`); the selector and the input never scroll or wrap. The composer never exceeds the column.

### Mobile (390 x 844)

```

Location row        (45)
```

- Slot row on mobile: 52px slots, gap 4, `overflow-x: auto`, hidden scrollbar (`scrollbar-width: none`), `scroll-snap-type: x proximity`. At 390 the 7th slot peeks by about 22px, which is the scroll affordance (no edge fade; a mask would need a named color).

- iOS Safari zooms a focused input under 16px. The input stays at 14px (type scale); the viewport meta must be `width=device-width, initial-scale=1, viewport-fit=cover` and must not use `maximum-scale`. Recorded as A9.

## Feed Contract (CON-01, CON-06)

### Container

`role="log"`, `aria-label="Story"`, `aria-live="polite"`, `aria-relevant="additions"`. Lines are appended in arrival order; rows that arrive in the same tick sort by `createdAt` then `id`. A line is identified by (source table, row id), so a resubscribe after reconnect never duplicates a line. The history keeps the last 300 lines in memory; older lines drop from the top. Dropping lines never moves the visible text (`overflow-anchor: auto`). A row with no `segments` and an empty `message` renders nothing. No line is ever dropped for having an unknown kind. No timestamps are shown (mock). Lines appear instantly, no entrance animation (Assumption A6).

On frame open for the active character the client sends one automatic `look` through `submit_intent`; its scene block is the first line. No echo is shown for the automatic look.

### Line kinds (one visual per kind)

Segment rows (`segments` present, Phase 46): every segment is its own line. A reply of 3 segments is 3 lines. Text is always a text node (Phase 46 contract A6): no `v-html`, no markup, no `{{color}}` interpretation. `speakerNpcId` is optional. Rows without `segments` render from `message` with the kind-based style in the same table.

| Kind | Source | Visual |
|------|--------|--------|
| Keeper narration | segment `kind = narration` (speaker "The Keeper"); no-segment rows of kind `narrative`, `llm`, `creation`, `combat_narration`, `class`, `character_created` | Two-row stack, gap 4: Micro uppercase label `The Keeper` (accent, `letter-spacing: 0.1em`) over the text, Body italic `--color-accent-200`. Every narration segment carries its label |
| NPC speech | segment `kind = dialogue`; no-segment `npc` rows (whole message, no split) | One line: speaker name (Body 500, `--color-line-npc`), then ` says, ` and the text in `--color-neutral-300` wrapped in typographic quotes added by the renderer (the server strips the outer quotes). With `speakerNpcId` the name is a keyword button (hail), hue unchanged, underline on hover and focus only |
| Whisper | `whisper` rows | `Name whispers, “text”` per the mock (sent whispers read `You whisper to Name, “text”`; planner parses the server's formats). Name 500 `--color-line-whisper`, rest `--color-neutral-300`. If the format is not recognized, the whole message in `--color-line-whisper` |
| Party chat | `event_group` rows of kind `group` whose message starts with `<author name>: ` | `PhUsersThree` 12px (visually hidden text `Party`) then `Name says, “text”`: name Body, `--color-neutral-400`, text `--color-text` |

### Keywords (CON-02)

- Detection is client-side and total: it never throws, matches whole words case-insensitively with Unicode word boundaries, prefers the longest name, never overlaps, and never matches inside an existing keyword. Vocabulary is the names the client already holds from subscribed tables: NPCs at the location, connected locations, resource nodes, and other players here. The player's own character name never matches. Every occurrence in a line is a keyword, not only the first. There is no server markup and no schema change.
- Scope: Keeper narration, NPC dialogue text, scene blocks, ripple blocks, quest and system lines. Not whispers, party chat, echoes or any player-authored text, so a player cannot place a clickable travel or hail control in the feed by typing a name. A dialogue speaker with `speakerNpcId` is a keyword regardless.
- Element: `<button type="button" class="keyword">`, inline, `display: inline; padding: 0; border: 0; background: none; font: inherit; color: var(--color-accent-300); text-decoration: underline; text-decoration-color: color-mix(in srgb, var(--color-accent) 45%, transparent); text-underline-offset: 3px; cursor: pointer`. Content is the matched substring as a text node. `title` and `aria-label` carry the action: `Hail Ferryman`, `Travel to Gloamwood`, `Examine Old Well`, `Whisper Marisol`.
- Actions: NPC hails (conversation starts, see Input). Connected place travels. Resource node or object sends `look at <name>` through `submit_intent` (echo `› look at <name>`). Player pre-fills a whisper. No confirmation for any of them. Travel echoes `› go to <name>`.
- While disconnected (Reconnecting bar) keywords stay visible, are `aria-disabled="true"` and inert.

### Keeper progress line and staged reveals (CON-06)

- A transient row after the last feed line, outside the 300-line history. Shown while the character has an active job in `my_llm_jobs`. Text is the Phase 43 indicator line for the job's route, imported from the server's `llm_indicator_lines` module through `@game-data` (never copied); an unknown route uses `LLM_INDICATOR_FALLBACK_LINE`; a route with a `null` line shows nothing. If more than one job is active, the oldest is shown.
- Visual: one row, `PhCircleNotch` 14px accent (rotating 1s linear; static under `prefers-reduced-motion`), 8px gap, text Body italic `--color-neutral-400`. No label, no tint. `role="status"`, `aria-live="polite"`.
- It disappears the moment the job is gone or terminal. If the job ended with an `errorCode`, one Error line carrying `userMessage` is appended once per job id.
- Staged reveals (world, class) are ordinary Keeper narration lines that arrive as the server writes them: stage 1 lands as narration, then the fill-route indicator shows while the rest fills. They are not a separate component.
- Narrative sends while a job is active are queued, see Input.

### Scrolling and the New lines pill

- Pinned means within 48px of the bottom. While pinned, each new line scrolls into view. While unpinned, new lines append silently and the pill shows.
- Pill: `button.btn.btn-secondary`, Label 12, `PhArrowDown` 14px after the text `New lines`, background `var(--color-surface)`, `box-shadow: var(--shadow-md)`, `border-radius: var(--radius-lg)`, height 32. Absolutely positioned bottom center of the feed region, 8px above the bottom edge. `aria-label="New lines, jump to latest"`. Hover, pressed and focus-visible as Nocturne.
- Activating the pill scrolls to the bottom (smooth, instant under reduced motion), hides the pill, re-pins. Scrolling back to within 48px by hand also hides it. Sending a line always re-pins and scrolls. The pill never shows when pinned and never shows with zero lines.

## Input Contract (INP-01, INP-02)

### Composer controls

| Element | Contract |
|---------|----------|
| Input | `input.input`, single line, Body 14, `min-height` 40 desktop / 44 mobile, leading `PhCaretRight` 16px accent inside at 16px from the left (`padding-left` 32), placeholder `What do you do?`, `autocomplete="off"`, `autocapitalize="sentences"`, `enterkeyhint="send"`, `aria-label="Your action"` |
| Send | Desktop: `.btn .btn-primary` with the text `Send`, padding `0 16px`. Mobile: `.btn .btn-primary .btn-icon` 44 x 44 with `PhPaperPlaneRight` 18px and `aria-label="Send"`. Disabled (45% opacity) when the trimmed input is empty or the connection is down |
| Enter | Sends. While an IME composition is active (`isComposing`) Enter does not send |
| After send | Input clears and keeps focus. The feed re-pins |
| Focus | On desktop the input takes focus when the frame opens. On mobile it does not. Enter, when no field has focus and no drawer or sheet is open, focuses the input. Esc in the input blurs it (so the number keys work) and never clears the draft |
| Reconnecting | Input and Send are disabled, placeholder becomes `Reconnecting…`, the draft is kept |

### History (INP history)

Up and Down recall the last 50 lines sent this session, newest first, in memory only. The first Up saves the current draft; Down past the newest restores it. Consecutive duplicates and empty lines are not stored. The caret moves to the end on recall. History stores the text as typed, not the routed form, and includes lines that went to conversation. Up and Down do nothing while an IME composition is active.

### Routing (pure client module, no server change)

`routeInput()` decides one of: command reducer, `talk_to_npc`, `submit_intent`. Rule from CONTEXT, restated so the matrix test and the UI agree:

- Command if the text starts with `/`, or its first word is a command word and the rest has that command's exact shape. Exact shapes: `who accept decline leave end endc endcombat renown factions events group` with nothing after; `invite kick promote friend` + one name; `w whisper` + a name and a message; `faction` + a name.
- Everything else goes to the conversation or intent path. "Who is that over there?", "Leave him alone", "End this now" and "Accept my apology" reach intent; `who`, `/who`, `invite Bob` run commands.
- A `/`-prefixed unknown command still goes to `submit_command`; the server answers in the feed. The client adds no new error copy.
- Visible feedback for every route is the echo line (see Feed) plus the server's own lines. Routing has no mode indicator except the conversation chip.

### Conversation mode

- Enter: a keyword hail, a Nearby NPC row, `hail X`, `talk to X`, or the NPC's bare name. Free text then goes to `talk_to_npc`.
- Exit: a farewell word (bye, farewell, leave, goodbye, end, quit, exit, back), a game action (go, look, attack, gather, craft and the like), travelling, the chip's end button, or the NPC leaving the location. Exit is client state only.
- Chip: `role="status"`, in the chip row directly above the input and below the hotbar, left aligned. A `.tag .tag-neutral`-style pill, 32px high: `PhChatCircleText` 14px accent, then `Talking with {Name}` Label 12 (max-width 240px, ellipsis, `title` carries the full name), then an end button with `PhX` 12px, `aria-label="End conversation with {Name}"`. Hover and pressed on the end button use the neutral tint (45). Nothing renders when not in conversation (no empty row).
- The input placeholder becomes `Say something to {Name}…` while the chip shows.

### Narrative send queue (input while the Keeper works)

- While the character has an active LLM job (`my_llm_jobs`), `submit_intent` and `talk_to_npc` sends do not go out. The line clears from the input, appears as a Queued echo, and is sent in order when the job clears. Commands and chat (`who`, whisper, party chat, group commands, every command-form reducer) go through immediately.
- The queue holds at most 3 lines. A fourth narrative send is refused: the text stays in the input and one System line appears, `Wait for the Keeper to finish first.`
- The queue is dropped when the character changes, the session ends or the connection is lost (a Reconnecting disable cannot hold queued lines; the Queued suffix lines stay in the feed without the suffix and a System line `Your queued lines were not sent.` follows). A queued line has no cancel control in this phase (Assumption A8).

### Pre-fill actions

| Control | Effect |
|---------|--------|
| Vitals rail `Invite` button | Input value becomes `invite ` and takes focus, caret at the end |
| Player keyword or Nearby player `Whisper` | Input value becomes `whisper {name} `, focus, caret at the end |
| Nearby player `Invite` | Sends the invite immediately (echo `› invite {name}`); no pre-fill |

If the input already holds an unsent draft, a pre-fill replaces it and the replaced draft is pushed to history so Up recovers it.

## Assumptions (decided here, not asked)

- **A1. Hotbar width.** The mock's desktop row is 728px inside a 676px column, so it overflows. Slots are 52px square and the strip scrolls sideways when it must. At 1280 everything fits exactly with 8px spare.
- **A2. Mock hues become tokens.** The NPC, whisper and quest hues exist only as `oklch()` literals in the mock. They become `--color-line-npc`, `--color-line-whisper`, `--color-line-quest` in the client token file and the pin test grows to 23 tokens. The debuff chip is derived with `color-mix`, so no fourth token. Party chat has no hue in the mock and stays neutral; combat kinds reuse the existing `--color-con-*` tokens.
- **A3. Effect time is rounds.** CONTEXT says "time remaining, counting down", but `my_character_effects` holds `roundsRemaining` only. The chip shows rounds and changes as the server decrements it. No client clock runs. If a duration-in-time field appears later, the same chip shows minutes and seconds.
- **A4. No route direction.** `location_connection` has no compass direction, so every route row uses `PhArrowRight` instead of the mock's up, right and down arrows.
- **A5. Italic.** The mock sets narration in italic. Nocturne loads upright Inter only, so the browser synthesizes the slant. Kept because the design depends on it; revisit by self-hosting Inter italic.
- **A6. No line animation.** The old client revealed sentences one by one. This client shows lines as they arrive; the Keeper's staged reveals already arrive over time. Motion is limited to the spinner, the cooldown ring and smooth scroll, all disabled under `prefers-reduced-motion`.
- **A7. Objects.** The mock lists an object (Old Well). No known subscribed table holds location objects. The row type and the keyword action are specified; if the planner finds no source, objects do not appear.
- **A8. Queue instead of block.** CONTEXT says narrative sends "wait". They are queued (3 max, in order, Queued suffix, no cancel) rather than the input being locked, so the player can keep typing. A cancel control is deferred.
- **A9. iOS focus zoom.** The input stays 14px per the type scale. If testing shows iOS zoom is intrusive, the owner may allow a 16px mobile input as one more exception.
- **A10. World event sides.** CONTEXT lists `world_event`, `event_contribution` and `faction` for the split. The event carries success and failure counters and no per-faction column. The bar uses those counters; side names are factions when the event names two, otherwise `For` and `Against`. Planner confirms the faction source.
- **A11. Level up and New skill tags** stay display-only. 45 A11 expected Phase 47 to wire them, but CONTEXT and CON-01 to CON-06 do not include them; the Character screen (Phase 50) owns those flows.
- **A12. Mobile rail content lives in the Map sheet**, and the party block in the Social sheet, because the approved tab mapping has no dedicated tab for routes, Nearby, quests or events. Phase 51 adds the map above the Here card.
- **A13. Local echo scope.** Intents, commands and keyword and rail actions echo `› text` locally. Talk, whisper and party chat rely on the server's echo (46 OQ5). The planner confirms the server echoes whispers and party chat; if it does not, a local echo is added in the same style.
- **A14. Whisper pre-fill form** is `whisper {name} ` (the exact command shape for a name plus message). Names containing spaces are out of scope for the exact form.
- **A15. Hotbar number keys** are ignored while any drawer or sheet is open because the hotbar is hidden beneath it.
- **A16. Keyboard compaction** on mobile and the 120px threshold are additions; the mock shows no keyboard state.
- **A17. Cooldown tick** is 250ms (1s under reduced motion) and sweeps use the client clock against server `startedAtMicros`; skew is absorbed by clamping.
