# Phase 51.3.1.2 Plan 08: Stage 2b State Machine Summary

Stage 2b now has its pieces in `helpers/world_gen.ts`, all built from stored rows:
- the 2a job carries the server's place count, and the planned family count is gone;
- the families input and start (`FILLING_FAMILIES`), and its own error state (`FAMILIES_ERROR`, never `FILL_ERROR`);
- failure lines that follow the hold: the owner's 7d line at the crossing, the section 5 line on the creation console;
- `finishRegionFill`, which opens the region with the 7c line plus the discovery line, then starts the economy after `COMPLETE`.

## What was built

**Task 1 (2a count, 2b input and start, planned count retired)**
- `buildWorldFillInput` returns `placeCount: placeCountFor(region.id)`. It no longer has `familyCount` or `feudCount`.
- `buildWorldFamiliesInput(tx, genState)`:
  - places come from `regionChartedPlaces`: the arrival point first, then by id, with the doorway left out;
  - each place gets a flag: hub before safe, otherwise ordinary;
  - it also carries `hubNames`, `dominantFaction` (missing or empty becomes undefined) and `threats` (parsed from the stored JSON);
  - `familyCount = familyCountFor(places)` and `feudCount = feudCountFor(familyCount, familySeed(regionId))`;
  - it throws a plain Error when the region or its arrival point is missing.
- `startWorldFamilies` mirrors `startWorldFill`:
  - it enqueues route `'world_gen_families'` with sourceKey `SOURCE_KEYS.worldGen(genState.id)`, the state's player and character, and request `{ genStateId, input }`;
  - a successful enqueue moves the state to FILLING_FAMILIES;
  - an input that cannot be built fails with `WORLD_FAMILIES_FAILED_MESSAGE`;
  - a resting refusal fails with `LLM_RESTING_LINE`, and any other refusal with `WORLD_FILL_REFUSED_MESSAGE`.
- `DENSITY_RULES.FILL_PLANNED_PLACES`, `askedFamilyCount` and `keptFamilyCount` were removed, along with their tests. density_rules.test.ts now asserts that they are absent.

**Task 2 (families error state, hold-aware lines)**
- `WORLD_FAMILIES_FAILED_MESSAGE = 'The land is remembered, but not yet what lives in it.'` is copied from `prompt_draft.mjs chosen` key 5, without the hint. A test pins it to the literal, checks that the message plus hint equals the chosen line, and checks that the draft contains that line.
- `failWorldFamilies` sets FAMILIES_ERROR with the message. It places no hub and changes no row; a test compares the JSON of region, location, location_connection and npc before and after.
- `postFillFailure` (private) is shared by `failWorldFill` and `failWorldFamilies`:
  - a triggering character in creation gets the creation_error Keeper segment;
  - otherwise the triggering character, wherever he is, and everyone at the crossing get `REGION_HOLD_FAILED_LINE`, or `LLM_RESTING_LINE + ' Type [explore] to try again.'` after a resting refusal;
  - each person gets the line once.
- `failWorldFill` keeps its FILL_ERROR step, its stored message, its rule hubs and its creation-console line.

**Task 3 (finishRegionFill)**
- When the state is FILLING_FAMILIES or FILLING, `finishRegionFill`:
  - sets COMPLETE and clears errorMessage;
  - posts `regionOpenedLine(region.name)` to the triggering character and the crossing, once each;
  - then posts `pickDiscoveryMessage(region.name, tx.timestamp)` to the triggering character;
  - then calls `startRegionEconomy` in a try/catch that logs `Region economy start failed for region <id>: <ErrorName>`.
- Starter states (sourceLocationId 0n) get no lines here, but the economy still starts.
- `worldFillCompleteLine` stays exported; llm_apply.ts still calls it until Plan 11.
