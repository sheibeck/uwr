# Phase 51.3.1.2 Plan 09: Live-proof and golden tooling for the families call Summary

The proof and golden scripts now count, price, label and drive the world_gen_families call. The live proof waits for the families before it treats a character as placed or travels into a new region. The worst-case bound is $1.3277, under the $1.80 stop line, and a free unit test checks it.

## What changed

**Task 1: proof and golden route lists, call counts and a free bound check**
- `proof_rules.mjs`:
  - PROOF_STEPS has `world_gen_families` right after `world_gen`.
  - PROOF_DOMAINS.world_gen is `['world_gen_start', 'world_gen', 'world_gen_families', 'explore_region']`.
  - plannedCallCounts counts `world_gen_families` 2 + 1 smoke = 3, in server route order. The run now plans 42 calls: 9 smoke and 33 domain calls.
  - New pure exports:
    - `proofPricingInput(route)`: the first sweep fixture, else `smokeInputFor(route)`; `{}` for smoke_test.
    - `proofReservationMicroUsd(route)`: one call's full reservation by the server rule. Throws on an unknown route.
    - `worstCaseMicroUsd(counts, reservationFor)` returns `{ total, lines: [{ route, calls, eachMicroUsd }] }`. A bad count or reservation throws, so the bound never silently under-counts (T-51.3.1.2-29).
- `golden_rules.mjs`: GOLDEN_SHAPE_CHANGED_ROUTES adds `world_gen_families`. GOLDEN_ROUTE_COUNTS is unchanged and pinned by a test, so no paid golden item was added.
- `golden_review.mjs`: `GROUP_LABELS` is now exported and frozen, with `world_gen_families: 'World: creature families'`.

**Task 2: prove-live.live.ts (edited, NOT run)**
- `world_gen_start`:
  - Waits for the stage-1 landing: FILLING or later, or ERROR/HELD.
  - An unplaced character is expected (D-17) and is recorded in `detailFlags.unplacedAfterStage1`.
  - It passes on a completed stage-1 job plus the existing tab-close check (one region, one state).
  - The "say during fill" action was removed: the character is still in creation at this point.
- `world_gen` (2a): settles the 2a job. It passes when the state reaches FILLING_FAMILIES, COMPLETE or FAMILIES_ERROR.
- `world_gen_families` (new step):
  - Settles the 2b job.
  - Passes only when the state is COMPLETE and the character is placed (`locationId !== 0n`).
  - `timeToPlayableMs` is now measured from the confirm to this placement.
  - FAMILIES_ERROR (or any other end state) is a failed step. Its note is the stored `errorMessage`, scrubbed and capped by `excerpt` (PROOF_EXCERPT_MAX).
- `explore_region`:
  - Settles the region's world_gen_start, world_gen and world_gen_families jobs, then travels from the crossing into the new region (D-15).
  - A `REGION_HOLD_REFUSED_LINE` (7b) seen in the private events becomes a note and the move is retried once. It never fails the step on its own.
  - Timings are recorded as stage1Ms, stage2Ms and stage2bMs.
- The dry-run bound now comes from `worstCaseMicroUsd(plannedCallCounts())`. The local pricing code and its imports (SWEEP_FIXTURES, buildRouteLayers, buildClaudeRequest, reserveCostMicroUsd, LLM_ROUTES) were removed.
- Type check: `npx vue-tsc -b` does not cover `scripts/` (tsconfig includes only `src`). A temporary tsconfig limited to the harness was run with `tsc --noEmit` against both the old and the new file. The new file has only the errors the old one already had: TS7016 "no declaration file" for the `.mjs` imports, plus one unrelated server error in combat_narration.ts. The temporary files were deleted.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking, coordinator-approved] Golden and sweep world_gen checks rejected the new 2a reply**
- **Found during:** Task 2 verification, after Plan 10's cc673146 removed `families` and `levelOffset` from REGION_FILL_SCHEMA.
- **Issue:** golden_rules.test.mjs failed 2 tests: wld-03 `structure_invalid`, and the route JSON schema check. The `WORLD_FILL` fixture still had the 51.3.1.1 shape. `structuralCheck('world_gen')` in sweep_rules.mjs also required families or enemies and capped the reply at 4 locations, so a real 2a reply in the owner's golden re-record would have failed too.
- **Fix:**
  - `WORLD_FILL` drops `families` and `levelOffset`.
  - `structuralCheck` accepts a places-only reply (no families, no enemies array) with 2..REGION_PLACES_MAX-1 places. The 51.3.1.1 families shape and the older enemies shape keep their exact checks.
  - New sweep_rules test case for the 2a shape.
  - No golden_set.mjs change was needed: wld-03's input chains from wld-01.

- **Commit:** b9f9a51a

**2. [Rule 1 - Bug] The dry-run pricing would have thrown on the new route**
- **Issue:** the harness priced each route from `SWEEP_FIXTURES[route][0]`, and no sweep fixture exists for world_gen_families.
- **Fix:** `proofPricingInput` falls back to the server's `smokeInputFor`, and the harness prices through `worstCaseMicroUsd`.
- **Commits:** adb06719, 409c22f8

**3. Signature: `worstCaseMicroUsd(counts, reservationFor)` instead of the planned `(counts, routes)`.** The plan required the harness's own rule, which also needs the request length. A function argument keeps the summation pure and testable. The default is that full rule.

**4. RED commit typo.** 32ebda5b's golden_review test had a quote syntax error (an apostrophe inside a single-quoted name). The suite therefore failed RED on a parse error instead of the missing export. adb06719 fixed the wording, and the test then passed against the export.
