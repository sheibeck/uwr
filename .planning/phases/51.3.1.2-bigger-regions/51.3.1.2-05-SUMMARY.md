# Phase 51.3.1.2 Plan 05: Region writers split (2a places, 2b families) Summary

The one-shot region writer is now two writers. `writeRegionPlaces` (stage 2a) writes 8-10 places under the server rules: place count trim, a floor of 6 that refuses before any write, the shaped edge set, the hop gradient, unchanged hubs, the host floor, and the doorway at the farthest place. `writeRegionFamilies` (stage 2b) writes 12-15 families from the real charted place count, and it refuses a malformed or empty reply without writing anything. `writeRegionFill` stays as the legacy one-reply composition of the two, so a job that was in flight at the publish still completes its region.

## What was built

- **`writeRegionPlaces`** (world_gen.ts). Steps, each commented with its D-number:
  1. Collect the usable items. Names are deduped case-insensitively, the arrival point's name is taken first, and collection stops at the most the server could keep (T-13).
  2. Call `acceptedNewPlaces`. When it says no, return `too_few` before any write.
  3. Write the region facts.
  4. Map connectsTo names to indices; a trimmed or unknown name is dropped. Then run `shapeRegionEdges` and `hopsFrom`.
  5. Insert the kept places with `levelOffsetForHops(arrival offset, hops)`. The reply's levelOffset is never read.
  6. Connect exactly the shaped edges.
  7. Run `placeRegionHubs` with `readHubMarks` over the kept rows only.
  8. Apply `hostFloorFlips` (the arrival point skipped).
  9. Write the arrival place words.
  10. Place the NPCs. One naming a trimmed or unknown place goes to the arrival point.
  11. Run `settleRegionServices`.
  12. Write the doorway at `boundaryAnchorFor` over the final rows.
- **`regionChartedPlaces`** returns the arrival point first, then the other charted places by id. The doorway is never included. Plan 08 uses it for the 2b input.
- **`writeRegionFamilies`**:
  - The count is `familyCountFor(regionChartedPlaces.length)`.
  - A missing families array returns `malformed`. An array with no usable family returns `empty` unless `ruleOnlyAllowed`. Both return before any write.
  - Otherwise it runs `completeRegionFamilies` with the seeded feud count, then `buildAiFamilies`.
- **`writeRegionFill`** (legacy, doc comment says in-flight compatibility):
  - It runs `writeRegionPlaces` with `placeCount: null`.
  - With a families array, it then runs `writeRegionFamilies` with `ruleOnlyAllowed: true`.
  - Otherwise it runs `insertReplyEnemyTemplates` plus `buildRegionFamilies` over the charted places.
  - It returns `{ locations, boundary }`.
- Removed: the `keptFamilyCount` call and import, and the now-unused private `reachableWithin`. `askedFamilyCount` stays in `buildWorldFillInput` (Plan 08); its comment now says so.
