Design choices (Claude's discretion):
- **Column default.** `npc.gender` is appended as the last column with the migration default `''`. This follows the project precedent for new columns on existing tables (`stamina` and `pendingLevels` on character use `.default(0n)`), so no publish is forced to delete data. Two things keep the default from ever showing:
  - Every insert the module performs writes a resolved value.
  - Every reader goes through `npcGender(row)`, which resolves a pre-column row deterministically.

  The local database holds zero NPC rows today, which was checked on 2026-09-30.
- **Resolution order.** A valid model value comes first, then the pronouns already written in the NPC's description and greeting (so the stored gender agrees with generated text), then an FNV-1a hash of the lowercased name.
- **Humanoid enemies.** Enemy templates are group types and get no stored gender. The Bible rule ("when the facts are silent, choose one and keep to it") governs narration. Fixed enemy strings are pronoun-free.
- **Text another player reads about a player's character** is pronoun-free, because player characters have no gender.
- **Plural "they"** (for two or more people) is not banned by PR-02. Fixed strings avoid it anyway where that is cheap.
- **Out of scope.** `data/races.ts` legacy race descriptions talk about peoples (plural, species-level), not persons, so they are untouched. The legacy `data/llm_prompts.ts` is off the Claude request path, but two of its lines (around 148 and 200: "The new arrival describes themselves as:") trip the reflexive guard, so Task 3 fixes them ("describes the character as:"); if 41-15 already deleted those prompts, there is nothing to do.

**1. Create `spacetimedb/src/data/npc_gender.ts`.** It is a pure module with no imports. Its header comment cites the user decision of 2026-09-30 (PR-02, PR-05). It exports:
- `NPC_GENDERS = ['male', 'female'] as const` and `type NpcGender`.
- `genderFromName(name)`:
  - Compute an FNV-1a 32-bit hash (offset basis 2166136261, multiply by 16777619 with Math.imul, final `>>> 0`) over the UTF-16 code units of `String(name ?? '').trim().toLowerCase()`.
  - An even hash gives 'male'; an odd hash gives 'female'.
- `inferGenderFromText(text)`:
  - Count whole-word, case-insensitive matches of he, him, his, himself against she, her, hers, herself.
  - Return the side with more matches, or null on a tie or when there are none.
- `resolveNpcGender(value, name, text?)`:
  - A string value that trims and lowercases to male or female wins.
  - Otherwise return `inferGenderFromText(text ?? '')` when it is not null.
  - Otherwise return `genderFromName(name)`.
  - It never returns anything else.
- `npcGender(row)`: `resolveNpcGender(row?.gender, row?.name ?? '', (row?.description ?? '') + ' ' + (row?.greeting ?? ''))`. This is the single reader every consumer uses. It covers rows written before the column existed, whose stored value is the migration default.
