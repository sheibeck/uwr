# Phase 46.1 Plan 05: Round engine, guarded tick and retired loop Summary

Fights now run in rounds: round 1 opens in the transaction that creates the fight, one guarded scheduled tick per fight resolves each round through `resolveRound`, and the per-second loop is gone (its table stays defined; a fight that was running at publish drains onto rounds).

## What changed

- `reducers/combat.ts`
  - `startCombatForSpawn`: writes `nextAutoAttackAt: 0n` on participants, calls `beginCombatCooldowns` per participant, and calls `startRound(ctx, combat.id, 1n)` instead of the loop schedule. `addEnemyToCombat` writes `0n` too.
  - `resolveRound(ctx, combat, round, { firedScheduledId? })` after `tickEffectsForRound`: (a) only the open `action_select` round of an active fight resolves, set to `resolving`, other pending ticks cancelled; (b) players in ascending character id, each with a stored ability choice (re-validated, `executeAbilityAction`, `setRoundCooldown`) or an auto-attack; (c) stop when no enemy lives; (d) pets once; (e) enemies in ascending id, stunned ones skip, each turn in try/catch; (f) `tickEffectsForRound`, `decrementRoundCooldowns`, `processPendingAdds`, `markNewlyDeadParticipants`, retarget; (g) fresh reads then `handleVictory` or `handleDefeat`; (h) round `resolved`, `clearRoundChoices`, `startRound(N + 1)`.
  - `resolve_round_timer`: `ctx.sender` must equal `ctx.databaseIdentity`, combat must be active, `isStaleTick` must be false.
  - `processPlayerAutoAttackForRound` and `processEnemyAutoAttackForRound` take a trailing `roundNumber`; seeds use `roundSeed`; the player target is `autoAttackTargetId` over the id-sorted living enemies. Damage formulas unchanged.
  - `tickEffectsForRound`: both every-third-tick gates removed; regen, character DoT and enemy DoT apply every round.
  - `combat_loop`: module-identity guard, then `ensureRound` for an active fight; never reschedules. The duplicate realtime ability reducer is deleted.
  - `clearCombatArtifacts`: leftover round cooldowns go through `endCombatCooldowns`, the fight's `combat_moment` rows are deleted, ticks go through `cancelRoundTicks`; loops collect rows before deleting.
  - Marker comment is now `// ── Round-Based Combat Functions ──` directly after `handleDefeat`; exactly two outro enqueue calls remain; no new `clearCombatArtifacts(ctx, combat.id)` call before `handleVictory`.
- `helpers/combat_fight_fixture.ts` (TEST-ONLY): `T0`, `MODULE`, `ALICE`, `BOB`, `fightSeed`, `fightCtx`, `rows`, `openTickArg`, plus `startSeed` (a fight-less seed for `start_combat`).
- Tests: 31 in `combat_rounds.integration.test.ts` and 5 in `combat_round_clock.invariant.test.ts`.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Missing critical] Round cooldown re-check at resolution**
- **Found during:** Task 1
- **Issue:** `executeAbility` does not check cooldowns; a choice made before a cooldown started (or a forged row) would run an ability that is still blocked.
- **Fix:** `resolveAbilityChoice` refuses an ability with `roundCooldownRemaining > 0n` with an `Ability failed: <name> is on cooldown` line and falls back to the auto-attack. Test added.
- **Commit:** 385ffb18

**2. [Rule 1 - Bug] clearCombatArtifacts iterated a live table while deleting**
- **Found during:** Task 2
- **Issue:** the old tick-delete loops deleted while iterating `iter()`, which skips rows under the mock db.
- **Fix:** collect ids first (round ticks now through `cancelRoundTicks`); same for choices, rounds and moments.
- **Commit:** 36501304

**3. [Rule 2 - Missing critical] Live wall-clock cooldowns on a migrated fight**
- **Found during:** Task 2
- **Issue:** a fight that was running at publish had no `beginCombatCooldowns` call, so its live wall-clock cooldowns would not have been enforced as rounds.
- **Fix:** `combat_loop` calls `beginCombatCooldowns` for each participant once, only when the fight has no round rows at all, then `ensureRound`.
- **Commit:** 36501304

**4. Task order detail (not a rule deviation).** To keep Task 1 green, the old `combat_loop` body stayed for one commit with its two auto-attack calls passing `0n`; Task 2 replaced it. Task 2's tests were committed with its code rather than as a separate failing commit.

No non-strict mock was needed: every test in both new files uses `createMockCtx({ strict: true })` through `fightCtx`.

## Notes for later plans

- The mock never deletes a fired scheduled row (the platform does). Tests use a `fire` helper that removes it; `openTickArg` returns the last pending tick for the fight.
- `clearCombatArtifacts` still deletes the currently firing tick as part of a fight end (as the old loop's did); the platform's own deletion afterwards is a no-op.
- Pets (`processPetCombat`), pending adds and enemy ability cooldowns are still micros-based inside resolveRound; 46.1-07 converts them and extends the invariant test file.
- 46.1-06 adds the early path: it must call `resolveRound(ctx, combat, round)` (which cancels the pending tick) and the `flee` branch inside step (b). Step (g) already treats an empty participant list as defeat.
- `scheduleCombatTick` is still imported and destructured in `reducers/combat.ts` and `index.ts` (no calls); 46.1-08 removes it. The generated client bindings still list `use_ability_realtime` until 46.1-09 regenerates them; no client code calls it.
- `tryEnemyAbilityForRound` still rolls with `nowMicros`; with no enemy abilities (the fixture) it returns false before the roll, so the invariant test is not affected.
