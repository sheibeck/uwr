<domain>
## Phase Boundary

Backend only. Combat resolves in rounds of at most 10 seconds. A round ends early once every living player in the fight has chosen an action, and a player with no choice auto-attacks. Actions resolve in a deterministic order. Cooldowns, effects, DoTs/HoTs and enemy abilities count in rounds. Round state goes in public tables, and the client bindings are regenerated. The Keeper narrates big moments and the end of the fight as Phase 46 speaker segments, within a per-encounter budget. Requirements: RND-01 to RND-05.

Out of scope:
- The combat UI: round headers, the countdown on the hotbar, chosen-action display (Phase 48: CMB-04, CMB-06).
- Any client change beyond regenerated bindings.

This reverses the v2.0 "real-time combat" decision.

<decisions>
## Implementation Decisions

### Round flow (RND-01, RND-02)
- A round lasts at most 10 seconds. It resolves either when the deadline passes or as soon as every living player participant has chosen an action. A solo player who acts at once resolves the round immediately; there is no waiting out the timer.
- A player chooses through the existing `use_ability` reducer. While the player is in combat, the reducer records the choice for the current round instead of executing at once. Choosing again replaces the previous choice until the round resolves. The Phase 47 hotbar already calls `use_ability`, so it becomes the round-choice input with no client change.
- A player with no choice when the round resolves auto-attacks their current target. With no valid target, they attack the living enemy with the lowest id.
- Disconnected or AFK players are never waited on beyond the 10-second deadline, and they auto-attack under the same rule.

### Resolution order and timing (RND-03)
- The order is deterministic. Player actions resolve in ascending character id, then enemy actions in ascending enemy id. Dead actors skip.
- In combat, cooldowns, effects and DoT/HoT count in rounds.
  - Rounds = ceil(seconds ÷ 4), with a minimum of 1. This reuses the existing `EFFECT_ROUND_CONVERSION_MICROS` (4s) constant.
  - Effects and DoT/HoT tick once at the end of each round.
  - Out of combat, the real-time ability cooldowns are unchanged.
- An enemy ability with a cast or wind-up time is announced in round N and lands at the end of round N + ceil(castSeconds ÷ 4), with a minimum of 1 round.
- Once rounds work, the real-time swing scheduling (weapon-speed swing timers, per-second `combat_loop` resolution) is removed, together with any code it leaves dead.
  - The v2.0 round experiment (commits `8a94bf47` and `74137f46`, reverted in quick-348) is a code reference.
  - `ROUND_TIMER_MICROS` and `SOLO_TIMER_MICROS` (30s) become 10s.

### Public round state (RND-04)
- Add two public tables:
  - `combat_round`: combat id, round number, deadline timestamp, status.
  - `combat_round_choice`: combat id, character id, chosen ability template id or none for auto-attack, chosen-at timestamp.
- Both are keyed for lookup by combat id, so party members can see each other's choices for coordination.
- Schema changes are additive, so a local publish with `--break-clients` needs no `--clear-database`. If a non-additive change ever turns out to be needed, STOP and ask the owner, because clearing wipes the stored Anthropic key.
- Regenerate the client bindings. The Phase 47 client keeps working outside combat. Combat display is Phase 48.

### Narration (RND-05)
- Big-moment triggers:
  - the first kill of the fight, plus any boss or named-enemy kill
  - a player's first drop below 20% HP in this fight (once per player per fight)
  - a boss or named enemy crossing 50% HP (the phase change)
- The end of the fight (victory or defeat) is also narrated. There is no fixed every-N-rounds summary.
- Per-encounter budget: at most 3 big-moment narrations plus 1 end narration per fight. The existing global narration budget threshold (`NARRATION_BUDGET_THRESHOLD`) still applies, so a refused enqueue is skipped silently, as today.
- Rounds never wait for narration. Narration lands in the feed when ready, tagged with its round number. The existing stale-narration age cut-off stays.
- Voice:
  - Reuse the Phase 46 owner-approved `combat_narration` JSON route, `COMBAT_NARRATION_SCHEMA` and combat route block, with no route-block or Bible change.
  - The per-call user text gains the moment type (`kill`, `near_death`, `phase`, `victory`, `defeat`) and its facts.
  - Collect any new per-call wording in a short `46.1-VOICE-ADDENDUM.md` for the owner's later review. It was auto-approved overnight, and the owner can revise it at the end-of-milestone pass.
- No paid LLM calls in this phase.

### Decisions after research (2026-10-06, auto-approved under the owner's overnight instruction)
- **Tables.**
  - Reuse the existing round tables that survived the quick-348 revert:
    - `combat_round` holds the round number, deadline and state.
    - `combat_action` holds each player's chosen action per round, which fulfils the "choice" table in RND-04.
    - The scheduled `round_timer_tick`, keyed by `scheduledId`, drives the round timer.
  - Do not add a table named `combat_round_choice`.
  - Every schema change must be additive:
    - A new column on a persisted table gets a `.default(...)` and goes last.
    - Never remove or modify a column.
    - Keep the `combat_loop_tick` table defined even if it is unused, so no table is dropped and no pre-publish emptiness check is needed.
    - Legacy columns such as `nextAutoAttackAt` stay and are written as `0n`.
- **Cooldown meaning.** An ability with an in-combat cooldown of C rounds that is used in round N can be chosen again from round N + C. With C = 1 it can be chosen every round.
  - The cooldown is stored on the same `ability_cooldown` row in a new defaulted `roundsRemaining` column.
  - The wall-clock fields stay populated as a client estimate, so the Phase 47 hotbar stays truthful.
- **Explicit choice reducer.** Add `submit_combat_action` so a player can choose a plain auto-attack (or "ready") and the round can resolve early without waiting out the 10 seconds. `use_ability` in combat records an ability choice through the same path.
- **Flee.** Flee is a round choice that resolves at round resolution under the existing flee rules. This fixes the pre-existing `fleeing` status that nothing resolves. If the existing rules cannot be found, flee succeeds at round end.
- **Scheduled-reducer guard.** The round tick reducer is guarded with `ctx.sender` against `ctx.databaseIdentity` (the `llm_run` pattern) and checks for a stale tick by round number and state. Add the same guard to `combat_loop` and `resolve_pull` if they are touched.
- **Target validation.** In combat, `use_ability` and `submit_combat_action` accept a `targetCharacterId` only when it names a participant in the same fight. This fixes a pre-existing hole where a stranger could be healed or buffed.
- **Fix in scope.** The existing round mechanics must work, so these pre-existing bugs are fixed:
  - Enemy stun stores an expiry time with `roundsRemaining: 0`, so it never takes effect. It becomes a real round count.
  - DoT and HoT fire only when `roundsRemaining % 3 === 0`. They tick every round instead.
- **Boss and named detection.** Detection uses `isBoss` or an existing named-enemy marker if one exists. No new world logic sets `isBoss`. Until something does, boss and phase moments fire rarely, which is acceptable. Record this in the summary.
- **Budget constants.** The unused `NARRATION_BUDGET_THRESHOLD` and `MAX_COMBAT_NARRATIONS` constants can be wired to the per-encounter cap (3 big moments + 1 end) or removed. The real global budget is the budget refusal in `enqueueLlmJob`.
- **Balance.** Weapon speed no longer drives timing, and resource regen stays wall-clock. Accept this for now and tune balance in the end-of-milestone playtest.
- **Voice addendum.** The per-call moment strings (research M1-M8) go into `46.1-VOICE-ADDENDUM.md`, marked "auto-approved overnight, owner to review". The route block and the Bible do not change.
