# Phase 46.1 Plan 04: Round state service and effect durations in rounds Summary

The database side of rounds now has one owner (`combat_round_state.ts`: rounds, one tick per fight, choices, round cooldowns and their conversion at the fight boundary), and every effect duration plus the enemy stun counts in rounds.

## What changed

- `combat_round_state.ts` (new): `roundsForCombat`, `currentRound`, `scheduleRoundTick`, `cancelRoundTicks`, `startRound`, `ensureRound`, `upsertChoice`, `choicesForRound`, `clearRoundChoices`, `waitingCharacterIds`, `allWaitingChosen`, `roundCooldownRemaining`, `setRoundCooldown`, `decrementRoundCooldowns`, `beginCombatCooldowns`, `endCombatCooldowns`. Imports only `spacetimedb` (`ScheduleAt`) and `combat_rounds`; no server SDK, no events.
- `helpers/combat.ts`: `secondsToRounds(ability.effectDuration ?? <same default>)` at all 12 reads (dot, hot, buff, debuff, shield, cc, song/aura, fear, potion/bandage buff, travel, craft/gather boost, food summon); pet bleed passes `secondsToRounds(3n)` (1 round); the stun branch of `addEnemyEffect` stores `magnitude: 1n`, `roundsRemaining: rounds`, keeping the larger value on re-apply. `reducers/combat.ts` already read stun by `roundsRemaining > 0n` and counted it down, so the stun now works end to end.
- `combat_perks.ts`: both buff durations use `secondsToRounds(BigInt(buffDuration))` (was `ceil(seconds / 3)`); player-facing "for Ns" text kept.
- Removed `convertDurationToRounds`, `scheduleRoundTimer`, `createFirstRound` (helpers/combat.ts), their import names in `index.ts`, the constants import block they used, and `SOLO_TIMER_MICROS`.
