# Phase 48 — UI Design Contract

> Visual and interaction contract for Phase 48: Combat Encounter. Generated by gsd-ui-researcher, to be verified by gsd-ui-checker.
>
> This contract **extends** `45-UI-SPEC.md` and `47-UI-SPEC.md` (both approved, including 47's "Owner try-out changes": the desktop feed fills the center column and every scrollable surface uses the dark scrollbar rule). Tokens, the 10/12/14/20 type scale, the 400/500 weights, the 4/8/16/24/32/48/64 spacing scale, the 900px breakpoint, the frame measurements (header 48, rails 252 and 288, tab bar 64) and the drawer and sheet rules all apply unchanged. Where this file adds a value it says so. Where it maps a mock value onto the scale it records the mapping. Where it replaces a 45 or 47 line it says so under "Supersedes".
>
> Design source (imported fresh 2026-10-06 from the claude_design project "Unwritten Realms", never cached): Console & Combat 1c "Ledger · combat" (desktop 1280x800 and mobile 390x844), Ledger 2j "Console · combat" (identical content to 1c), Nocturne `_ds/styles.css` and `_ds/readme.md`. 1a and 2i were read for the exploring baseline already contracted in 47. 1d (Folio direction) was not used. The design files contained no text addressed to the assistant; nothing was ignored.
>
> Phase 48 fills five existing surfaces and adds one: `ContextRail` (becomes the Encounter panel), `FeedView` (round headers, wind-up warning block, late-narration tag), `HotbarRow` (round row, chosen slot, rounds cooldowns), `VitalsRail` and `VitalsStrip` (damage flash, ally targeting, In combat tag on mobile), `HeaderBar` (In combat tag, disabled screens), plus a new mobile **encounter strip** and **encounter sheet**. The server adds one public per-sender view of the threat order (see "Data the UI reads").

## Color

60/30/10 as in 45 and 47. Dominant `var(--color-bg)` (feed, composer ground), secondary `var(--color-surface)` (rails at 30%, hostile cards, warning block, slots), accent `var(--color-accent)`.

### Difficulty colors (CMB-01, level-difference rule from the old client, `v2.2-client` `useCombat.ts`)

`diff = enemyLevel - playerLevel`, enemy level from `enemy_template.level` through `combat_enemy.enemyTemplateId`, player level from the active character. Missing template: treat as `diff = 0`.

| diff | Token (hostile name text) | Meaning, used in `title` and `aria-label` |
|------|---------------------------|-------------------------------------------|
| <= -5 | `--color-con-gray` | Trivial |
| -4 to -2 | `--color-con-light-green` | Easy |
| -1 | `--color-con-blue` | Slightly easy |
| 0 | `--color-con-white` | Even match |
| 1 | `--color-con-yellow` | Tough |
| 2 | `--color-con-orange` | Hard |
| >= 3 | `--color-con-red` | Deadly |

Color is never the only cue: `Lv N` is always visible next to the name and the `aria-label` carries the meaning word.

## Round Contract (CMB-04, CMB-06)

### Data used

`combat_round` for the open round (`state = 'action_select'`): `roundNumber`, `timerExpiresAtMicros`, `startedAtMicros`. `combat_action` rows where `characterId` is the active character and `roundNumber` is the open round: the player's current choice. `character.combatTargetEnemyId`: the current target. The Phase 47 server clock skew converts `timerExpiresAtMicros` to client time.

### Timer

- Remaining = `timerExpiresAtMicros - serverNow`, clamped at 0. Seconds shown = `ceil(remaining / 1s)`, so `10s` at the start, `1s` at the end, never `0s`. Bar fill = `remaining / (timerExpiresAtMicros - startedAtMicros)`, clamped 0 to 1.
- One shared 250ms tick (1s under reduced motion, matching the 47 cooldown ticker). The bar width has a 250ms linear transition; under `prefers-reduced-motion` there is none and the width steps once per second.
- At 0, or whenever no `action_select` row exists yet for the fight: the bar is empty and the seconds cell is replaced by `PhCircleNotch` 14px (accent, 1s linear rotation, static under reduced motion) and `Resolving…` (Label 12, `--color-neutral-300`). It stays until the next round row arrives. The cell is `role="status"`.
- While resolving, ability slots, Ready and Flee are inert (`aria-disabled`, 45% opacity), and number keys are ignored.

### Choice chip (the player's current choice)

Derived only from the `combat_action` row. No optimistic state (CLAUDE.md: let subscriptions drive state); a click that has not echoed yet shows the 47 pressed state on the slot.

| State | Chip | Visual |
|-------|------|--------|
| No row, a living target exists | `Auto-attack → {target}` | `.tag .tag-neutral`, `PhSword` 12px; follows the current target live |
| No row, no living hostile | `Auto-attack` | same, no arrow part |
| `auto_attack` row (Ready pressed) | `Auto-attack → {target}` | `.tag .tag-accent`, `PhCheck` 12px |
| `ability` row | `{Ability} → {target}` or `{Ability}` when it names no target | `.tag .tag-accent`, the ability's 47 kind icon 12px. Target is the ally's name (`you` for the player) when the row has `targetCharacterId` and the ability is an ally kind, else the enemy's name from `targetEnemyId` |
| `flee` row | `Fleeing` | health tint, `PhPersonSimpleRun` 12px |
| Player HP 0 | `You are down` | `.tag .tag-neutral`; slots, Ready, Flee inert |

The chip's text is a text node. `→` (U+2192) is a text character in the copy, like the 47 echo `›`, not an icon.

### Ready and Flee

- **Ready** records an auto-attack: `submit_combat_action({ characterId, targetEnemyId: current target })` with no ability. It is disabled (`aria-disabled`, 45% opacity) while any `combat_action` row exists for the player and the round (the choice is already in; click a different slot or Flee to replace it), while resolving, while the player is down and while disconnected. Once the server has every active player's choice it resolves the round at once (46.1), so solo play shows `Resolving…` almost immediately.
- **Flee** calls `flee_combat({ characterId })`. Once the `flee` row exists the button reads `Flee chosen` (health tint, `aria-pressed="true"`, `PhCheck` replaces the runner icon); clicking it again does nothing. Choosing an ability replaces the flee row (the engine updates the choice in place) and the button reverts to `Flee`. No confirmation dialog (A3 reasoning: the choice is replaceable until the round ends and the engine may fail the attempt). Disabled while resolving, down or disconnected.

### Chosen slot (hotbar)

The slot whose `abilityTemplateId` matches the player's `ability` row for the open round shows the **chosen** state: inset 1px accent ring, `0 0 12px` accent 35% glow, background the 16% accent tint, `aria-pressed="true"`, `aria-label` adds `, chosen`. It clears when the next round opens or when another choice replaces it. It composes with Hover and Focus-visible.

### Rounds on cooldowns and effects (CMB-06)

- **Hotbar cooldown in combat** (character has an active participant row): the slot is cooling when `ability_cooldown.roundsRemaining > 0`; wall-clock fields are ignored for abilities while in combat. Visual: the 47 conic sweep overlay with `--cd` = `roundsRemaining / totalRounds`, where `totalRounds = max(roundsRemaining, round(durationMicros / 10s))` (the server's estimate field; the sweep steps once per round, it does not run continuously). Text: `{n} rounds` (`1 round`), centered over the slot (Micro 10 / 500 `--color-neutral-200`, tabular-nums; the 47 top-right seconds position would collide with the key number at this length). Icon and name drop to `--color-neutral-600`. `aria-disabled`, `aria-label` adds `, ready in {n} rounds`. Click and key ignored. Item-bound slots (potion, bandage) keep the 47 wall-clock seconds display because the round engine does not model item cooldowns.
- **Out of combat**: unchanged 47 wall-clock display.
- **Effect chips** (vitals rail and strip): already `{n} rounds` since 47 (47 A3). Phase 48 changes nothing; they keep ticking down as the server decrements `roundsRemaining` (A13).

## Feed Contract (CMB-04)

### Round headers

- A header is a `div` (not a heading) in the log: Micro 10 uppercase `letter-spacing: 0.1em`, text `Round {N}`, flanked by two 1px rules (`linear-gradient(to left, <rule color>, transparent)` left, `to right` right), label gap 16 (mobile 8). Margin `8px 0 0` on top of the 8px line gap (mobile `4px 0 0`). Colors per Color: the header of the **open** round is accent; every other header is neutral. When the fight ends, all headers of that fight are neutral.
- Placement per the 46.1 contract: an event with `createdAt` t belongs to round N when `startedAtMicros(N) < t <= startedAtMicros(N+1)`; events at or before round 1's `startedAtMicros` are the fight's opening lines and sit **before** the `Round 1` header. The header for round N is inserted at the boundary the moment the round row is first seen, even before any event lands under it.
- The client keeps every boundary it has seen for the fight in memory, because `combat_round` rows are deleted when the fight ends. A line already in the feed never moves when the rows disappear. After a reconnect, a boundary the client never saw is not invented; lines fall under the headers it has.
- A new fight restarts at `Round 1` with its own headers. The 300-line cap applies to headers too (they are lines of kind `round`, deduped by (combat id, round number)).
- Mobile keeps the same header, compact (see margins above), so a round costs one 16px line.

### Combat lines

Kinds `combat`, `damage`, `heal`, `ability`, `buff`, `debuff`, `combat_prompt`, `combat_status`: Body 14 / 400 `--color-neutral-300`, one line each, no label, no block. In a `damage` line the last standalone integer is wrapped in a span (weight 500, `--color-con-red`); in a `heal` line the same with `--color-con-light-green`. No integer, no span. Text stays a text node (no `v-html`). Ability names are not highlighted (no server markup exists, A10). `combat_narration` stays Keeper narration (47). Echo and system lines are unchanged.

### Wind-up warning block (CMB-03, feed half)

When a `combat_enemy_cast` row is **inserted** while the client is subscribed, one block is appended to the feed (not on the initial load of an existing fight; the rail row already shows it). Block: flex, align center, gap 8, padding `8px 16px`, `--radius-md`, background `var(--color-surface)`, text Body 14 `--color-neutral-200`, leading `PhWarning` 16px `--color-con-orange`, the ability name inside the text as a 500 weight `--color-text` span. Text: `{enemy} winds up {ability} → {target} · lands in {N} rounds` (same copy and the same N rule as the rail row, N taken at announcement). One block per cast row id. It sits under the round it arrives in. The server's own `{enemy} begins to cast {ability}.` line also appears as an ordinary combat line next to it; the client does not suppress it (A15).

### Late narration tag

A `combat_narration` Keeper block whose narrated round differs from the round of the header it landed under gets one extra tag in its label row: `The Keeper` (47 label) followed by ` · Round {M}` in the same Micro 10 uppercase style, `--color-neutral-500`, where M is the round it narrates (`combat_narrative.roundNumber`, or the round of the request that produced it). The block is **not** moved; it shows where it lands (CONTEXT). Same round, or no round known: no tag. `aria-label` on the label row reads `The Keeper, about round {M}`.

## Party, Flee and Vitals (CMB-05)

### Header

- `HeaderBar` gets an `inCombat` flag. After the location, in the 45 order position between location and time of day: `.tag` (Label 12, gap 4) with the 6px dot and `In combat · Round {N}`, health tint. No animation.
- While `inCombat`, the six screen buttons (Map, Bag, Stats, Craft, Social, Events) are disabled: 45% opacity, `aria-disabled="true"`, `title="Unavailable in combat"`, click ignored, still focusable. Any open drawer or sheet closes when combat starts. The account button stays enabled. The Level up and New skill tags (display-only) stay.

### Ally targeting

- Selected ally: client state `allyTargetCharacterId`, default the player. It is sent as `targetCharacterId` on the next ability choice (`use_ability` / `submit_combat_action`); abilities that take no ally ignore it (CONTEXT).
- Desktop: the Party block in combat shows header `Party · {n}` (47 `h6`) left and Micro 10 `--color-neutral-500` `Click to target` right (the `Invite` button is hidden in combat). Cards become `button`s with `aria-pressed`. A `You` card comes first (name `You`, own HP text, same bars) so the player can re-select themself. Card visuals are the 47 card plus: HP text `{hp}/{max}` (Label 12, `--color-neutral-400`, tabular-nums) replacing `Lv N` on the right; the selected card has the ring (inset 1px accent plus 12px glow); hover 7% overlay, pressed 14%. `aria-label="Target {name} with your next ability"`.
- Mobile: the strip chips described in the mobile layout.
- The selection resets to the player when the ally leaves the fight, when the party changes so the ally is gone, and when the fight ends. A selected ally at 0 HP stays selectable (resurrection abilities).
- Not in a party: nothing to select, the 47 `Not in a party.` line shows.

### Damage flash

- Applies to the active character's HP bar in `VitalsRail` and the HP bar in `VitalsStrip` whenever HP drops between two consecutive row updates (not on first load and not on a character switch).
- Motion version (default): (a) a ghost chunk covers the lost portion of the track in the ghost color and fades to transparent over 600ms ease-out; (b) the fill and the value text go from `var(--color-con-red)` to their normal color over 400ms ease-out; (c) a delta `−{n}` (Label 12 desktop, Micro 10 mobile strip, `--color-con-red`, tabular-nums) appears after the HP value and is removed 1500ms after the last drop. Drops within that window add up in the delta.
- Reduced motion (`prefers-reduced-motion: reduce`): no animation and no transition at all. For 600ms the fill and value text are `var(--color-con-red)` (a class toggled by a timer), the ghost chunk is shown at its starting color for the same 600ms, then everything reverts instantly. The delta shows for the same 1500ms.
- Healing and regeneration never flash. Party members' bars do not flash (CONTEXT scopes it to the player).

## Assumptions (decided here, not asked)

- **A1. Ready and Flee live in the round row, not on the slot row.** CONTEXT says Flee sits "at the end of the hotbar". A 52px slot-style Flee button at the end of the slot strip would push the tenth slot off screen at 1280 (47 A1 fits ten slots with 8px spare). The round row is part of the hotbar block and Flee is at its end, so the slot strip keeps all ten slots. Mobile follows CONTEXT ("the mobile hotbar row carries the round timer, Ready and Flee") with the same row above the slots.
- **A2. Ready is disabled once any choice row exists.** The engine treats a chosen ability as the player's choice, so Ready only means "auto-attack now". Choosing a different slot or Flee replaces it. There is no "back to auto-attack" after picking an ability; if that proves wanted, Ready can stay enabled after an ability choice.
- **A3. Flee needs no confirmation and the chip says `Fleeing`.** The button carries the `Flee chosen` copy CONTEXT asks for; the chip uses `Fleeing` so the same phrase does not appear twice.
- **A4. Tab hijack is scoped for accessibility.** CONTEXT: Tab cycles targets only when no input is focused and no drawer or sheet is open. A page-wide hijack would trap keyboard users, so it applies only with focus on the body, the Encounter panel or the feed; header buttons, hotbar slots, Ready, Flee and the input keep native Tab. Esc in the input blurs it, which re-enables cycling.
- **A5. Mobile combat hides the tab bar and the location row.** The mock's mobile combat frame has neither, and the vertical budget at 844 needs the space (about 360px of feed instead of about 296). Sheets other than the encounter sheet are unreachable on mobile during a fight. On desktop the six header screen buttons are disabled instead (45 A12, mock 1c). An open drawer or sheet closes when combat starts.
- **A6. The encounter strip sits above the feed** (CONTEXT). The mock draws the hostile list between the feed and the composer. CONTEXT wins; the strip is kept short (header 44 plus one chip row 44) so the feed stays readable.
- **A7. A `You` card and `You` chip are added in combat.** 47 lists only other members, but the default ally target is the player and a selected ally needs a way back. Out of combat nothing changes. The mock selects an ally with a ring and shows no self card; the ring recipe is taken from it.
- **A8. Threat percent is relative to the top entry** (top row = 100%). The mock's 88/71/40 has no 100% row and no stated basis; the server value is raw. The owner can change the basis at UAT; only the percent computation changes.
- **A9. Enemy effect chips are not drawn.** The mock shows `HEX OF ROT 2r`, `ACID DRIP 6s`, `ATTACHED · VEX` on hostile cards. CONTEXT defers enemy DoT, HoT and debuff indicators (backlog 999.1). The party cards' effect text (`Taunting`, `Bleeding 3r`) is also not drawn: no per-member effect source is in the subscribed set.
- **A10. Damage and heal amounts are emphasised by parsing the last integer.** The mock colors ability names, amounts and effect words, which needs server markup that does not exist (and the client must not interpret markup). Only the last standalone integer in `damage` and `heal` kinds is colored; ability names are not.
- **A11. No new token.** The mock's `oklch()` literals (In combat tag, boss tag, dark enemy HP fill, wind-up amber, delta red) are all derived with `color-mix` from `--color-health`, `--color-con-orange`, `--color-con-red`, `--color-surface` and `--color-text`. `tokens.client.test.ts` stays at 23.
- **A12. Rounds cooldown is centered text and a stepped sweep.** The key number occupies the slot's top-left and `2 rounds` is too wide for the 47 top-right position. The sweep fraction uses the server's `durationMicros` estimate and steps once per round.
- **A13. Effect chips are not changed.** CONTEXT says effect chips show `N rounds` instead of seconds, but 47 (A3) already shows rounds because `my_character_effects` carries only `roundsRemaining`. Phase 48 leaves them as is. The 47 checker note (hide the time out of combat) is not applied: out-of-combat buffs only count down in fights (46.1), so `5 rounds` stays true and useful.
- **A14. Mock sizes and spacing** are normalized as recorded in the Typography and Spacing tables. The mock's 0.14em header tracking becomes 0.1em to match the 47 overline treatment.
- **A15.
