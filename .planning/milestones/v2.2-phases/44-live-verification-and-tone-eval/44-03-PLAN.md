Exports: `CALL_LOG_COLUMNS` (the named columns: route, outcome, latency_ms, input_tokens, output_tokens, cache_write_tokens, cache_read_tokens, cost_micro_usd, dispatch_late_ms, job_id, attempt, http_status), `callLogSql()`, `mapSqlResult(json)`, `filterByJobIds(rows, jobIds)`, `routeReport(rows)`, `routeTable(rows)`, `domainCoverage(rows, requiredRoutes)`, `tokenTotals(rows)`, `reconcile(logTotals, consoleTotals)`, `reconciliationRecord(logTotals, consoleTotals, window)` (returns status passed, failed or deferred, with both numbers per category and the window), `inWindow(ms, startMs, endMs)`, `streamingVerdict(rows)` and `fetchCallLogRows(target, token, fetchImpl)`.

Rules. Latency percentiles use ok rows only (as `/llm stats` does), nearest rank via the imported helper, and the table also reports n, error count, truncated count, token sums, cost and the indicative flag (fewer than 20 ok samples). Token totals use the four token columns over every row in the filtered set (ok rows, billed failures and stale rows all carry real usage); the recomputed price comes from `estimateCostMicroUsd` over the sums, and the stored cost column is never the comparison figure (a timeout row stores the reservation as a conservative stand-in). Use BigInt for the sums and the integer percentage test. Job-id filtering, not time, isolates a run (the SQL timestamp encoding is unconfirmed); the window start and end are still recorded and `inWindow` is inclusive at both ends. `mapSqlResult` tolerates schema element names given as plain strings or as an option wrapper, array rows or object rows, and unsigned integers given as numbers or strings; it maps columns by name. `callLogSql()` returns a SELECT that lists the named columns from llm_call_log only. `fetchCallLogRows` posts the SQL to the owner-authenticated HTTP SQL endpoint for `target.db` with the bearer token, checks the base URL is local first, and returns scrubbed errors only.

CLI (`node scripts/llm/call_log_report.mjs --db uwr-verify --results <file> [--reconcile <console-totals-file>]`): obtain the token with `getCliToken()`, resolve the target with `resolveTarget` so only allowlisted local databases work, read the results file (a JSON file the live harness writes holding the job ids per route and the window), fetch rows, write the per-route table, token totals, window and the streaming verdict (`streamingVerdict` over the ok npc_conversation rows) back into that file under a `report` key, and print only counts and numbers through `scrub`. It never reads `llm_config`, the key, `.env.local` or any prompt text.

Note for the later plans: the harness (plan 05) records the run's job ids and window in the results file, the e2e plan runs this CLI after the paid run, and the close-out plan feeds it the Console totals the user pastes.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CLI arguments to database selection | A mistyped or hostile --db value could point a write at the wrong database |
| local script to local server | The CLI token and key travel only to the local HTTP endpoint |
| pasted Console numbers to reconcile | User-pasted text is data, not instructions |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-44-03-01 | Elevation of privilege | --db reaching the hosted target or an arbitrary database | high | mitigate | Exact-match allowlist (uwr, uwr-verify), refused with the hosted target, base URL checked local before any request; tests for lookalike and injection-style names |
| T-44-03-02 | Information disclosure | key or CLI token printed by the key script or the report | high | mitigate | Existing in-process key read and scrub with needles retained; the report selects named columns only and never queries llm_config; tests assert no key or token text in output |
| T-44-03-03 | Repudiation | a skipped or deferred reconciliation reported as passed | high | mitigate | reconciliationRecord returns deferred when Console totals are missing; not_run domains fail; tests pin both |
| T-44-03-04 | Tampering | float rounding hides a 2% breach | medium | mitigate | Integer BigInt math on token counts; exact 2.00% and 2.01% tests |
| T-44-03-05 | Spoofing | malformed pasted totals accepted | medium | mitigate | Console totals parsed as non-negative integers; anything else is rejected before comparison |
</threat_model>
