# Quick Task 261006-gy6: Quest turn-in follow-ups (inventory space, level-ups, NPC memory, starter name clash)

Follow-up to 261006-g12. Both turn-in paths (`turn_in_quest` in `spacetimedb/src/reducers/quests.ts` and the "turn in <quest>" branch of `submit_intent` in `spacetimedb/src/reducers/intent.ts`) move onto one shared helper, `turnInCompletedQuest`, so they behave identically. Reward formula unchanged (gear budget redesign is backlog 999.12). No schema change, no publish.

## Task 1: Shared turn-in helper + inventory space check

- New exported `turnInCompletedQuest(ctx, character, qi, qt, appendPrivateEvent, fail)` in `quests.ts`: everything after validation (present line, XP, gold, item, affinity, NPC memory, quest removal).
- Before anything is applied: an item-reward quest (rewardType 'item' with a rewardItemName) needs one free bag slot (`getInventorySlotCount < MAX_INVENTORY_SLOTS`, the take_loot rule for a non-stackable item). Full bags: `fail()` with an in-voice line naming the giver, return without changes, quest stays turn-in-able.

## Task 2: Quest XP through awardXp

- `awardQuestXp`: `awardXp(ctx, character, character.level, xp)` (level diff 0 -> 100% modifier, so the promised amount is unchanged) so pendingLevels rises when a threshold is crossed; level-up messaging as combat (`You can advance to level N! Click [Level Up] when ready.` / pending-levels variant). At MAX_LEVEL awardXp grants 0, so the helper adds the promised XP directly there (keeps the promised amount; no level-up possible).

## Task 3: NPC memory on the intent path

- The shared helper calls `recordQuestCompletion` for both paths.

## Task 4: Starter item name clash

- `grantQuestItemReward` never creates a template whose name (case-insensitive) matches an existing item_template: on a clash the reward is named "<Giver>'s <name>" (numeric suffix if that clashes too). Starter templates exist from init, so the starter upsert-by-name can no longer land on a reward row and starter/crafting name lookups never return a reward.

## Task 5 (small, found while sharing): location gate

- `turn_in_quest` let a direct reducer call turn in away from the quest giver; the intent path checked. The location check moves into the shared helper.

## Tests (`spacetimedb/src/reducers/quest_turn_in.test.ts`)

Real `turn_in_quest` and `submit_intent` handlers on the strict mock db, both paths: full bags refuse with no side effects (xp, gold, affinity, memory, quest row, item rows) and a later turn-in succeeds; xp crossing a threshold raises pendingLevels with the [Level Up] message and the promised amount; max level keeps the promised xp; NPC memory records the quest; a reward named like a starter item does not touch the starter row and survives `ensureStarterItemTemplates`. Each test checked to fail without its fix.
