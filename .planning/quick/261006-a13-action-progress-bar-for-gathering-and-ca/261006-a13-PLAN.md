<objective>
Add an "action in progress" row to the new client: while the player gathers or casts out of combat, a compact row directly above the hotbar shows what they are doing, a progress bar, and the seconds left (owner feedback 2026-10-06: "we should have some sort of rail showing that you are taking an action, and bar that shows how much time is left").

Purpose: gathering (and out-of-combat casting) currently gives no visible sign that an action is running or how long it will take.

Output: a pure progress module, a composable with first-seen tracking and one shared ticker, two per-character subscriptions (resource_gather, character_cast), the ActionRow component mounted in the composer, and unit tests for all of it.

Client only. No server change, no binding regeneration, no new tokens (the token pin stays at 23). Never publish, push, clear the database, or start, stop or touch the running SpacetimeDB or Vite servers.

Facts established during planning (the executor does not need to re-derive them):
- Neither resource_gather nor character_cast is bound in src/game/gameData.ts today. Both are public tables with a by_character index; the generated client tables are `tables.resourceGather` and `tables.characterCast` (src/module_bindings/index.ts), and the row types `ResourceGather` and `CharacterCast` are in src/module_bindings/types.ts.
- Gather duration: the server's base constant `RESOURCE_GATHER_CAST_MICROS` (8 s) lives in spacetimedb/src/helpers/location.ts (and a local copy in reducers/items_gathering.ts). That helper imports `spacetimedb/server` and the schema, so it is not a data module and cannot be imported through `@game-data`. The server also shortens the duration by the character's gatherSpeedBonus perk (floor 0.5 s), so the constant is not the true total anyway. Per the owner's fallback, a gather's start is the first-seen time (server-clock estimate when the row first appears on the client). Nothing is duplicated.
- Cast duration: `ability_template.castSeconds`. The server raises a mana ability below MANA_MIN_CAST_SECONDS (3 s, spacetimedb/src/data/combat_scaling.ts) to that floor. Instead of importing that file (it pulls a relative `.js` import of class_stats into the client type-check), the cast total is max(castSeconds, endsAt minus first-seen), which yields the floored total whenever the row is seen at insert, and the exact castSeconds total when the client loads mid-cast. Nothing is duplicated.
- A resurrect cast (corpse.ts) may carry abilityTemplateId 0n; its label falls back to 'Casting'.
- Cancel: src/module_bindings has no cancel reducer for gather or cast (only cancel_trade). Per the brief, no Cancel control is shown.
- The cast row is deleted by tick_casts (200 ms tick) and the gather row by finish_gather at endsAt, so 'Finishing…' shows only briefly.
- Quick task 261006-a0i (Nearby enemies with Pull actions) lands before this plan and edits src/game/gameData.ts, src/game/context.ts, src/game/queries.ts and their tests. Every edit here to those shared files is additive, anchored next to the existing renownPerks entries, and must not move, rename or reformat anything else. Read each shared file fresh before editing it.

Claude's discretion choices (documented):
- The bar fills from 0 to 100% as the action progresses (a cast bar); the seconds cell shows the time left. The progressbar exposes percent complete (aria-valuenow 0 to 100) and aria-valuetext with the summary.
- If a cast row and a gather row exist at the same time, the cast is shown (the more immediate act); the gather shows again, with its original first-seen start, once the cast row is deleted.
- Gather icon is PhCube (the Nearby node icon); cast icon is abilityIcon(kind) from src/hotbar/hotbar.ts (falls back to PhSparkle).
