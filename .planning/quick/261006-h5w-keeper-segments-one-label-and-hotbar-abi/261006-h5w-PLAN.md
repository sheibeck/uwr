# Quick Task 261006-h5w: One Keeper label per reply, and a hotbar ability tooltip

Two client-only fixes from the owner's 2026-10-06 play session (todos `combat-victory-summary-looks-like-three-keeper-lines`, client part only, and `hotbar-hover-shows-ability-description`). No server, prompt, Keeper Bible, route or `src/module_bindings` change. No publish.

## Task 1: One Keeper label per reply (client part)

- `lines.ts`: `classifySegments` marks a segment `continued` when the previous line emitted from the same row has the same kind and the same speaker (Keeper narration, or the same NPC name and id). A continued line is its own `FeedLineView` (own key, own paragraph, own keyword parts) with no label. A speaker change inside the row starts a new label.
- `FeedLine.vue`: a continued Keeper line draws no "The Keeper" header; a continued NPC line draws only the quoted body, without the "Name says," lead. Text nodes only, keyword buttons unchanged.
- The round tag stays on the first Keeper line of the entry (that line always keeps its label), so the grouped label still reads "THE KEEPER · ROUND M".
- `creationLines.ts` builds its own Keeper lines for the same segments contract, so its multi-segment rows get the same `continued` marking.
- Tests: a 3-segment Keeper victory row gives one label and three paragraphs; Keeper, NPC, Keeper gives three labels; the round tag is kept on the grouped label; FeedLine renders no header for a continued line; creation rows group too.

## Task 2: Hotbar ability tooltip

- `hotbar.ts`: new pure `slotTooltip(ability, inCombat)` giving name, stat parts (cost, cooldown, cast time) and description. The cooldown reads in rounds in combat (`cooldownTotalRounds` / `roundsText` from `combat/roundCooldown`), seconds otherwise; cast 0 reads "Instant". `slotTitle` and `slotAriaLabel` keep their behaviour and tests.
- `HotbarRow.vue`: one popover above the row, shown for the hovered (mouse or pen pointer), keyboard-focused (`:focus-visible`) or long-pressed slot; text nodes only. Each filled slot carries `aria-describedby` pointing at a hidden description element holding the same text, so keyboard and screen-reader users get it. The native `title` is dropped (it would double the popover). Escape dismisses it.
- Mobile: touch or pen press held about 500 ms opens the same popover without casting; the click that follows the long-press is swallowed. A normal tap still casts. A press elsewhere dismisses it.
- Tests: hover, focus, long-press (and that a short tap still casts, a long-press does not), combat rounds, "Instant", `aria-describedby`, an `<img onerror>` description rendered as text, Escape, source guards.
