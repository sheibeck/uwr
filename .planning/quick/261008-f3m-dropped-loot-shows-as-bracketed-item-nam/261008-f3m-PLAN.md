<objective>
The owner (2026-10-08, verbatim): "Enemies are dropping loot now. But we don't have a UI yet for looting. Could we make the dropoped items have square brackets and clicking them puts them in our bag if the bag has room?" The owner later confirmed the take-all link (via the coordinator): "yes, add the Take all link too". It is required: it calls take_all_loot, it is clickable only while that fight still has rows in my_combat_loot, and its accessible name is "Take all loot".

What exists today (checked by the planner):
- The victory announcement (`spacetimedb/src/reducers/combat.ts`, about lines 2020-2038) writes one private `reward` event. The text is "Loot dropped:" followed by one line per `combat_loot` row, `  {{color:<hex>}}[Take <name>]{{/color}}`, using a local RARITY_COLORS map of hex literals. It does NOT carry the loot id. With no drops it writes "No loot dropped from {summaryName}." The `combat_result` row is deleted when `charLoot` is empty.
- Each victory first deletes the character's older `combat_loot` rows (about line 1972). So at any time a character's rows belong to one fight only.
- The `loot` text command (`spacetimedb/src/reducers/intent.ts`, about lines 611-639) writes the same legacy form under the header "Loot available:", as a private kind `look`. With no rows it writes "There is nothing to loot here." (kind `system`).
- `take_loot({ characterId, lootId })` (items.ts about line 373) checks ownership. When there is no matching stack and `MAX_INVENTORY_SLOTS` (50) unequipped rows are already held, it refuses with `failItem(..., 'Backpack is full')`, which writes a private `system` line. Otherwise it adds the item, deletes the row and writes "You receive {displayName}." plus a party line. `take_all_loot({ characterId })` (about line 462) takes every row that fits, writes "You take all loot: a, b." and warns "Backpack full — N item(s) left behind." Neither reducer changes in this plan.
- The view `my_combat_loot` (views/combat.ts about line 58) returns the rows of the sender's active character. The generated bindings already have `tables.myCombatLoot`, `conn.reducers.takeLoot` and `conn.reducers.takeAllLoot`. The client never subscribes to the view: no `myCombatLoot` appears outside `src/module_bindings`. `GameReducers` (src/game/context.ts) has no take reducers.
- Client feed: `lines.ts` `classifyByKind` sends a `reward` row through `cleanServerText`, which strips color tokens and unwraps `[x]`. The result is a `quest` line labelled "Reward" and is keyword-eligible. Today a drop therefore reads as plain "Take Rusty Dagger" lines, and nothing is clickable.
- Keyword pipeline: `findKeywords` builds `KeywordPart { text, entry }`. `FeedLine.vue` renders an entry as `<button class="keyword">`, with title and aria-label set to `keywordActionLabel(entry)` (VERBS by kind) and aria-disabled while offline. The click goes through `FeedView` to `consoleApi.actOnKeyword(entry)`, a switch on `entry.kind` in `useConsole.ts`.
- Rarity color: the Inventory, Vendor and Crafting screens color item names with `rarityColor(rarity)` from `src/ledger/itemModel.ts`. It returns a `var(--color-rarity-*)` string and is applied as an inline style. There are no rarity classes. Correction to the brief: this plan reuses `rarityColor` and does not invent classes. Valid rarity keys are `QUALITY_TIERS` in `@game-data/mechanical_vocabulary`.
- `src/ledger/NoticeLine.vue` mirrors private `reward` lines through `cleanServerText`, so that function must hide the new tokens.

Design: the line carries the loot id (judgement call, and why). The server writes each item as a machine token, `{{loot:<id>:<rarity>}}<name>{{/loot}}`, and the take-all link as `{{lootall}}Take all{{/lootall}}`. The client parses the tokens, never displays them, and draws `[name]` / `[Take all]`. Matching by loot id is the only exact method:
- names repeat (two Wolf Pelts);
- order mapping breaks once a row is taken;
- private event rows carry no combat id to join on.
Ids are unique and never reused. A forged token is harmless because it is clickable only when its id is in the player's own `my_combat_loot`, and the server re-checks ownership. The grammar lives ONCE in `spacetimedb/src/data/loot_line.ts` (pure, imported by the client as `@game-data/loot_line`), per the "server is source of truth" rule.

Judgement calls (record them in the SUMMARY):
1. Loot id in the line, not mapping by combat id or by order (reasons above).
2. Layout follows the owner's ROADMAP 51.4 note: one line, `Loot dropped: [Rusty Dagger], [Wolf Pelt] [Take all]`. The link sits after every loot line that lists at least one item (owner-required).
3. The [Take all] gate is "any of this line's own loot ids is still in my_combat_loot". This equals "that fight still has rows" for two reasons:
   - every victory deletes the character's older rows first;
   - the line lists exactly the fight's takeable rows. A row whose template is missing is skipped by the line AND by both reducers.
   So no second id is needed in the token.
4. The `loot` command uses the same grammar and moves from kind `look` to kind `reward`. The client parses tokens only on `reward` rows, so typing `loot` re-lists clickable drops after the announcement scrolls away.
5. Taking writes no client echo. The server writes the success line and the refusal, as the owner asked ("no client-made feed lines").
6. A taken item keeps its rarity color as plain text, so history stays readable.
7. History rows in the old format stay plain text ("Take Rusty Dagger"). This follows the greenfield rule: no compatibility shim.
8. Junk is not shown in a neutral color in the line, because the token carries rarity only. That is acceptable for the stopgap.

## Interfaces the executor builds (exact names; later tasks rely on them)

`spacetimedb/src/data/loot_line.ts` (pure; imports only `QUALITY_TIERS` and `QualityTier` from `./mechanical_vocabulary`):
- Constants:
  - `LOOT_DROPPED_LEAD = 'Loot dropped:'`
  - `LOOT_AVAILABLE_LEAD = 'Loot available:'`
  - `TAKE_ALL_LABEL = 'Take all'`
  - `LOOT_NAME_MAX = 80`
- `type LootLinePiece`, one of:
  - `{ kind: 'text'; text: string }`
  - `{ kind: 'item'; lootId: bigint; rarity: QualityTier; name: string }`
  - `{ kind: 'takeAll'; label: string }`
- `interface LootRowLike { id: bigint; itemTemplateId: bigint; qualityTier?: string | null }`
- `interface LootTemplateLike { name: string; rarity?: string | null }`
- `cleanLootName(raw: unknown): string`. Removes the characters `[ ] { }`, turns control characters (including CR and LF) into spaces, collapses whitespace, trims, and cuts to LOOT_NAME_MAX. A non-string gives ''.
- `formatLootLine(lead: string, rows: readonly LootRowLike[], templateOf: (templateId: bigint) => LootTemplateLike | null | undefined): string | null`
  - For each row in the given order: skip it when `templateOf` returns nothing or the cleaned name is ''.
  - rarity = `row.qualityTier`, else the template's rarity, lowercased. Anything not in QUALITY_TIERS becomes 'common'.
  - Each item is `{{loot:<id>:<rarity>}}<name>{{/loot}}`.
  - With no items, return null.
  - Otherwise return `<lead> <items joined by ', '> {{lootall}}Take all{{/lootall}}`, all on one line.
- `parseLootLine(raw: unknown): LootLinePiece[] | null`
  - Use one module-level `/g` regex, with `lastIndex` reset to 0 at the start of every call, and an `exec` loop. Never build a regex from data. Quantifiers are bounded and never nested. The regex alternates:
    - an item: double-brace `loot:` + 1-20 digits + `:` + 1-16 lowercase letters + close braces, then 1-80 characters that are not a brace or newline, then the double-brace `/loot` close;
    - a take-all: double-brace `lootall`, then 1-40 characters that are not a brace or newline, then the double-brace `/lootall` close.
  - Text between matches becomes text pieces, kept literal. A malformed token stays as literal text.
  - Trim the start of the first text piece and the end of the last one, and drop empty text pieces.
  - A rarity outside QUALITY_TIERS becomes 'common'. The id is `BigInt(digits)`.
  - Return null when there is no item piece, when the input is not a string, or on any exception (wrap the body in try/catch). It never throws.
- `stripLootTokens(raw: string): string`. Every item token becomes its name. Every take-all token is removed, together with ONE space directly before it. Use `.replace` with `/g` regexes.

`src/console/lootLine.ts` (pure, no Vue):
- `TAKE_ALL_ENTRY_NAME = 'all loot'`. `keywordActionLabel` gives 'Take all loot'.
- `lootPlainText(pieces): string`. Text pieces as-is, items as `[name]`, take-all as `[label]`.
- `lootParts(pieces, available: ReadonlySet<bigint>): KeywordPart[]`, one part per piece:
  - text: `{ text, entry: null }`;
  - item: `{ text: '[name]', entry: available.has(lootId) ? { kind: 'loot', id: lootId, name } : null, rarity }`;
  - takeAll: `{ text: '[label]', entry: <any item of THIS line has its id in available> ? { kind: 'lootAll', id: 0n, name: TAKE_ALL_ENTRY_NAME } : null }`. The id 0n is unused; take_all_loot takes only the character id.

`src/console/keywords.ts`:

- `KeywordPart` gains optional `rarity?: string`.
- `buildVocabulary` and `findKeywords` are unchanged. The loot kinds never come from the vocabulary.
