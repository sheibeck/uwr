<objective>
Fix (a) from the todo: when no enemy type fits a place's level band, the spawn takes the place's target level, and its stats, rewards and every level display follow that level.

Owner, 2026-10-08, verbatim: "as I travel around to different zone currently, I'm noticing the nearby enemies seem to all be level 1. Even though I went into a level 4-6 zone. I'm looking at Armond, who is currently in Kesterlane Basin · Mother Pan Undercroft". He picked "Quick fix (a) now".

Design (Claude's discretion, the smallest additive one that covers combat, rewards and the client):
- Add one defaulted column `level: t.u64().default(0n)` LAST on `enemy_spawn` and on `combat_enemy`. Both tables are already public. 0 means "a row from before the column", which reads as the type's level. Phase 43 found that a bare optional column is refused by the auto-migration. A `.default()` column appended last is the repo's proven pattern (combat_round_schema.test.ts, party_privacy.test.ts), so no clear is needed.
- Spawning writes `level = placeSpawnLevel(type level, place target, levelOffset)`: the type's own level when it sits inside the place band, otherwise the place's target level.
- Fight start copies the spawn level onto `combat_enemy.level` and builds the stats from `templateAtLevel(template, level)`. That is the template with maxHp, baseDamage, armorClass and xpReward taken from the world-gen formulas, now one shared function `enemyStatsForLevel`. The result then goes through the unchanged `computeEnemyStats`.
- Victory maps each combat enemy through `templateAtLevel` once, before any reward code, so XP, gold, the loot gates and renown follow the level. The loot code itself is not edited, because Phase 51.3 rewrites it.
- The client reads `spawn.level` and `combat_enemy.level` through the shared `effectiveEnemyLevel` imported from `@game-data/enemy_rules`.
- Out of scope: the world-gen enemy level ranges (fix b, Phase 51.3.1), prompt wording, event spawn scaling (event enemies keep their authored type level), and the separate formula llm_apply uses for quest-invented types.

Output: the server rules and wiring with tests, a local publish (two new columns, no clear, key preserved), regenerated bindings, and the client Nearby and Encounter level from the spawn.
</objective>
