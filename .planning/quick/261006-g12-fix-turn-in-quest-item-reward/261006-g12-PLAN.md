# Quick Task 261006-g12: Fix the item reward created by `turn_in_quest`

LLM quest offers can carry `rewardType: 'item'` with a `rewardItemName`. The reward insert in `turn_in_quest` did not match the `item_template` schema and picked invalid slots and armor types.

## Task 1: Schema-valid, equippable reward (`spacetimedb/src/reducers/quests.ts`)

- `computeQuestRewardStats`: keep the budget formula; slots cycle `head, chest, legs, boots, hands, mainHand` (all `EQUIPMENT_SLOTS`); return `isWeapon` instead of the invalid armor type.
- New `grantQuestItemReward(ctx, character, qt, appendPrivateEvent)`: inserts an `item_template` row with every schema column, mapping budget outputs onto the real columns (str -> `strBonus`, maxHp -> `hpBonus`, armor -> `armorClassBonus`, damage -> `weaponBaseDamage`, `weaponDps` = damage + 1 as starter weapons do). Armor type = heaviest proficient armor (`cloth` fallback); weapon type = first proficient weapon in `WEAPON_TYPES` (`sword` fallback); `allowedClasses: 'any'`; `requiredLevel` = the character's level. `item_instance` gets `qualityTier` = rarity.
- `turn_in_quest` calls the helper.

## Task 2: Grant the reward on the path players use (`spacetimedb/src/reducers/intent.ts`)

- The client's [Turn In] link goes through `submit_intent` ("turn in <quest>"), which never granted the item. Call `grantQuestItemReward` there too.

## Task 3: Tests (`spacetimedb/src/reducers/quest_reward.test.ts`)

Real `turn_in_quest`, `equip_item` and `submit_intent` handlers on the strict mock db:
- turn-in succeeds; `item_template` / `item_instance` rows pass `rowColumnProblems` (no unknown keys, no missing required columns);
- slot in `EQUIPMENT_SLOTS`, armor type valid, weapon fields valid, across levels 1-6 (full slot cycle), 12 and 30;
- the rewarded character can equip the item (martial, mystic, cloth-only, legacy no-proficiency characters);
- xp/gold-only quests create no item; intent turn-in grants the same item.

No schema change. No publish.
