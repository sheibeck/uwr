# Quick Task 261006-g12 Summary: quest item rewards are schema-valid and equippable

## What was wrong

- `turn_in_quest` inserted `item_template` with columns that do not exist (`damage`, `armor`, `str`, `dex`, `int`, `wis`, `cha`, `maxHp`, `maxMana`) and without required ones (`requiredLevel`, `allowedClasses`, all `*Bonus` columns, `weaponBaseDamage`, `weaponDps`, `weaponType`, `stackable`, `wellFed*`). The SpacetimeDB 2.10 product serializer writes every schema column from the row (`value.requiredLevel` -> `DataView.setBigUint64(undefined)`), so the insert threw a TypeError and the whole turn-in rolled back: no xp, no gold, quest never removed. Unknown keys alone would have been ignored.
- Slots `feet` and `weapon` are not equipment slots; armor type `medium` is not an armor type (the equip proficiency check would refuse it).
- The client never calls `turn_in_quest`: the [Turn In <quest>] link goes through `submit_intent`, whose turn-in branch never granted the item at all.

## Changes

- de82b155 `spacetimedb/src/reducers/quests.ts`: budget formula unchanged; slots cycle `head, chest, legs, boots, hands, mainHand`. New exported `grantQuestItemReward` writes every `item_template` column: stat outputs mapped to `strBonus`/`dexBonus`/`hpBonus`/`armorClassBonus`/..., weapon `weaponBaseDamage` = damage, `weaponDps` = damage + 1 (starter-weapon pattern). Armor type = heaviest of plate/chain/leather/cloth the character is proficient in (cloth fallback); weapon type = first proficient `WEAPON_TYPES` entry (sword fallback); `allowedClasses: 'any'` (legacy class check); `requiredLevel` = character level. `item_instance.qualityTier` = rarity.
- 1c7b41f8 `spacetimedb/src/reducers/intent.ts`: "turn in <quest>" also calls `grantQuestItemReward`.
- `spacetimedb/src/reducers/quest_reward.test.ts`: 63 tests on the real handlers (strict mock db). Mutation checks: dropping `requiredLevel` / restoring `feet` fails 21 tests; removing the intent call fails 8.

## Not fixed (reported)

- Neither turn-in path checks inventory space before adding the reward (loot does).
- Both turn-in paths add xp directly instead of `awardXp`, so no level-up check runs on quest xp.
- The intent turn-in path does not call `recordQuestCompletion` (NPC memory), unlike `turn_in_quest`.
- Reward templates use the LLM item name; a name equal to a starter item name would be overwritten by `ensureStarterItemTemplates`' upsert-by-name.
