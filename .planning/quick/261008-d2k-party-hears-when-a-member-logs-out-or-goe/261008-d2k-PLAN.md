## Facts the executor builds on (checked by the planner; no need to re-explore)

**Which path the Logout button takes.**
1. `src/frame/AccountMenu.vue` emits logout. AppFrame and App.vue pass it on to `session.logout()` (`src/session/useSession.ts:565`).
2. `session.logout()` awaits `conn.reducers.logout({})`, then calls `controller.disconnect()` (no retry).
3. Server, at time L: the `logout` reducer (`reducers/auth.ts:71-76`) inserts a `disconnect_logout_tick` with `disconnectAtMicros = L`, due at L + 30 s, and stamps `player.lastSeenAt = L`.
4. Server, at time D > L: `clientDisconnected` (`index.ts:727-745`) stamps `lastSeenAt = D` and inserts a second tick with `disconnectAtMicros = D`.
5. Tick L fires and returns early, because `lastSeenAt` (D) is greater than L.
6. Tick D runs `disconnect_logout` (`auth.ts:78-122`). It writes the friend presence lines, dismisses pets, clears `userId`, `activeCharacterId` and `sessionStartedAt`, then calls `syncCharacterOnline`.
7. So an explicit Logout and a link-dead drop both release in `disconnect_logout`, normally from the clientDisconnected tick. The tick cannot tell them apart. The label must come from player-row state that the logout reducer sets.

**The marker: `player.sessionStartedAt`.**
- Writers today:
  - `login_email` sets it;
  - `disconnect_logout` clears it;
  - the new-row insert in clientConnected leaves it undefined.
- No reader anywhere: not on the server, and not in client code outside the generated bindings.
- Plan: the logout reducer clears it (the signed-in session ends at the click, while the character lingers for the enforced window from commit c477890d). At the release, a missing `sessionStartedAt` means Logout; a present one means link-dead.
- After a Logout and a sign-in inside the window, the client sends no `login_email`, because `player.userId` is still set. So clientConnected must restore the session (`sessionOnReconnect`). Otherwise a later drop would be mislabelled as Logout.
- No schema change. The 51.3 plans edit `schema/tables.ts`, so a marker table would collide with them.

**Gating on the flip.**
- `syncCharacterOnline(ctx, characterId): boolean` (`helpers/online.ts:42`) returns true only when it wrote a real flip.
- After a release, a true return means the character went from online to offline.
- In `set_active_character` and clientConnected, a true return for the selected or re-synced character means it went from offline to online.
- Gate every announcement on that return. This gives exactly one line per real transition. It also gives no line when another player row still holds the character, and none on a second tick after the release (by then `activeCharacterId` is undefined, so the sync returns false).

**Groups.**
- `appendGroupEvent(ctx, groupId, characterId, kind, message)` (`helpers/events.ts:156`) inserts one `event_group` row.
- The `my_group_events` view (`views/groups.ts:20`) gives every member of the group all of its rows.
- `disconnect_logout` never touches `group_member`, so an offline member stays in the party.
- `campCharacter` (`helpers/character.ts:147-167`) removes the member and writes "{name} headed to camp." before its own sync. It is not touched, so camp gets no new line.
- `helpers/events.ts` must get no new exports (eight suites mock it). The new helper imports `appendGroupEvent` from `./events`, as `helpers/character.ts` does.
